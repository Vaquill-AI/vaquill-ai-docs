Grounding means you retrieve the authoritative sections first and give the model their verbatim text. The model then answers only from that text and cites each claim.
Every section Vaquill AI returns has a citation, full text, and a link to the official government source, so users can check the answer.

<Note>
  The runnable implementation is in the [RAG grounding recipe](/api-guide/recipes/rag-grounding). It includes the retrieval loop, the prompt, the citation check, and a tool-calling agent variant.
</Note>

## The pattern

<Steps>
  <Step title="Retrieve the relevant sections">
    Send the user's question to `POST /us/statutes/search`. Scope it with `corpusType` (and `state` for state-scoped corpora) so off-target jurisdictions do not compete for the model's attention. Each result carries an `actId`, a `citation`, an `excerpt`, and a source URL.
  </Step>

  <Step title="Fetch the authoritative text">
    The `excerpt` is a ranking preview, not quotable text. Set `includeBody: true` on the search to attach each hit's full text on `body`. Or call `GET /us/statutes/section/{actId}/body` per section. Both bill the same body price (see [what a search costs](/api-guide/concepts/search#what-a-search-costs)).
  </Step>

  <Step title="Construct a grounded prompt">
    Give the model the retrieved sections, each labeled with its citation and source URL. Tell it to:

    - answer only from the provided sections,
    - cite each claim by its `citation`,
    - say it cannot find support when the sources do not cover the question.
  </Step>

  <Step title="Link back to the source">
    Show the answer with its citations, and link each one to the official source URL returned with the section.
  </Step>
</Steps>

## Practical guidance

[Best practices](/api-guide/best-practices) covers scoping, `excerpt`, `relevanceScore` and cost per body.

<AccordionGroup>
  <Accordion title="Keep the retrieved text verbatim">
    Pass the `body` text through untouched. Paraphrasing can shift the meaning.
  </Accordion>

  <Accordion title="Carry the citation and source URL with every passage">
    Keep each passage next to its `citation` and its source URL (for example `htmlUrl`, `stateHtmlUrl`, or `govInfoHtmlUrl`). The model can then attribute claims, and your UI can show clickable citations.
  </Accordion>

  <Accordion title="Gate the context block on noGoodMatch">
    Check `noGoodMatch` on the search response before you build the context. When it is `true`, nothing in the corpus looks on point. Tell the user, and do not give the model weak passages. When it is `null`, retry the query.

    Do not drop results below a fixed `relevanceScore` cutoff. Use the score only to order what you show.
  </Accordion>

  <Accordion title="Verify the model's citations before showing the answer">
    Check that every `actId` or citation in the model's answer appears in the set you passed in. Drop or flag anything that does not.
  </Accordion>

  <Accordion title="Watch what retrieval costs">
    A grounded turn is one search plus one body per section you cite. Cost grows with the sections you cite, not the sections you retrieve. Cache on `actId`.
