**What this gets you:** an AI agent (Claude, Cursor, or one you built) that can look up US law on its own, mid-conversation, with citations, instead of guessing from training data.

There are two ways to ground an agent in legal text: connect an MCP-compatible client to the hosted Vaquill MCP server, or wrap the REST API as a tool your own agent can call.
Both return citations and source links to official government text.

**Endpoints used:** `POST /us/statutes/search` for the custom-tool path.
The hosted server path needs no direct REST calls from you.

<Tip>
  Using an MCP-compatible client?
  Connect the [hosted Vaquill MCP server](/integrations/mcp/vaquill) and skip this page: no glue code, with statute search and retrieval exposed as tools and a citation and official source link on each result.
</Tip>

## Wrap the REST API as your own tool

When you are building your own tool-calling agent, define a `search_statutes` function backed by `POST /us/statutes/search` and register it as a tool.
The agent decides when to call it, and you return cited results the model can quote.

<Steps>
  <Step title="Implement the tool function">
    Ask the API for a narrow result with `fields` rather than fetching 40+ fields (most null on any row) and trimming them in Python.
    A field you do not request never crosses the wire and never reaches the model's context window, and the saving scales with `limit`.
    `actId` and `citation` always come back, because a row without them cannot be used or attributed.

    ```python Python
    import requests

    BASE_URL = "https://api.vaquill.ai/api/v1/us"
    HEADERS = {
        "Authorization": "Bearer vq_key_...",
        "Content-Type": "application/json",
    }

    # Exactly what the model needs to answer and cite, and nothing else.
    # An unknown name here is rejected with 422, so a typo cannot silently
    # drop a field you were relying on.
    TOOL_FIELDS = [
        "title",
        "excerpt",
        "govInfoHtmlUrl",
        "stateHtmlUrl",
        "htmlUrl",
    ]

    def search_statutes(
        query: str,
        corpus_type: str | None = None,
        state: str | None = None,
        limit: int = 5,
    ) -> list[dict]:
        """Search US statutes and regulations. Returns cited results."""
        payload: dict = {"query": query, "limit": limit, "fields": TOOL_FIELDS}
        if corpus_type:
            payload["corpusType"] = corpus_type
        if state:
            payload["state"] = state

        resp = requests.post(
            f"{BASE_URL}/statutes/search", headers=HEADERS, json=payload
        )
        resp.raise_for_status()

        # best_source_url(): the canonical order from Text formats and source URLs
        # (linked below). Copy it once; do not re-derive the field order.
        return [
            {
                "actId": r.get("actId"),
                "citation": r.get("citation"),
                "title": r.get("title"),
                "excerpt": r.get("excerpt"),
                "sourceUrl": best_source_url(r),
            }
            for r in resp.json()["results"]
        ]
    ```

    `best_source_url()` is the canonical source-link preference order in [Text formats and source URLs](/api-guide/concepts/formats#picking-the-best-available-format).
    Trimming in Python fixes the context window but not the transfer; `fields` fixes both.
  </Step>

  <Step title="Declare the tool schema">
    Tool-calling agents need a schema so the model knows when and how to call your function.
    This shape (a name, a description, and a JSON Schema for parameters) is the common convention across tool-calling frameworks.

    ```python Python
    SEARCH_STATUTES_TOOL = {
        "name": "search_statutes",
        "description": (
            "Search US statutes and regulations (US Code, CFR, state codes, "
            "constitutions, court rules, and more). Use for any question about "
            "what the law says. Returns citations, excerpts, and source links."
        ),
        "parameters": {
            "type": "object",
            "properties": {
                "query": {
                    "type": "string",
                    "description": "Natural language question or keywords.",
                },
                # Tool argument corpus_type maps to the API's corpusType.
                # See Corpus types for every valid value.
                "corpus_type": {
                    "type": "string",
                    "description": (
                        "Optional corpus filter, e.g. USC, CFR, STATE, "
                        "REGULATION. Omit to search everything."
                    ),
                },
                "state": {
                    "type": "string",
                    "description": "Optional 2-letter lowercase state code, e.g. ca.",
                },
            },
            "required": ["query"],
        },
    }
    ```
  </Step>

  <Step title="Dispatch the call and keep answers grounded">
    When the model asks to call `search_statutes`, dispatch to the function and hand the cited results back; the plumbing depends on your framework.

    ```python Python
    def dispatch_tool_call(name: str, arguments: dict) -> list[dict]:
        if name == "search_statutes":
            return search_statutes(
                query=arguments["query"],
                corpus_type=arguments.get("corpus_type"),
                state=arguments.get("state"),
            )
        raise ValueError(f"Unknown tool: {name}")
    ```

    Instruct the model to cite the `citation` field and link the `sourceUrl` for every legal claim, and to say when the corpus returns no match rather than guessing.
    The prompt pattern is in [Ground an LLM answer (RAG)](/api-guide/recipes/rag-grounding).
  </Step>
</Steps>

<Tip>
  For heavy agent traffic, cache the `/us/statutes/coverage` response and use it to steer `corpusType` and `state` on tool calls.
  Searches stay narrow and skip jurisdictions with no data.
</Tip>
