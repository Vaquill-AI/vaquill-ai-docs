---
title: "Map a compliance requirement to the governing law"
description: "Turn a plain-language obligation into governing sections, grouped by jurisdiction, with citations and official source links"
---

**What this gets you:** a plain-English obligation mapped to the statutes, regulations, and agency rules that govern it, across federal and state law.
Each one comes with a citation and a source link, which is the building block of a compliance or RegTech product.

Start from a plain-language obligation like "breach notification timelines" and end with the governing sections, each with its citation and a link to the official source.

**Endpoints used:** `POST /us/statutes/search`, `GET /us/statutes/section/{actId}/body`, `GET /us/statutes/coverage` (free, to discover which corpora a jurisdiction has).

Run `POST /us/statutes/search` once per corpus with the same plain-language query:

- `CFR` for federal regulations.
- `FEDERAL_REGISTER` for agency rules.
- `AGENCY_GUIDANCE` for rulings and notices.
- `REGULATION` for state administrative rules, paired with a `state`.
- `STATE_AGENCY_GUIDANCE` for state insurance bulletins and circular letters, paired with a `state`.

Add `"excludeRepealed": true` so a rule the publisher has already killed cannot enter the map as an obligation.
Then fetch each section's full text with `GET /us/statutes/section/{actId}/body`, group by `corpusType` and jurisdiction so the map reads by source of authority, and show each section with its `citation` and the official government URL so a reviewer can open the primary source.

## Step 1: search across the regulatory corpora

```bash cURL
# Federal regulations (CFR)
curl -X POST https://api.vaquill.ai/api/v1/us/statutes/search \
  -H "Authorization: Bearer vq_key_..." \
  -H "Content-Type: application/json" \
  -d '{"query": "data breach notification timeline", "corpusType": "CFR", "limit": 5}'
```

Change `corpusType` and add the parameters for each corpus.

| Corpus | `corpusType` | Extra parameters |
|---|---|---|
| Federal regulations | `CFR` | none |
| Federal Register agency rules | `FEDERAL_REGISTER` | `agency`, `documentType`, `publishedFrom`, `publishedTo`; for example `"agency": "federal-trade-commission", "documentType": "final", "publishedFrom": "2020-01-01"`. Filter, or you rank one query against every rule every agency has published. |
| Agency guidance | `AGENCY_GUIDANCE` | optional `source` |
| A state's administrative regulations | `REGULATION` | `"state": "wa"` (Washington, for example) |
| A state's insurance bulletins | `STATE_AGENCY_GUIDANCE` | `"state"` |

Not sure which corpora a state has?
Call `GET /us/statutes/coverage`, read the jurisdiction's `corpora` keys, and pass one as `corpusType`.
State regulations (`REGULATION`) are ingested for a subset of states, so drive the state list from coverage rather than assuming every state is present.

## Narrowing the Federal Register sweep

`FEDERAL_REGISTER` holds every rule and every proposal every agency has published, so an unfiltered sweep ranks your obligation against all of it.
A compliance map wants all four filters.

| Filter | What it does | Applies to |
|---|---|---|
| `documentType` | `final` for a rule in force, `proposed` for an NPRM, `presidential` for a Presidential Document | `FEDERAL_REGISTER` |
| `agency` | Federal Register agency slug, or a list of them. Ask for `agencySlugs` in `fields`, or read it off a broad sweep, to scope the follow-up query. | `FEDERAL_REGISTER` and `EXECUTIVE_ACTION` |
| `publishedFrom` | Only documents published on or after this date (`YYYY-MM-DD`). It is the publication date and differs from `yearFrom`, which filters the version year of a section. | `FEDERAL_REGISTER` |
| `publishedTo` | Only documents published on or before this date | `FEDERAL_REGISTER` |

Other corpora carry no agency or publication date, so combining these filters with them returns nothing.

```json
{
  "query": "emissions standards for power plants",
  "corpusType": "FEDERAL_REGISTER",
  "agency": "environmental-protection-agency",
  "documentType": "final",
  "publishedFrom": "2024-01-01",
  "publishedTo": "2024-12-31",
  "limit": 5
}
```

Use `documentType: "final"` for obligations, and run a separate, labelled `proposed` pass for what is coming.

## Narrowing to one named source

`AGENCY_GUIDANCE` is a registry of many named sources under one `corpusType`.
When you already know the obligation is, say, a CFTC swaps-clearing question or a BSA/AML question, skip the broader sweep and add `source` to go straight to that registry entry:

```json
{
  "query": "digital asset margin collateral",
  "corpusType": "AGENCY_GUIDANCE",
  "source": "cftc_staff_letter",
  "limit": 5
}
```

Every result already carries its own `source`, so a hit from a broad sweep tells you which registry entry to scope a follow-up query to.
An unrecognized value is rejected with `422` rather than silently matching nothing.
See [Filtering to one named source](/api-guide/concepts/corpus-types#filtering-to-one-named-source) for the full list of `source` values and which corpus each belongs to.

<Accordion title="Sources under AGENCY_GUIDANCE, FEDERAL_RULES and CFR">

SSA rulings, IRS notices/procedures/rulings, DOJ & FTC Merger Guidelines, the DOJ Antitrust Leniency Policy, Copyright Office Circulars, the DOJ Justice Manual, the USCIS Policy Manual, USPTO MPEP/TMEP, CFTC Staff Letters, FinCEN rulings and guidance, Federal Reserve/OCC/FDIC banking guidance, DFARS PGI, and NLRB memoranda all live under `AGENCY_GUIDANCE`.
`FEDERAL_RULES` and `CFR` similarly fold in several sets (the Federal Rules of Procedure plus Supreme Court Rules; FAR and DFARS within CFR Title 48).

</Accordion>

## Step 2 and 3: collect, fetch text, and group

```python Python
import requests
from collections import defaultdict

BASE = "https://api.vaquill.ai/api/v1/us"
HEADERS = {"Authorization": "Bearer vq_key_..."}


def search(query, corpus_type, state=None, limit=5, **filters):
    body = {"query": query, "corpusType": corpus_type, "limit": limit}
    if state:
        body["state"] = state
    body.update(filters)  # agency, documentType, source, excludeRepealed ...
    resp = requests.post(f"{BASE}/statutes/search", headers=HEADERS, json=body)
    resp.raise_for_status()
    return resp.json()["results"]


def fetch_body(act_id):
    resp = requests.get(f"{BASE}/statutes/section/{act_id}/body", headers=HEADERS)
    resp.raise_for_status()
    data = resp.json()
    return data.get("plain") if data.get("available") else None


# Canonical preference order from Text formats and source URLs (linked below).
SOURCE_FIELDS = (
    "sourceUrl", "govInfoHtmlUrl", "stateHtmlUrl", "htmlUrl", "govInfoPdfUrl",
    "pdfUrl", "textUrl", "xmlUrl", "docxUrl", "externalUrl",
)


def best_source_url(result):
    return next((result[f] for f in SOURCE_FIELDS if result.get(f)), None)


def map_requirement(obligation, states=None, limit=5):
    # Federal regulatory corpora, plus one REGULATION and one
    # STATE_AGENCY_GUIDANCE pass per requested state.
    plan = [
        ("CFR", None, {}),
        # Rules in force. Add "agency" once you know which regulator owns it.
        ("FEDERAL_REGISTER", None, {"documentType": "final", "publishedFrom": "2020-01-01"}),
        ("AGENCY_GUIDANCE", None, {}),
    ]
    for st in states or []:
        plan.append(("REGULATION", st, {}))
        plan.append(("STATE_AGENCY_GUIDANCE", st, {}))

    grouped = defaultdict(list)
    for corpus_type, state, filters in plan:
        # excludeRepealed drops what the publisher marks dead; read goodLawStatus on survivors.
        for r in search(
            obligation,
            corpus_type,
            state=state,
            limit=limit,
            excludeRepealed=True,
            **filters,
        ):
            text = fetch_body(r["actId"])
            if not text:
                continue  # skip sections with no available text
            # Group key: corpusType, plus the state for state-scoped corpora.
            jurisdiction = (r.get("state") or "federal").upper()
            key = f"{corpus_type} / {jurisdiction}"
            grouped[key].append(
                {
                    "citation": r.get("citation") or r["actId"],
                    "title": r.get("title"),
                    "sourceUrl": best_source_url(r),
                    "text": text,
                }
            )
    return grouped


def render(obligation, grouped):
    print(f"Governing law for: {obligation}\n")
    for group, sections in grouped.items():
        print(f"== {group} ==")
        for s in sections:
            print(f"  {s['citation']} - {s['title']}")
            print(f"    Source: {s['sourceUrl']}")
        print()


if __name__ == "__main__":
    obligation = "data breach notification timeline"
    result = map_requirement(obligation, states=["wa", "md"])
    render(obligation, result)
```

A grouped result reads by source of authority:

```text
Governing law for: data breach notification timeline

== CFR / FEDERAL ==
  16 CFR § 318.5 - Notification to the Federal Trade Commission
    Source: https://www.ecfr.gov/...

== AGENCY_GUIDANCE / FEDERAL ==
  ... - Agency guidance on breach reporting
    Source: https://www.govinfo.gov/...

== REGULATION / WA ==
  WAC ... - Notice to affected consumers
    Source: https://app.leg.wa.gov/...
```

Each result carries several optional source URL fields and any may be null.
`best_source_url()` applies the canonical order from [Text formats and source URLs](/api-guide/concepts/formats#picking-the-best-available-format), so a reviewer opening the link from your compliance map lands on the same official page as everywhere else in your product.
