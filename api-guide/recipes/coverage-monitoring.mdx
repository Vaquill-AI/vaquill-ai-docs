Find out when the law you depend on changes, and when a state or agency gains coverage.

| Question | Use |
|---|---|
| Did any section I care about change since my last run? | `changedSince` on `POST /us/statutes/search` |
| Did a jurisdiction gain a whole new corpus? | Snapshot and diff `GET /us/statutes/coverage` |
| Tell me the moment one specific section changes | [Law Change Alerts](/api-guide/alerts), webhook or email, no polling |

## The sync filter: `changedSince`

`changedSince` takes a `YYYY-MM-DD` date and limits a search to sections that changed since then.

<CodeGroup>
```bash cURL
curl -X POST https://api.vaquill.ai/api/v1/us/statutes/search \
  -H "Authorization: Bearer vq_key_..." \
  -H "Content-Type: application/json" \
  -d '{"query": "data breach notification", "corpusType": "STATE", "state": ["ca", "ny", "tx"], "changedSince": "2026-08-01", "limit": 50, "fields": ["title", "state", "lastAmendedDate", "actStatus"]}'
```

```python Python
import requests

BASE_URL = "https://api.vaquill.ai/api/v1/us"
HEADERS = {
    "Authorization": "Bearer vq_key_...",
    "Content-Type": "application/json",
}


def changed_since(query: str, since: str, **scope) -> list[dict]:
    """Sections matching `query` that we observed change on or after `since`."""
    resp = requests.post(
        f"{BASE_URL}/statutes/search",
        headers=HEADERS,
        json={
            "query": query,
            "changedSince": since,
            "limit": 50,
            # Ask for only what your sync writes back (see Best practices);
            # actId and citation always come back.
            "fields": ["title", "state", "lastAmendedDate", "actStatus"],
            **scope,
        },
    )
    if resp.status_code == 422:
        # The window matched too many sections to answer safely. Narrow it.
        # The error body names the cause; see Errors for the 422 shape.
        raise RuntimeError(resp.json())
    resp.raise_for_status()
    return resp.json()["results"]
```
</CodeGroup>

Read a hit's history with `GET /us/statutes/section/{actId}/changes` to see what moved.

A `422` means the window is too broad. Use a later date, `corpusType` or `state` (see [Errors](/api-guide/errors)).

<Accordion title="How changedSince behaves">

- **Dates are when we saw the change.** They are an upper bound on when it took effect, not an effective date.
- **An empty result means no captured change in the window.** It does not prove nothing was amended.
- **A window that is too broad returns `422` instead of partial results.** Narrow it with `corpusType` and `state`.
- **A search still needs a `query`.** Run one search per topic you track.

In ranked modes `limit` caps at 50 and `offset` at 70, so the deepest result is 120.
Boolean mode (`matchType: "boolean"`) pages to the end of the matches, with `offset` up to 10,000.
See [Search](/api-guide/concepts/search).

An empty window is charged the ordinary 4-credit search price. Read `creditsConsumed`.

</Accordion>

### A nightly job

```python Python
from datetime import date, timedelta

TOPICS = [
    {"query": "data breach notification", "corpusType": "STATE", "state": ["ca", "ny", "tx"]},
    {"query": "hazard communication standard", "corpusType": "CFR"},
]


def run(since: str) -> None:
    for topic in TOPICS:
        scope = {k: v for k, v in topic.items() if k != "query"}
        query = topic["query"]
        hits = changed_since(query, since, **scope)
        if not hits:
            continue
        print(f"{len(hits)} change(s) touching {query!r} since {since}")
        for h in hits:
            print(f"  {h['citation']}  {h.get('lastAmendedDate') or ''}")


if __name__ == "__main__":
    # Overlap the window by a day so a run that fails cannot open a gap.
    run(since=(date.today() - timedelta(days=2)).isoformat())
```

## The other question: a jurisdiction gaining a new corpus

`changedSince` cannot show that a state you do not yet query has gained regulations.
To catch that, snapshot `GET /us/statutes/coverage` on a schedule and diff the snapshots.
<FreeRateLimited /> Daily or weekly is enough.

<Accordion title="Snapshot and diff code">

The response is `{ "data": {...}, "meta": {...} }`.
Inside `data` are a `corpusTypes` legend and a `jurisdictions` array. Each jurisdiction has a `corpora` object that maps a corpusType token to its section count (the same count [Coverage](/api-guide/coverage) shows).

**1. Fetch and flatten the coverage matrix**

```python Python
def fetch_coverage() -> dict:
    resp = requests.get(
        f"{BASE_URL}/statutes/coverage",
        headers={"Authorization": HEADERS["Authorization"]},
    )
    resp.raise_for_status()
    return resp.json()["data"]


def to_snapshot(coverage_data: dict) -> dict:
    """Flatten coverage into {code: {corpusToken: count}}."""
    return {
        j["code"]: dict(j["corpora"])
        for j in coverage_data["jurisdictions"]
        if j["hasData"]
    }
```

**2. Save and diff**

Save each snapshot as JSON. Compare two snapshots for a new jurisdiction, a new corpus, or a corpus whose count grew.

```python Python
import json
from datetime import datetime, timezone
from pathlib import Path

SNAPSHOT_DIR = Path("coverage_snapshots")


def save_snapshot(snapshot: dict) -> Path:
    SNAPSHOT_DIR.mkdir(exist_ok=True)
    stamp = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M%SZ")
    path = SNAPSHOT_DIR / f"coverage-{stamp}.json"
    path.write_text(json.dumps(snapshot, indent=2, sort_keys=True))
    return path


def load_latest_snapshot() -> dict | None:
    files = sorted(SNAPSHOT_DIR.glob("coverage-*.json"))
    return json.loads(files[-1].read_text()) if files else None


def diff_snapshots(old: dict, new: dict) -> list[str]:
    changes: list[str] = []
    for code, corpora in new.items():
        if code not in old:
            changes.append(f"NEW jurisdiction {code}: {sorted(corpora)}")
            continue
        prev = old[code]
        for token, count in corpora.items():
            if token not in prev:
                changes.append(f"{code}: new corpus {token} ({count} sections)")
            elif count > prev[token]:
                changes.append(
                    f"{code}: {token} grew by {count - prev[token]} "
                    f"({prev[token]} -> {count})"
                )
    return changes
```

Example output when a state gained regulations (counts are placeholders):

```text
2 coverage change(s) detected:
  - va: new corpus REGULATION (20000 sections)
  - tx: STATE grew by 2000 (120000 -> 122000)
```

</Accordion>

<Warning>
  A growing count shows the corpus got bigger, not which sections moved.
  Use `changedSince` to find what changed.
</Warning>
