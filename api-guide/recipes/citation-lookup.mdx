---
title: "Resolve and verify a statute citation"
description: "Resolve a statute or regulation citation to its governing section, and check a whole document's citations in one batch call"
---

Check whether a citation is real before it ships, whether it came from an LLM, a user or your own database.

Send a Bluebook citation such as `42 U.S.C. § 1983`, `16 C.F.R. § 444.1` or `Del. Code Ann. tit. 13, § 1301`. `/us/statutes/resolve` returns the exact section, its metadata and an official source link.
Use `GET` for one citation and `POST` for a whole document.

Bluebook citations resolve best. The safest string to send is the `citation` value we returned.
See [Citation formats](/api-guide/concepts/citation-formats) for shared acronyms that need a `state`.

<Accordion title="Every form that resolves">

  - Federal statute: `42 U.S.C. § 1983` (annotated `42 U.S.C.A. § 1983` /
    `42 U.S.C.S. § 1983` and `Title 42 U.S.C. § 1983` also resolve)
  - Federal regulation: `16 C.F.R. § 444.1`
  - State statute: `Del. Code Ann. tit. 13, § 1301`
  - US Constitution: `U.S. Const. art. I, § 8`, `U.S. Const. amend. XIV, § 1`
  - State constitution: `Cal. Const. art. I, § 7`
  - Federal court rule: `Fed. R. Civ. P. 12`, `Fed. R. Evid. 702`
  - Federal Acquisition Regulation / DFARS: `FAR 52.219-14`, `DFARS 252.225-7001`
    (with or without periods, and with a pinpoint like `FAR 52.219-14(b)`). These resolve into CFR Title 48.

  The form a state's own courts print also resolves:
  `O.C.G.A. § 51-1-6`, `RCW 59.18.060`, `R.C. 2305.10`, `§ 292.290, RSMo`.

  Agency guidance has no Bluebook form. Send its citation exactly as we returned it: `NY Insurance Circular Letter No. 4 (2022)`, `TDI Commissioner's Bulletin B-0004-22`, `IL Company Bulletin 2021-03`.
  This covers `STATE_AGENCY_GUIDANCE` (state insurance bulletins and circular letters) and `AGENCY_GUIDANCE` (IRS Notices, OCC Bulletins, CFTC staff letters and others).
</Accordion>

This recipe covers statutes and regulations only. Case law is not part of the Vaquill Developer API.

**Endpoints:** `GET /us/statutes/resolve` for one citation, `POST /us/statutes/resolve` for a batch.

## Resolve in one call

`GET /us/statutes/resolve` returns the section metadata and an official source link.
Check the `resolved` flag to see whether the citation is real.

<CodeGroup>
```bash cURL
curl -G https://api.vaquill.ai/api/v1/us/statutes/resolve \
  -H "Authorization: Bearer vq_key_..." \
  --data-urlencode "cite=42 U.S.C. § 1983"
```

```python Python
import requests

resp = requests.get(
    "https://api.vaquill.ai/api/v1/us/statutes/resolve",
    headers={"Authorization": "Bearer vq_key_..."},
    params={"cite": "42 U.S.C. § 1983"},
)
data = resp.json()
if data["resolved"]:
    sec = data["section"]
    print(sec["citation"], "->", sec["actId"])
else:
    print("Unverified citation:", data["inputCitation"])
```
</CodeGroup>

A resolved response carries the full section (the same shape as `/us/statutes/section/{actId}`).
If the citation had a pinpoint like `42 U.S.C. § 1983(b)(2)`, the response also has `subsection` and a `pinpoint` object with the text of that subsection.
See [Pinpoints](/api-guide/concepts/pinpoints) for the fields and [Get one subsection](/api-guide/recipes/pinpoint-subsection) for an example.

A call is charged whether or not the citation resolves. Only server errors are refunded.

<Accordion title="Ambiguous guidance citations">
  Some regulators reuse one citation across several documents, such as `MA Bulletin 1991-01`.
  When a citation does not identify a single document, `resolved` is `false`.
  Reach those documents by `actId`, or search with `corpusType=STATE_AGENCY_GUIDANCE` scoped to the state.
</Accordion>

## Resolve a whole document's citations at once

`POST /us/statutes/resolve` takes a batch of citations in one call and returns a verdict for each.

<CodeGroup>
```bash cURL
curl -X POST https://api.vaquill.ai/api/v1/us/statutes/resolve \
  -H "Authorization: Bearer vq_key_..." \
  -H "Content-Type: application/json" \
  -d '{"citations": ["42 U.S.C. 1983", "16 C.F.R. 444.1", "Cal. Civ. Code 1950.5"]}'
```

```python Python
import requests

resp = requests.post(
    "https://api.vaquill.ai/api/v1/us/statutes/resolve",
    headers={
        "Authorization": "Bearer vq_key_...",
        "Content-Type": "application/json",
    },
    json={
        "citations": [
            "42 U.S.C. 1983",
            "16 C.F.R. 444.1",
            "Cal. Civ. Code 1950.5",
        ]
    },
)
resp.raise_for_status()
data = resp.json()

print(f"{data['resolvedCount']}/{data['count']} resolved, "
      f"{data['creditsConsumed']} credits")
for item in data["results"]:
    if item["resolved"]:
        print("OK  ", item["inputCitation"], "->", item["section"]["actId"])
    else:
        print("FLAG", item["inputCitation"])
```
</CodeGroup>

A trimmed response:

```json
{
  "results": [
    {
      "resolved": true,
      "inputCitation": "42 U.S.C. 1983",
      "section": {
        "actId": "USC_T42_C21_S1983",
        "citation": "42 U.S.C. § 1983",
        "title": "Civil action for deprivation of rights"
      },
      "subsection": null
    },
    {
      "resolved": false,
      "inputCitation": "42 U.S.C. 19833",
      "section": null,
      "subsection": null
    }
  ],
  "resolvedCount": 1,
  "count": 2,
  "creditsConsumed": 4
}
```

The batch route works like this:

- Every input gets an entry. An unresolved citation comes back with `resolved: false`.
  The `results` array matches your de-duplicated input, in order.
- Set `state` or `corpusType` when every citation belongs to one jurisdiction or corpus.
  `22 CCR 76227` is California and `8 CCR 1206-2` is Colorado, so the acronym alone is not enough.
  Omit both for a mixed batch.

**Limits and billing**

- At most 50 citations per call. An empty list or a longer one returns `422`.
- Duplicates are collapsed before pricing, so a citation sent twice costs once.
- Cost is per citation, resolved or not. Batching saves round trips, not credits.
  Read `creditsConsumed`. Citations that fail on our side are refunded.

## If you need your own match tolerance

Both resolve routes use the same parser. Build your own matcher only for tolerance it does not offer, such as flagging a section number that is off by one digit.
Send the citation as the `query` on `POST /us/statutes/search`, compare the top result's `citation` and `citationShort`, then call `GET /us/statutes/section/{actId}/body`.
This costs a search plus a body, so use it only when you need that tolerance.

## Flagging what you cannot resolve

<AccordionGroup>
  <Accordion title="Return an unresolved flag, not a guess">
    `resolved: false` means unverified. Do not fall back to a loosely related section.
    For an LLM citation, an unresolved flag suggests the model made it up.
  </Accordion>
  <Accordion title="Scope by corpus to cut false matches">
    The corpus token is in the citation.
    `... CFR ...` means `corpusType: "CFR"`, `... U.S.C. ...` means `"USC"`, and a state code section means `"STATE"` with the two-letter `state`.
    A citation that names a different jurisdiction returns `resolved: false`, so leave scope off unless you are disambiguating.
    `FAR` and `DFARS` citations are `corpusType: "CFR"`.
    The `source` filter (`"far"`, `"dfars"`) works on `POST /us/statutes/search` only. The resolve routes take `state` and `corpusType`.
  </Accordion>
  <Accordion title="Text unavailable on a resolved citation">
    A citation can resolve before its full text is available.
    Then `GET /us/statutes/section/{actId}/body` returns `available: false` and `creditsConsumed: 0`.
    You still have the `actId`, citation and source link.
  </Accordion>
  <Accordion title="Picking the official source link">
    Source URL fields on a resolved section can be null.
    Pick one with the order in [Text Formats and Source URLs](/api-guide/concepts/formats#picking-the-best-available-format).
  </Accordion>
</AccordionGroup>
