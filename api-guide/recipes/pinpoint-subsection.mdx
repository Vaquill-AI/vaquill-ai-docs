Get the text of the subsection a citation names. The response also has the lead-in sentence, the units inside and beside it, and a quality grade.

A citation such as `625 ILCS 5/11-601(c)` names one subsection. Add the pinpoint to a resolve call. The response has the whole section plus a `pinpoint` object for unit (c).
See [Resolve and verify a statute citation](/api-guide/recipes/citation-lookup) for batch resolve and unresolved citations.

**Endpoints:** `GET` and `POST /us/statutes/resolve`, `POST /us/statutes/extract-citations`, `GET /us/statutes/section/{actId}/body`, `POST /us/statutes/search`.

[Pinpoints](/api-guide/concepts/pinpoints) has the full field reference and errors. This page has working examples.

## Add a pinpoint to the resolve call

Put the pinpoint in the citation as a statute book prints it.
A resolve with a pinpoint costs 2 credits per citation.

<CodeGroup>
```bash cURL
curl -G https://api.vaquill.ai/api/v1/us/statutes/resolve \
  -H "Authorization: Bearer $VAQUILL_API_KEY" \
  --data-urlencode "cite=625 ILCS 5/11-601(c)" \
  --data-urlencode "state=il"
```

```python Python
import os

import requests

resp = requests.get(
    "https://api.vaquill.ai/api/v1/us/statutes/resolve",
    headers={"Authorization": f"Bearer {os.environ['VAQUILL_API_KEY']}"},
    params={"cite": "625 ILCS 5/11-601(c)", "state": "il"},
)
resp.raise_for_status()
data = resp.json()

if not data["resolved"]:
    print("Unverified citation:", data["inputCitation"])
elif "pinpoint" in data:
    pin = data["pinpoint"]
    print(pin["matched"], pin["matchLevel"], pin["structure"]["quality"])
    print(pin["text"])
else:
    # The section resolved but the unit could not be looked up this time.
    print(data.get("pinpointNote"))
```

```javascript JavaScript
const url = new URL("https://api.vaquill.ai/api/v1/us/statutes/resolve");
url.searchParams.set("cite", "625 ILCS 5/11-601(c)");
url.searchParams.set("state", "il");

const resp = await fetch(url, {
  headers: { Authorization: `Bearer ${process.env.VAQUILL_API_KEY}` },
});
if (!resp.ok) throw new Error(`resolve failed: ${resp.status}`);
const data = await resp.json();

if (!data.resolved) {
  console.warn("Unverified citation:", data.inputCitation);
} else if (data.pinpoint) {
  const pin = data.pinpoint;
  console.log(pin.matched, pin.matchLevel, pin.structure.quality);
  console.log(pin.text);
} else {
  // The section resolved but the unit could not be looked up this time.
  console.log(data.pinpointNote);
}
```
</CodeGroup>

A trimmed response (the `section` object is cut to two fields):

```json
{
  "resolved": true,
  "inputCitation": "625 ILCS 5/11-601(c)",
  "section": { "actId": "STATE_IL_C625_A5_S11-601", "citation": "625 ILCS 5/11-601" },
  "subsection": "c",
  "pinpoint": {
    "requested": "(c)",
    "path": ["c"],
    "label": "(c)",
    "level": "subsection",
    "matched": true,
    "matchLevel": "exact",
    "text": "Unless some other speed restriction is established under this Chapter, the maximum speed limit in an urban district for all vehicles is:",
    "leadIn": [],
    "fullText": "(c) Unless some other speed restriction is established under this Chapter, the maximum speed limit in an urban district for all vehicles is: 1. 30 miles per hour; and 2. 15 miles per hour in an alley.",
    "children": [
      { "path": ["c", "1"], "label": "1.", "level": "paragraph", "text": "30 miles per hour; and" },
      { "path": ["c", "2"], "label": "2.", "level": "paragraph", "text": "15 miles per hour in an alley." }
    ],
    "siblings": { "previous": "b", "next": "d" },
    "charStart": 1493,
    "charEnd": 1693,
    "structure": {
      "source": "request_time",
      "quality": "verified",
      "builder": "text-grammar/1:il",
      "textSha256": "dfbee96a02574de186178e776364f8557f6e2ed760a31ae5df7232d1f27104b0"
    }
  },
  "creditsConsumed": 2.0
}
```

`subsection` echoes the dot-joined pinpoint (`c`). Read `pinpoint.path` for the unit itself.
`textSha256` is the hash of the text the offsets index into.
`creditsConsumed` is a float in every response.

## Read the result

Five fields tell you what to do with the answer.

| Field | What it tells you |
|---|---|
| `matched` | `true` when the unit you asked for exists. Check this first, on every call |
| `matchLevel` | `exact`, `ancestor` or `none`. On `ancestor` the block describes a unit above the one you asked for |
| `structure.quality` | `native`, `verified`, `heuristic` or `none`. How far to trust the outline |
| `children` | The units inside this one, each with its own `path`, `label`, `level` and `text` |
| `siblings` | The labels of the previous and next unit at the same level, `null` at either end |

Some units finish a sentence that starts above them.
`leadIn` holds those parent sentences, outermost first. To quote the unit in full, join the `leadIn` text and the unit's `text`.

<Expandable title="Example with a lead-in: Mo. Rev. Stat. 565.021.1(1)">
The first paragraph of Missouri murder in the second degree:

```json
{
  "requested": "(1)(1)",
  "path": ["1", "1"],
  "label": "(1)",
  "level": "paragraph",
  "matched": true,
  "matchLevel": "exact",
  "text": "Knowingly causes the death of another person or, with the purpose of causing serious physical injury to another person, causes the death of another person; or",
  "leadIn": [
    {
      "path": ["1"],
      "label": "1.",
      "text": "A person commits the offense of murder in the second degree if he or she:"
    }
  ],
  "fullText": "(1) Knowingly causes the death of another person or, with the purpose of causing serious physical injury to another person, causes the death of another person; or",
  "children": [],
  "siblings": { "previous": null, "next": "2" },
  "charStart": 120,
  "charEnd": 282,
  "structure": {...}
}
```
</Expandable>

<Expandable title="Three more citations, all exact matches">
| Citation | `path` | `structure.quality` | `structure.source` |
|---|---|---|---|
| `Wis. Stat. 940.01(1)(a)` | `["1", "a"]` | `verified` | `request_time` |
| `Iowa Code 422.5(1)(b)` | `["1", "b"]` | `verified` | `request_time` |
| `Minn. Stat. 609.02 subd. 2` | `["2"]` | `native` | `artifact` |

The Wisconsin unit has `leadIn` text `Offenses.`, the heading of subsection (1).
The Iowa unit (b) opens with two numbered paragraphs, so its `text` is empty and the content is in `children`.
The Minnesota unit is a whole subdivision, `Subd. 2.` with the heading `Felony.`
</Expandable>

`structure.source` is `artifact` (a pre-built outline) or `request_time` (parsed on this call). It is not a grade.
`structure.quality` is the grade. Confirm a `heuristic` unit against the text. Read `none` as "unknown", not "no subsections".

## Handle a miss

A pinpoint can name a unit the section does not have.
The call succeeds and is charged, and the block says what happened.

<Expandable title="Example miss: Minn. Stat. 609.02 subd. 2(1)">
Subdivision 2 has no paragraph (1). This is the `pinpoint` object from `POST /us/statutes/resolve`:

```json
{
  "requested": "(2)(1)",
  "path": ["2"],
  "label": "Subd. 2.",
  "level": "subdivision",
  "matched": false,
  "matchLevel": "ancestor",
  "text": "Felony.\n\n\"Felony\" means a crime for which a sentence of imprisonment for one year or more may be imposed.",
  "leadIn": [],
  "fullText": "Subd. 2.Felony.\n\n\"Felony\" means a crime for which a sentence of imprisonment for one year or more may be imposed.",
  "children": [],
  "siblings": { "previous": "1", "next": "2a" },
  "charStart": 179,
  "charEnd": 292,
  "unmatched": ["1"],
  "reason": "no_such_subsection",
  "note": "This section has no (2)(1). The text returned is (2), the deepest unit that exists; (1) was not found.",
  "structure": {
    "source": "artifact",
    "quality": "native",
    "builder": "mn-native-1",
    "textSha256": "e8329c88c5f2a40182e61c63ac6e02f516eacb95e4ab55a183c97e632294a2b8"
  }
}
```
</Expandable>

Here `matched` is `false` but `text` is real. It is the deepest unit that exists (`path` is `["2"]`). Do not present it as the answer to `(2)(1)`.

<CodeGroup>
```python Python
pin = data["pinpoint"]
if pin["matched"]:
    use(pin["text"], pin["leadIn"])
elif pin["matchLevel"] == "ancestor":
    # The section has a unit above the one requested. Show it as context
    # and tell the reader which part was not found.
    print("Not found:", pin["unmatched"], "-", pin["note"])
    print("Closest unit:", pin["label"])
elif pin["reason"] == "no_structure":
    # We could not recover this section's outline. The text is still at /body.
    fetch_full_body(data["section"]["actId"])
else:
    print("No such subsection. Labels that exist:", pin.get("available"))
```

```javascript JavaScript
const pin = data.pinpoint;
if (pin.matched) {
  use(pin.text, pin.leadIn);
} else if (pin.matchLevel === "ancestor") {
  // The section has a unit above the one requested. Show it as context
  // and tell the reader which part was not found.
  console.warn("Not found:", pin.unmatched, "-", pin.note);
  console.log("Closest unit:", pin.label);
} else if (pin.reason === "no_structure") {
  // We could not recover this section's outline. The text is still at /body.
  await fetchFullBody(data.section.actId);
} else {
  console.warn("No such subsection. Labels that exist:", pin.available);
}
```
</CodeGroup>

The reasons:

- `no_such_subsection`: the section has no such unit. `available`, when present, lists the labels that exist.
- `no_structure`: we could not get the section's outline. The text is still at `/body`.

If the response has `pinpointNote` and no `pinpoint`, the unit could not be looked up. The call is charged, and a retry usually works.

## Other ways to get a pinpoint

Three more routes return the same `pinpoint` object.

### Pinpoints in a document

`POST /us/statutes/extract-citations` finds every citation in a block of text. With `resolve: true`, it resolves each one.
It is priced per distinct citation.

<Accordion title="Request, response and range rules">
The two citations below cost 4 credits.

```bash
curl -X POST https://api.vaquill.ai/api/v1/us/statutes/extract-citations \
  -H "Authorization: Bearer $VAQUILL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "The speed limit in an urban district is set by 625 ILCS 5/11-601(c). Intentional homicide is covered by Wis. Stat. 940.01(1)(a).",
    "resolve": true
  }'
```

A trimmed response, keeping the fields used here:

```json
{
  "citations": [
    {
      "citation": "Wis. Stat. 940.01",
      "raw": "Wis. Stat. 940.01(1)(a)",
      "pinpoint": "(1)(a)",
      "resolved": true,
      "actId": "STATE_WI_C940_S940.01"
    },
    {
      "citation": "625 ILCS 5/11-601",
      "raw": "625 ILCS 5/11-601(c)",
      "pinpoint": "(c)",
      "resolved": true,
      "actId": "STATE_IL_C625_A5_S11-601"
    }
  ],
  "counts": { "found": 2, "distinctSections": 2, "resolved": 2, "unresolved": 0, "skipped": 0 },
  "creditsConsumed": 4.0
}
```

Each row has `pinpoint` (as printed in your text) and `raw` (the full citation as printed).
A row also has `pinpointMatch`, the same block as `pinpoint` above, when the unit was found in the same call. Read `pinpointMatch.matched` first.

Each row has `charStart` and `charEnd`, the span of the first mention of `raw` in your `text`, so `text[charStart:charEnd] == raw`.
Offsets count Unicode code points. Both are null for a row with no span of its own, such as one section from a list like `§§ 1981, 1983`.

A range returns its two ends as resolved rows, and the sections between them as `interior` rows.
`18 U.S.C. §§ 2510 through 2523` gives rows with `rangeRole` `start` and `end`. Each has `rangePartner` naming the other end, and each end is charged as its own section.
For a range written with a word (`§§ 101 through 105`), the sections between come back with `rangeRole` `interior`, `skipped` `range_interior` and `rangePartner` set to the range start.
Interior rows are never resolved or charged. At most 25 are listed per range and 500 per call.
`counts.found` counts rows. `counts.distinctSections` counts sections, which sets the price and the per-call cap.

If the corpus is unavailable, or half or more of the citations cannot be read, the call returns 503 and is fully refunded.

When a row has no `pinpointMatch`, resolve its `raw` to get the unit. Send the raw values in one batch of up to 50 (see [batch resolve](/api-guide/recipes/citation-lookup#resolve-a-whole-documents-citations-at-once)).
</Accordion>

### Pinpoints from an act ID you already hold

If you have an `actId`, ask the body route for the unit. You get the full body and the unit together.
A body with a pinpoint costs 6 credits.

<Accordion title="Request, response and offset check">
```bash
curl -G https://api.vaquill.ai/api/v1/us/statutes/section/STATE_IL_C625_A5_S11-601/body \
  -H "Authorization: Bearer $VAQUILL_API_KEY" \
  --data-urlencode "pinpoint=(c)(1)"
```

A trimmed response (`html` and `plain` carry the whole section and are cut here):

```json
{
  "actId": "STATE_IL_C625_A5_S11-601",
  "plain": "(625 ILCS 5/11-601) (from Ch. 95 1/2, par. 11-601) Sec. 11-601. General speed restrictions. ...",
  "sourceUrl": "https://www.ilga.gov/legislation/ilcs/documents/062500050K11-601.htm",
  "available": true,
  "pinpoint": {
    "requested": "(c)(1)",
    "path": ["c", "1"],
    "label": "1.",
    "level": "paragraph",
    "matched": true,
    "matchLevel": "exact",
    "text": "30 miles per hour; and",
    "leadIn": [
      {
        "path": ["c"],
        "label": "(c)",
        "text": "Unless some other speed restriction is established under this Chapter, the maximum speed limit in an urban district for all vehicles is:"
      }
    ],
    "fullText": "1. 30 miles per hour; and",
    "children": [],
    "siblings": { "previous": null, "next": "2" },
    "charStart": 1634,
    "charEnd": 1659,
    "structure": {...}
  },
  "creditsConsumed": 6.0
}
```

`charStart` and `charEnd` index into `plain` in the same response. Here `plain[1634:1659]` is the unit's `fullText`.
`structure.textSha256` is the SHA-256 of `plain`. Use it to check that stored text still matches the offsets:

```python
import hashlib

if hashlib.sha256(plain.encode("utf-8")).hexdigest() != pin["structure"]["textSha256"]:
    # The section text changed since you stored it. Fetch the body again
    # and use the new offsets.
    refresh()
```

A malformed `pinpoint`, or a `pinpoint` sent with `asOf`, returns `422` and is not charged.
</Accordion>

### Which subsection did a search hit match

Search ranks whole sections.
Set `includePinpoint: true` to name the matched subsection of each hit, in a `pinpoints` object keyed by `actId`. It adds no cost.

<Accordion title="Request, response and how to read it">
```bash
curl -X POST https://api.vaquill.ai/api/v1/us/statutes/search \
  -H "Authorization: Bearer $VAQUILL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query": "30 mph urban district speed limit", "state": "il", "includePinpoint": true, "limit": 2}'
```

The first of the two hits, trimmed to the `pinpoints` entry that goes with it:

```json
{
  "results": [
    { "actId": "STATE_IL_C625_A5_S11-601", "citation": "625 ILCS 5/11-601" }
  ],
  "pinpoints": {
    "STATE_IL_C625_A5_S11-601": {
      "located": true,
      "path": ["c", "1"],
      "label": "1.",
      "level": "paragraph",
      "pinpoint": "(c)(1)",
      "citation": "625 ILCS 5/11-601(c)(1)",
      "text": "30 miles per hour; and",
      "leadIn": [
        {
          "path": ["c"],
          "label": "(c)",
          "text": "Unless some other speed restriction is established under this Chapter, the maximum speed limit in an urban district for all vehicles is:"
        }
      ],
      "charStart": 1634,
      "charEnd": 1659,
      "matchedBy": "passage",
      "scope": "unit",
      "matchedTerms": ["30", "urban", "district", "speed", "limit"],
      "structure": {...}
    }
  }
}
```

The `citation` can go straight into `/us/statutes/resolve`.
`matchedBy: "passage"` means the unit lies inside the matched passage. `scope: "unit"` means one unit matched best.
The second hit, `625 ILCS 5/11-604`, has `scope: "parent"`. Several sub-units matched about equally, so the block names their common parent, `(b)`.

A hit that cannot be named says why in `reason`. This does not change which sections are returned or their order.
</Accordion>
