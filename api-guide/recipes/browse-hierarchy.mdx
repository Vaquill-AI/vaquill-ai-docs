---
title: "Browse the statute hierarchy"
description: "Walk a code top to bottom with /us/statutes/divisions: titles, chapters, parts, articles, rule sets and sections in statutory order"
---

Build a table of contents for any code or title. Show a law as a tree, in the order a person reads it.

Search finds the section that answers a question. To list the structure (titles, chapters, sections), use `GET /us/statutes/divisions`. Each call returns the children of one level.

**Endpoint:** `GET /us/statutes/divisions`. **Credits:** 1 per call. An empty level costs nothing.

<Note>
  Browse supports `USC`, `CFR`, `STATE`, `REGULATION`, `STATE_RULES`, `CONSTITUTION`, `STATE_CONSTITUTION` and `FEDERAL_RULES`.
  Each legend entry on `GET /us/statutes/coverage` has a `browsable` flag.
  Executive actions, the Federal Register and agency guidance have no common tree. Use `POST /us/statutes/search` for those (see the [Quickstart](/api-guide/quickstart)).
  A request with filters that do not fit the corpus returns `422` and is not charged.
</Note>

## How drilling works

Pass the deepest level you know. The response returns the level directly below it.

The levels depend on the code, and one listing can mix kinds. A state code lists chapters and loose sections together.
Read `level` and each node's `kind` on every response. Keep drilling until `isLeaf` is `true`.

| You pass | You get back (`level`) |
|---|---|
| `corpusType=USC` | the USC `titles` |
| `corpusType=USC&titleNumber=42` | the `chapters` in Title 42 |
| `corpusType=CFR&titleNumber=17&part=240` | the `subparts` and `subjectGroups` of Part 240 (a part with neither lists its sections) |
| `corpusType=STATE&state=tx&code=tx_pe` | the `titles` of the Texas Penal Code |
| `corpusType=REGULATION&state=ny&code=ny_10&chapter=I` | the `parts` in Chapter I of 10 NYCRR |

| You pass | You get back (`level`) |
|---|---|
| `corpusType=USC&titleNumber=42&chapter=21` | the `subchapters` of Chapter 21 (a chapter with no subchapters lists its sections) |

| `corpusType=USC&titleNumber=8&chapter=12&subchapter=II` | the `parts` of Subchapter II, which sit below the chapter in this title |
| `corpusType=CFR&titleNumber=17` | the `chapters` in Title 17 (Chapter I and Chapter II, each an agency) |
| `corpusType=CFR&titleNumber=17&chapter=II` | the `parts` in Chapter II of Title 17 |
| `corpusType=CFR&titleNumber=17&part=240&subpart=A` | the subject groups of Subpart A |
| `corpusType=STATE&state=tx` | the state's `codes` |
| `corpusType=STATE&state=tx&code=tx_pe&title=5` | the `chapters` in Title 5 of the Texas Penal Code |
| `corpusType=STATE&state=ca&code=ca_pen` | the `parts` of the California Penal Code, with any section outside a part beside them |
| `corpusType=STATE&state=il&code=il_225` | the `acts` in 225 ILCS, a code that is a single chapter |
| `corpusType=STATE&state=ny&code=ny_jud&article=2` | the `sections` in a New York article (New York is divided by article, not chapter) |
| `corpusType=STATE&state=de&code=de_6&article=2` | the `parts` of UCC Article 2 in Delaware Title 6, which sits outside any chapter |
| `corpusType=REGULATION&state=me&code=me_regs-me` | Maine's `umbrellas`, one per department |
| `corpusType=REGULATION&state=me&code=me_regs-me&umbrella=10` | the `agencies` under umbrella `10` (Health and Human Services) |
| `corpusType=REGULATION&state=me&code=me_regs-me&umbrella=10&agency=144` | the `chapters` of agency `144`, the right ones even though a chapter number repeats under other agencies |
| `corpusType=CONSTITUTION` | the `articles` and amendments of the US Constitution |
| `corpusType=CONSTITUTION&article=Amendment XIV` | the `sections` of the Fourteenth Amendment (leaf) |
| `corpusType=STATE_CONSTITUTION&state=nm` | the `articles` of the New Mexico Constitution |
| `corpusType=FEDERAL_RULES` | the rule sets (`codes`): FRCP, FRE, FRCrP, FRAP, FRBP, Supreme Court Rules |
| `corpusType=FEDERAL_RULES&code=frcp` | the Federal Rules of Civil Procedure (leaf) |
| `corpusType=STATE_RULES&state=tx` | the state's court rule sets, such as the local rules of one trial court |
| `corpusType=STATE_RULES&state=tx&code=HARRIS` | the levels and rules inside one rule set |

Federal rules appear as two rule sets: `frcp`, `fre` and so on, and the U.S. Code appendix copies such as `uscapp_t28a_fre`.
On `CFR`, `chapter` is ignored when you also pass a `part`.

<Accordion title="Filters by level">

The listing takes one filter per level. Pass the `identifier` of a node whose `kind` names that level. Text filters are case-insensitive.
The state-only filters all need `code`.

| Filter | Level it lists | Applies to | Needs |
|---|---|---|---|
| `title` | a title inside a code (`kind: title`), such as Title 5 of the Texas Penal Code | State codes and regulations | `code`. A U.S. Code or CFR title is `titleNumber`. |
| `subtitle` | a subtitle | U.S. Code and state codes | `titleNumber` (U.S. Code); `code` and the `title` it sits in (state) |
| `division` | a division | U.S. Code, as in Title 54, and state or regulation codes such as California's | `titleNumber` (U.S. Code); `code` (state) |
| `subdivision` | a subdivision | U.S. Code only, Title 54 | the `division` it belongs to |
| `part` | a part | CFR, U.S. Code, and state codes or rule sets wherever a listing returned `kind: part` | `code` on a state code or rule set |
| `subpart` | a subpart | U.S. Code, CFR, and Louisiana and Mississippi regulation codes | `part` and `titleNumber` (U.S. Code); `titleNumber` and `part` (CFR); `code` and the `part` it sits in (LA, MS) |
| `subjectGroup` | a subject group | CFR only | `titleNumber` and `part`, and the `subpart` when the group sits inside one |
| `subchapter` | a subchapter | U.S. Code and state codes or rule sets | `titleNumber` and `chapter` (U.S. Code); `code` (state) |
| `act` | an act | State codes and court rules only, such as an Illinois act inside an ILCS chapter | `code` |
| `umbrella` | an umbrella | State regulations only (Maine groups agencies under a department umbrella) | `code` |
| `agency` | an agency | State regulations only (Maine, Virginia, Wyoming). Name it to open the right chapter, because a chapter number repeats under different agencies | `code` |
| `program` | a program | State regulations only (Wyoming prints a program between an agency and its chapters) | `code` |

</Accordion>
</AccordionGroup>

`excludeRepealed` and `actStatus` narrow any listing by section status, as they do on search.

Interior nodes carry a `sectionCount` and `isLeaf: false`. Pass the `identifier` back as the filter named by its `kind`. (`title` is `titleNumber` on the U.S. Code and CFR, and `title` inside a state code.)
Leaf nodes are sections with `isLeaf: true` and an `actId`. Pass it to [`/us/statutes/section/{actId}`](/api-guide/concepts/section-ids).
Lists come back in statutory order: `9` before `10`, `240.9` before `240.10`.

## One level

<CodeGroup>
```bash cURL
curl -G https://api.vaquill.ai/api/v1/us/statutes/divisions \
  -H "Authorization: Bearer vq_key_..." \
  --data-urlencode "corpusType=USC" \
  --data-urlencode "titleNumber=42"
```

```python Python
import requests

resp = requests.get(
    "https://api.vaquill.ai/api/v1/us/statutes/divisions",
    headers={"Authorization": "Bearer vq_key_..."},
    params={"corpusType": "USC", "titleNumber": 42},
)
data = resp.json()
print(data["level"], "under", data["parentLabel"])
for node in data["divisions"]:
    print(f'  {node["identifier"]}  {node["name"] or ""}  ({node.get("sectionCount")} sections)')
```

## State regulations: umbrella, agency and program

Maine, Virginia, Wyoming, Louisiana and Mississippi regulation codes have agency-style levels. Name the level to open the right chapter.

<Accordion title="State regulations with agency levels">

Some state regulation codes list the issuing body above its chapters. A chapter number can repeat under different bodies, so name the body first.

- **Maine** groups agencies under a department umbrella, then lists the agency's chapters.
- **Virginia** lists agencies, inside a title.
- **Wyoming** lists agencies, then a program between the agency and its chapters. Chapter `1` repeats under every program, so pass the `program` too.
- **Louisiana and Mississippi** list `subpart` nodes inside a part. Pass the `part` and the `subpart` with `code`.

Walk Maine one level at a time. Pass each `identifier` back as the filter its `kind` names.
Take `code` from the `codes` listing of `corpusType=REGULATION&state=me` (`me_regs-me` below).

```bash
# 1. The root of the code lists its umbrellas (kind: umbrella)
curl -H "Authorization: Bearer vq_key_..." \
  "https://api.vaquill.ai/api/v1/us/statutes/divisions?corpusType=REGULATION&state=me&code=me_regs-me"

# 2. umbrella=10 (Health and Human Services) lists its agencies (kind: agency)
curl -H "Authorization: Bearer vq_key_..." \
  "https://api.vaquill.ai/api/v1/us/statutes/divisions?corpusType=REGULATION&state=me&code=me_regs-me&umbrella=10"

# 3. Adding agency=144 lists the chapters of that agency (kind: chapter)
curl -H "Authorization: Bearer vq_key_..." \
  "https://api.vaquill.ai/api/v1/us/statutes/divisions?corpusType=REGULATION&state=me&code=me_regs-me&umbrella=10&agency=144"
```

Each call costs 1 credit. Keep the filters you already passed at every step.
The walk helper below already handles `umbrella`, `agency` and `program`.

</Accordion>

## Walk a whole title

Drill from a title down to the leaves. A leaf carries the `actId` for metadata or full text.
The walk is recursive: pass each node back as the filter its `kind` names.

```python Python
import requests

BASE = "https://api.vaquill.ai/api/v1/us"
HEADERS = {"Authorization": "Bearer vq_key_..."}

# The request filter each kind of node drills with. `title` is `titleNumber`
# on the U.S. Code and the CFR, and `title` inside a state code.
FILTER = {"title": "titleNumber", "chapter": "chapter", "subchapter": "subchapter",
          "part": "part", "subpart": "subpart", "subjectGroup": "subjectGroup",
          "subtitle": "subtitle", "division": "division", "subdivision": "subdivision",
          "article": "article", "act": "act", "code": "code",
          "umbrella": "umbrella", "agency": "agency", "program": "program"}


def children(**scope) -> list[dict]:
    """Every node one level down, following `nextCursor` across pages."""
    out, cursor = [], None
    while True:
        params = {**scope, **({"cursor": cursor} if cursor else {})}
        resp = requests.get(f"{BASE}/statutes/divisions", headers=HEADERS, params=params)
        resp.raise_for_status()
        page = resp.json()
        out += page["divisions"]
        cursor = page.get("nextCursor")
        if not cursor:
            return out


def walk(scope: dict, depth: int = 0) -> None:
    for node in children(**scope):
        if node["isLeaf"]:
            # node["actId"] -> feed into POST /us/statutes/sections (see below)
            print("  " * depth + f'§ {node["identifier"]}  {node["name"] or ""}  [{node["actId"]}]')
        else:
            print("  " * depth + f'{node["kind"]} {node["identifier"]}  {node["name"] or ""}')
            walk({**scope, FILTER[node["kind"]]: node["identifier"]}, depth + 1)


walk({"corpusType": "USC", "titleNumber": 4})
```

<Warning>
  A large container comes back in more than one page.
  Check `truncated` on every section listing. When it is `true`, pass `nextCursor` back as `cursor` until it is `null`. `children()` above does this.
</Warning>

<Accordion title="Paging and search caps">

Each page is sorted, but pages are not. Sort the full list yourself after you fetch every page.

Do not use `POST /us/statutes/search` to list a container. Ranked search caps at 120 results per query.

</Accordion>

## Export a container with its text

Listing gives you identifiers. To get text, send the `actId` values to `POST /us/statutes/sections` with `includeBody`, 50 at a time.

```python
def export_container(**scope) -> list[dict]:
    ids = [s["actId"] for s in children(**scope) if s.get("actId")]
    out = []
    for i in range(0, len(ids), 50):
        resp = requests.post(
            f"{BASE}/statutes/sections",
            headers=HEADERS,
            json={"actIds": ids[i : i + 50], "includeBody": True},
        )
        resp.raise_for_status()
        out += resp.json()["sections"]
    return out
```

`includeBody` bills the body price for each row that returns text. Rows with `body: null` are not charged. Read `creditsConsumed` on each response.

Text is the costly part. To filter, use metadata first (omit `includeBody`) and fetch bodies only for what you keep.

To size an export, call `POST /us/statutes/count` with the same scoping filters. It returns an exact section count for one credit.

## Search within a container

A search result from any browsable corpus carries a `parent`: the query that lists its siblings.
Every key in it (`titleNumber`, `chapter`, `part`, `code`, `article`) is also a `POST /us/statutes/search` filter. Use it to search inside the hit's chapter, part, article or rule set.

<Accordion title="The parent object for every browsable corpus">

| A hit from | carries a `parent` like |
|---|---|
| `USC` | `{"corpusType": "USC", "titleNumber": 42, "chapter": "21"}` |
| `CFR` | `{"corpusType": "CFR", "titleNumber": 17, "part": "240"}` |
| `STATE` / `REGULATION` | `{"corpusType": "STATE", "state": "tx", "code": "tx_pe", "chapter": "31"}` |
| a New York code | `{"corpusType": "STATE", "state": "ny", "code": "ny_jud", "article": "2"}` |
| `CONSTITUTION` | `{"corpusType": "CONSTITUTION", "article": "Amendment XIV"}` |
| `STATE_CONSTITUTION` | `{"corpusType": "STATE_CONSTITUTION", "state": "nm", "article": "Article IV"}` |
| `FEDERAL_RULES` | `{"corpusType": "FEDERAL_RULES", "code": "frcp"}` |

</Accordion>

The same object works unchanged on `GET /us/statutes/divisions`.

```python Python
import requests

BASE = "https://api.vaquill.ai/api/v1/us"
HEADERS = {"Authorization": "Bearer vq_key_..."}


def search(body: dict) -> dict:
    resp = requests.post(f"{BASE}/statutes/search", headers=HEADERS, json=body)
    resp.raise_for_status()
    return resp.json()


# 1. Find one on-point section.
hit = search({"query": "insider trading", "corpusType": "CFR", "limit": 1})["results"][0]

# 2. Reuse its parent to search only within that part (17 C.F.R. Part 240).
neighbors = search({"query": "manipulative devices", "limit": 10, **hit["parent"]})
for r in neighbors["results"]:
    print(r["actId"], r["citation"])
```

`chapter` and `part` take one value or a list. Pair them with `titleNumber` (USC/CFR) or `code` (state). `parent` always includes these. An unpaired `chapter` or `part` returns `422`.
Shape errors return `422` and are not charged.

<Accordion title="Rules for article and federal rule sets">

`article` labels repeat, so it follows the same rule:

- It needs a `corpusType` from one family. Use `CONSTITUTION` or `STATE_CONSTITUTION` for the article label browse lists (`Amendment XIV`). Use `STATE` or `REGULATION` for a code divided by article (New York's `2-A`).
- `STATE_CONSTITUTION` also needs `state`.
- On `STATE` or `REGULATION` it needs `code`, and it cannot be combined with `chapter`.

Pass the `identifier` as the listing returned it. Case does not matter.

A federal rule set is a `code` under `corpusType=FEDERAL_RULES`: `frcp`, `fre`, `frcpsuppadm`, or an appendix copy such as `uscapp_t28a_fre`.
Without that `corpusType`, the request is refused.
`code=frcp` is the Federal Rules of Civil Procedure alone. `source=frcp` also covers the FRCP supplemental rules.

</Accordion>
