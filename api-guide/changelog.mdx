Dated changes to the Vaquill Developer API: new endpoints, new corpora, fixes and behavior changes.
Newest first.
Every entry carries tags (Corpus, Endpoint, Fix, Breaking, SDK, Docs), and each entry is an item in this page's RSS feed.
Counts in an entry are the counts on its date.
For current numbers call [`GET /us/statutes/coverage`](/api-guide/concepts/jurisdictions).
Older entries may name bare routes such as `/statutes/laws` that are deprecated but still live.
The documented routes are under `/us/statutes/`.

## Change policy

| Kind | What it covers | Tag |
|---|---|---|
| Additive | A new endpoint, optional parameter or optional response field, and a new `corpusType`, `source` or error `code` value | Corpus, Endpoint |
| Breaking | A removed or renamed field, endpoint or token, a changed meaning of a value, accepted input that becomes a `422`, or documents that move between tokens | Breaking |
| Fix | A wrong answer, charge or count corrected without changing the documented shape | Fix |

- Write clients to ignore response fields and enum values they do not know.
- A key documented as conditional is omitted when it does not apply.
  See [Treat a missing optional key as not applicable](/api-guide/best-practices#treat-a-missing-optional-key-as-not-applicable).
- A Breaking entry has a **Changed** heading that says what to do, and an entry that deprecates a route says so.
- SDK releases are announced here with the **SDK** tag.
  See [SDKs](/api-guide/sdks/overview).
- To be told when the law changes, not when the API changes, use [Law change alerts](/api-guide/alerts).

<Update label="2026-11-07" description="Null policy, error codes, per-key limits, refunds" tags={["Breaking", "Endpoint", "Fix"]}>

### Changed: statute rows omit conditional fields that do not apply

Statute responses now follow one null policy.

- **Core fields:** always present, and `null` when unknown (for example `citation`, `state`, `effectiveDate`).
- **Conditional fields:** omitted when they do not apply. Some were sent as `null` before.
- **What to do:** treat a missing conditional key as "not applicable". A client that reads `row["note"]` without a default now fails on rows where it used to get `null`.

See [Treat a missing optional key as not applicable](/api-guide/best-practices#treat-a-missing-optional-key-as-not-applicable).

<Accordion title="Changed: cross-state `statesCovered`">

- `statesCovered` on `GET /us/statutes/section/{actId}/cross-state` counts the other states actually examined, whether or not they appear in `neighbors`.
- A response with `rankingDegraded: true` is refunded (`creditsConsumed` 0).

See [multi-state comparison](/api-guide/recipes/multi-state-comparison).

</Accordion>

<Accordion title="Changed: cited-by `total` and new `returned`">

- On `GET /us/statutes/section/{actId}/cited-by`, `total` is now the count of citing sections across all pages (same as `totalCiters`), not the page size.
- New `returned` field: the number of rows on this page.

See [section intelligence](/api-guide/concepts/section-intelligence#cited-by-the-reverse-index).

</Accordion>

<Accordion title="Changed: extract-citations spans, ranges and outages">

- **Spans:** each row carries `charStart` and `charEnd`, the span of its first mention, so `text[charStart:charEnd] == raw`. Both are null when the row has no span.
- **Ranges:** a range such as `18 U.S.C. §§ 2510 through 2523` returns two rows marked `rangeRole` (`start` or `end`), with `rangePartner` naming the other end.
- **Interior rows:** a range written with a word (`§§ 101 through 105`) returns the sections between its ends as rows. They carry `rangeRole: "interior"` and `skipped: "range_interior"`. `rangePartner` is the range start. A hyphenated range stays two ends.
- **Limits:** at most 25 interior sections per range and 500 per call. A wider range returns its two ends and a `notes` entry.
- **Billing:** interior rows are never resolved or billed. Use `GET /us/statutes/resolve` to resolve one.
- **Counts:** `counts.distinctSections` is the billing unit. `counts.found` still counts rows. `counts.interior` counts interior rows, which are not in `counts.found`.
- **Outage:** if the corpus is unavailable, or half or more of the citations cannot be read, the call answers `503` and is fully refunded.

See [pinpoints in a document](/api-guide/recipes/pinpoint-subsection#pinpoints-in-a-document).

</Accordion>

<Accordion title="Changed: search billing and `excerptChars`">

- **Charged:** a search with `noGoodMatch: true`. An empty page with no filters is also charged.
- **Refunded:** a filtered search with an empty page (no match, or `offset` past the last result), with a note naming the filters. Also refunded: a page with `rankingDegraded: true` (bodies already delivered by `includeBody` stay charged).
- **`includeBody`:** adds the body price per row that returns text. Rows without a resolvable body are not charged for it.
- **Pinpoints:** `includePinpoint` lookups are never charged on their own.
- **Billing:** read `creditsConsumed` for what was billed.
- **`excerptChars`:** the range is 100 to 600. Other values are a `422`.
- **`fields`:** `includeBody: true` always adds `body` to `fields`, and `notes` says so.
- **`rankingPartial`:** pages served from a partial ranking carry `rankingPartial: true`, including pages 2 and later. Repeating the call may return the full ranking.

See [what a search costs](/api-guide/concepts/search#what-a-search-costs).

</Accordion>

<Accordion title="Changed: validation and routes">

- **API keys:** `POST /api-keys` with `scopes: []` is a `422`. `allowedIps` is removed and is a `422`.
- **Batch sections:** `POST /us/statutes/sections` rejects unknown request fields with a `422`. Inline bodies are capped at 4,000,000 characters per response. Bodies past the cap come back `null` with `bodyNote: response_size_cap` and are not charged.
- **Section body:** a future `asOf` is a `422`, and so is `structured` combined with `asOf`.
- **Session laws list:** `order` accepts `asc` (default) or `desc`. A blank `jurisdiction` is a `422`. A date filter the data cannot satisfy returns an empty page with `coverage.status: filter_unavailable`, names `unavailableFilters`, and is not charged.
- **Resolve:** a proposed Treasury regulation (`Prop. Treas. Reg.`) answers `missReason: out_of_scope_corpus` with a `missReasonHint`. Proposed rules are Federal Register documents.

</Accordion>

<Accordion title="Changed: resolve rejects malformed input before any charge">

`GET` and `POST /us/statutes/resolve` answer `422` with code `invalid_citation_input` for a `corpusType` or `state` they do not accept. This was a `400` that refunded the charge. Nothing is charged now.

</Accordion>

<Accordion title="Changed: coverage, divisions and count">

- `GET /us/statutes/coverage`: an unknown `state` is a `422`, not an empty `200`.
- `GET /us/statutes/divisions`: a backend outage answers `503` and is not charged.
- `POST /us/statutes/count`: a backend outage answers `503` and is refunded. A count of zero is refunded.

</Accordion>

<Accordion title="Changed: error codes and the `402` body">

- **New codes:** `method_not_allowed` (`405`, with an `Allow` header), `payload_too_large` (`413`), `unsupported_media_type` (`415`), `upstream_timeout` (`504`).
- **Renamed defaults:** a generic `400` has code `bad_request`, a session-law `404` has `section_not_found`, and the watch-cap `429` has `quota_exceeded` with `retryable: false`.
- **Every `404` and `405`:** the body carries `code` and `requestId`.
- **Test delivery:** the cooldown `429` sends `Retry-After: 30`.
- **`402`:** the body adds `creditsRequired`, `creditsAvailable` and `topUpHint` when known.

See [Errors](/api-guide/errors).

</Accordion>

<Accordion title="Changed: rate limits are per key">

- A valid API key has its own bucket at your plan limit. It no longer shares one with other callers on the same IP.
- A per-address ceiling of 10 times that limit also applies. Invalid keys fall into the shared per-address bucket.
- New header `X-RateLimit-Scope` (`key` or `ip`) says which bucket the other `X-RateLimit-*` numbers describe. Sent on API-key requests only.

See [Rate limiting](/api-guide/errors#rate-limiting).

</Accordion>

<Accordion title="Changed: refunds are tied to the charge">

- A refund reverses one specific charge and never exceeds it.
- Credits return to the bucket they came from. If that bucket has expired, they return as a new 30-day bucket.

</Accordion>

<Accordion title="Changed: session-law change feed fills `mergedInto`">

On `GET /us/session-laws/changes`, a `merged` change now carries `mergedInto`, the `sessionLawId` of the law it merged into. It was always `null`.

See [session laws](/api-guide/session-laws).

</Accordion>

<Accordion title="Changed: what an `Idempotency-Key` stores">

- Only `2xx`, `400` and `422` responses are stored and replayed for 24 hours.
- Other `4xx` responses and refunded calls are not stored, so a retry runs again.
- If you disconnect after being charged, the charge is refunded and the key is released.

See [Idempotency](/api-guide/sdks/overview#idempotency).

</Accordion>

<Accordion title="Changed: watch `corpusType` is an enum">

- `corpusType` on `POST /watches` now publishes the list of watchable boards.
- Accepted: the board key (`state_regulation`) or the search-style token (`REGULATION`, `USC`). Case does not matter.
- Anything else is a `422` listing the allowed values.
- Not watchable: `constitution`, `executive_action`, `agency_action`, `cfr_annual`, `usc_annual`, `federal_rules_annual`, `federal_rules_proposed`, `us_treaty`, `state_session_law`, `state_register` and `federal_bill`.

See [Law Change Alerts](/api-guide/alerts).

</Accordion>

<Accordion title="Changed: empty rulemaking pages are refunded">

- Empty pages of `GET /us/rulemaking/dockets/list`, `GET /us/rulemaking/dockets/{docketId}/documents` (for a docket we hold) and `GET /us/rulemaking/committee-records/list` answer `creditsConsumed: 0` with a `note` naming the filters.
- A `pageFrom` past the last page of a committee record sets `textNotice`.

See [rulemaking](/api-guide/rulemaking).

</Accordion>

<Accordion title="Changed: session-law search billing and the `session` filter">

- A filtered `POST /us/session-laws/search` with an empty first page is refunded, with a `note` naming the filters. An unfiltered empty search stays charged.
- The `session` filter now also applies to text, phrase and citation searches.

See [searching the text](/api-guide/session-laws#filters-and-paging).

<Accordion title="Changed: section lookups, neighbours and Boolean paging">

- `GET /us/statutes/section`: if the Federal Register related-documents scan fails, the call is not charged and the note says to repeat it.
- `GET /us/statutes/section/{actId}/related` now finds siblings whose records lack a state or title number.
- Boolean search: a page with selective filters now comes back full. `hasMore` is `false` once every candidate has been judged.

<Accordion title="Changed: the `StatuteResult` schema and `amendmentsCount`">

- The published `StatuteResult` schema lists its 49 core fields as required, each nullable where the value can be null.
- With a `fields` projection, only the keys you requested come back.
- `amendmentsCount` is capped at the length of `amendmentYears`, except for eCFR, state regulations, and state and federal court rules, which count amendment events.

</Accordion>

<Accordion title="Changed: definitions scope and errors">

- `GET /us/statutes/section/{actId}/definitions` refuses a definitions section scoped to a different chapter, subchapter or part. The call is not charged and the `note` names the differing container.
- If a container is unknown, the terms are kept and the `note` says scope could not be verified.
- A failed scan answers `500` and is refunded.

See [definitions](/api-guide/concepts/section-intelligence#definitions-the-terms-that-govern-a-section).

- A chapter cite such as `M.G.L. c. 265` or `Minn. Stat. ch. 609` answers `matchLevel: container` again, not `multiple`.
- `Ga JQC R 17` and `Ga JQC R 17(a)` resolve to the Judicial Qualifications Commission rule.

<Update label="2026-11-06" description="Federal Rules past texts, pending amendments, committee notes" tags={["Corpus", "Endpoint", "Fix"]}>

### New: `FEDERAL_RULES_ANNUAL` and `FEDERAL_RULES_PROPOSED`

Two opt-in tokens hold the Federal Rules' past texts and pending amendments. Neither is part of an unscoped search, and neither is watchable.

- **`FEDERAL_RULES_ANNUAL`:** 1,125 superseded texts of 510 Federal Rules. The `actId` is the current rule's `actId` plus `_E` and the year, for example `{actId}_E2015`. Use `FEDERAL_RULES` for the rule in force.
- **`asOf` on a Federal Rule:** `GET /us/statutes/section/{actId}/body?asOf=YYYY-MM-DD` with the current `actId` answers from these texts. The record begins 1998-01-26. An earlier date returns the earliest text with `asOf.isBounded: true`.
- **`FEDERAL_RULES_PROPOSED`:** 49 pending amendment documents on 36 current rules. The `actId` is the current rule's `actId` plus `_P` and the cycle year. `actStatus` is `proposed`.
- **`pendingAmendments`:** a Federal Rule result lists its pending amendments with `id`, `status`, `cycle`, `effectiveDate`, `commentPeriodEnd`, `sourceUrl`, `textComplete` and `commentDocketIds`. Absent when nothing is pending.

See [Corpus types](/api-guide/concepts/corpus-types), [Point-in-time law](/api-guide/point-in-time) and [Federal coverage](/api-guide/coverage/federal).

<AccordionGroup>
<Accordion title="New: committeeNotes and committeeNote1937Print on Federal Rules">

`GET /us/statutes/section/{actId}/body` on a Federal Rule now returns its Committee Note one amendment at a time. For the Civil Rules it also returns the original 1937 note.

- **`committeeNotes`:** a list in print order. Each entry has `year`, `kind`, `heading`, `text`, `effectiveDate` and `subdivisionsDiscussed`. `notes` is unchanged.
- **`committeeNote1937Print`:** the 1937 Advisory Committee note as printed in H.R. Doc. No. 588 (1938), with a `verdict` against the compiled note: `agrees`, `differs`, `print_only` or `none_printed`.
- **`printTextStatus`:** `verified` only when the print agrees with the compiled note. Otherwise it is `unverified_ocr`.
- **`format=operative`:** both fields are dropped, like `notes`.

See [Federal coverage](/api-guide/coverage/federal).

</Accordion>
<Accordion title="New: lifecycle events on Federal Rules watches">

A watch on a Federal Rule now fires when a pending amendment to that rule changes stage.

- **New optional keys:** `lifecycleStage` and `relatedActId` on changes in `GET /watches/{watchId}/changes`, on `changes[]` in a `board.updated` webhook, and on `GET /us/statutes/section/{actId}/changes`. Present only on lifecycle events.
- **Values:** `changeKind` is `amended`. `lifecycleStage` is one of `published_for_comment`, `approved_by_standing_committee`, `approved_by_judicial_conference`, `transmitted_to_supreme_court`, `adopted_by_supreme_court`, `transmitted_to_congress`, `in_force` or `withdrawn`. `relatedActId` is the `_P` document.
- **Counts:** lifecycle events are not counted in `sectionsAmended`.
- **Unchanged:** the `changeKind` enum is still `added`, `amended`, `removed`. Branch on `lifecycleStage` to tell a stage move from a text change.

See [Law change alerts](/api-guide/alerts#pending-federal-rules-amendments).

</Accordion>
<Accordion title="New: Rules Committee records">

Two metered routes under `/us/rulemaking/committee-records/` serve Judicial Conference Rules Committee records: minutes, agenda books, reports, rules packages, drafts, public comments and rules suggestions.

- **Endpoints:** `GET /us/rulemaking/committee-records/list` (1 credit per page) and `GET /us/rulemaking/committee-records/{recordId}` (2 credits).
- **Filters:** `committee`, `docType`, `year`, `ruleSet`, `rule` (needs `ruleSet`) and `docketId`.
- **Links:** each record names its comment dockets and Federal Rules, with the `method` and `confidence` of each link.
- **Public comments and rules suggestions:** `title`, `filename` and page text are `null` and `textWithheld` is `true`. `sourceUrl` points at the original.

See [US Rulemaking](/api-guide/rulemaking#rules-committee-records).

</Accordion>

- `actStatus` of dead rules: abrogated US Code appendix rules now report `repealed`. Transferred rules (Appellate Rule 35, Criminal Rules 22 and 54) report `transferred`. `excludeRepealed=true` drops both.
- No change events were emitted.

<Update label="2026-10-25" description="Pinpoint lookups" tags={["Endpoint"]}>

### New: pinpoints

A citation such as `625 ILCS 5/11-601(c)` now returns the text of subsection (c) itself, not only the parent section.

- **`GET` and `POST /us/statutes/resolve`:** a pinpoint adds a `pinpoint` object beside `section`, on each batch item too. It has the unit's `text`, `leadIn`, `children`, `siblings`, character offsets and `structure`.
- **`GET /us/statutes/section/{actId}/body`:** pass `pinpoint=(c)(1)` to get one unit beside the full body.
- **`POST /us/statutes/extract-citations`:** a resolved row with a pinpoint gets `pinpointMatch`.
- **`POST /us/statutes/search`:** set `includePinpoint: true` to get `pinpoints`, keyed by `actId`.
- Labels with a hyphen or dot are one label: `(d-1)`, `(a-5)`, `(f)(1.5)`.
- A pinpoint the section does not have returns `matched: false` with `matchLevel`, `unmatched` and `available`. A section with no recoverable outline says `no_structure`.

See [Pinpoints](/api-guide/concepts/pinpoints).
</Update>

<Update label="2026-10-22" description="Boolean terms-and-connectors search" tags={["Endpoint"]}>

### New: Boolean search (`matchType: "boolean"`)

`POST /us/statutes/search` accepts a terms-and-connectors expression when you send `matchType: "boolean"`.

```json
{ "query": "\"security deposit\" /s (return OR refund) NOT commercial", "matchType": "boolean", "state": "ca" }
```

- **Operators:** `AND`, `OR`, `NOT`, `/s`, `/p`, `/N` (1 to 255), `+s`, `+p`, `+N`, `atleastN(term)`, `atmN(term)`, exact phrases, the wildcards `*`, `!` and `?`, and `( )`. Word operators are UPPERCASE.
- Other services' spellings such as `w/5`, `NEAR/5` and `ADJ` are accepted. See [Also accepted](/api-guide/concepts/boolean-search#also-accepted).
- **Field restrictions:** `title( )` and `cite( )`.
- **New response fields** (Boolean mode only): `parsedQuery` shows how the expression was read, and `queryWarnings` lists warnings about ambiguous expressions.
- In `any` mode, `queryHint` says when a query looks Boolean.
- A malformed expression is a `422` with the character position, and is not charged.
- Pricing: 4 credits per call. A `503` is refunded.
</Update>

<Update label="2026-10-06" description="State session law search, multi-value filters" tags={["Endpoint"]}>

### New: search state session laws

`POST /us/session-laws/search` finds state session laws by plain-language question, title words, quoted phrase, citation, code section or bill number. Results are ranked, each with the matching passage and a snippet. Costs 4 credits per page.

- It searches enacted text. Struck language is never searched.
- Ranking uses keyword relevance only. Each result says how it matched (`matchType`, `matchedBy`). There is no "no good match" flag.
- Filters: `jurisdiction`, `session`, `series`, `instrumentType`, `approvedFrom`, `approvedTo`. `limit` is 1 to 25, and `offset` plus `limit` reaches at most the 60 best matches.
- An empty result is charged. A validation failure is a `422` and is not charged.

See [Searching the text](/api-guide/session-laws#searching-the-text).

### Changed

- `series` and `instrumentType` on `GET /us/session-laws/list` take several values (repeat the parameter, combined with OR). A value outside the published list is a `422`, not an empty charged page.
- The OpenAPI document now publishes allowed values on each value of every enum field (`state`, `corpusType`, `source`, `fields`, `actStatus` and others). `actStatus` is now published on `POST /us/statutes/count` and `GET /us/statutes/divisions`.
