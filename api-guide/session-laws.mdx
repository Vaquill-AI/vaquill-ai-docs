A session law is an act as the legislature enacted it, before it is folded into a code.
It has the act's approval date, effective dates, the code sections it changed, and the text as passed.

Eight endpoints serve them.

| Endpoint | What it returns | Credits |
|---|---|---:|
| [`GET /us/session-laws/list`](/api-reference/us-session-laws/list-a-states-session-laws) | One state's session laws, filtered and paged | 1 per page |
| [`POST /us/session-laws/search`](/api-reference/us-session-laws/search-the-text-of-state-session-laws) | Find laws by what they say: a question, a title, a quoted phrase, a citation or a bill number. See [Searching the text](#searching-the-text) | 4 per page |
| [`GET /us/session-laws/{sessionLawId}`](/api-reference/us-session-laws/get-a-state-session-law-by-id-or-by-citation) | One law: identity, dates, outcome, sources, code sections affected | 2 by id, 4 by citation |
| [`GET /us/session-laws/{sessionLawId}/body`](/api-reference/us-session-laws/get-a-state-session-laws-text-current-or-a-past-version) | The law's text, paged | 6 per page |
| [`POST /us/session-laws/batch`](/api-reference/us-session-laws/get-many-state-session-laws-at-once-by-id-or-citation) | Up to 50 laws by id or citation, optionally with each one's first page of text | 2 per law served, +6 per text page |
| `GET /us/session-laws/{sessionLawId}/versions` | Every version of a law's text, newest first. See [Text reliability](#text-reliability-and-older-versions) | 1 |
| [`GET /us/session-laws/changes`](/api-reference/us-session-laws/feed-of-changes-to-the-session-law-registry) | What changed in the registry since your cursor | 1 per page |
| [`GET /us/statutes/section/{actId}/enactments`](/api-reference/us-statutes/which-acts-a-state-publisher-lists-against-this-section) | The session laws a publisher lists against one code section | 1 |

The federal Statutes at Large are served by `/us/statutes` under `corpusType=SESSION_LAW`. See [Corpus Types](/api-guide/concepts/corpus-types).

## What is held

State session laws cover the 50 states, the District of Columbia and Puerto Rico, from 1975 at the earliest.
Coverage by state and session is on `GET /us/statutes/coverage`, which is free.
Each jurisdiction's `sessionLaws` block lists its sessions with the session `year`, counts and a `status`.
A session with `status: "partial"` is incomplete, so an empty result there does not prove a law does not exist.

## Identifiers

Every law has a `sessionLawId`, built from its jurisdiction, session, series and chapter (or bill, where the state numbers no chapters):

| `sessionLawId` | Law |
|---|---|
| `SSL_MN_2025R_G_Y2025_C1` | Minnesota, 2025 regular session, chapter 1 |
| `SSL_MN_2025S1_G_Y2025_C1` | Minnesota, 2025 1st special session, chapter 1 |
| `SSL_CA_2025R_G_Y2026_C1` | California, Statutes of 2026, chapter 1 (the 2025-2026 session) |
| `SSL_IL_2025R_G_C104-0001` | Illinois, Public Act 104-0001 |
| `SSL_NE_2025R_G_Y2025_BLB241` | Nebraska, LB 241 |
| `SSL_MO_2025R_G_Y2025_BHB145-59` | Missouri, House Bill 145 & 59 |

The session code is the year plus a letter: `R` (regular), `S` (special), `X` (extraordinary) or `U` (not stated).
A session number follows where there is one, as in `2025S1`, `2025X2` or Florida's `2025SC`.
An id never changes.

## Finding a law

**By id.** `GET /us/session-laws/SSL_MN_2025R_G_Y2025_C1`.

**By citation.** Put the citation in place of the id, URL-encoded.
It is matched against the citation the publisher prints and the law's bill number:

```bash
curl "https://api.vaquill.ai/api/v1/us/session-laws/Act%202025-127?jurisdiction=al" \
  -H "Authorization: Bearer vq_key_..."
```

A citation lookup is charged whether or not it resolves.
The response says what matched in `resolvedFrom`.
Pass `jurisdiction` (a two-letter state code) when the citation does not name its state, as `Act 2025-127` does not.

A bare bill number such as `S.F.No. 1552` is reused across sessions, so use the law's id or a citation with its year.
A citation that names more than one law is a `404` with `reason: ambiguous_citation`, every candidate in `didYouMean` and the usual reading in `defaultSessionLawId`.

**By state and date.** `GET /us/session-laws/list` takes a required `jurisdiction` and these filters:

| Parameter | Example | Meaning |
|---|---|---|
| `jurisdiction` | `ca` | Required. Two-letter code, case-insensitive. |
| `session` | `2025R` | Session code, exactly as `session.code` reports it |
| `series` | `general` | One or more numbering series. Repeat the parameter for several (they combine with OR). See the series values below. Any other value is a `422` |
| `instrumentType` | `act` | One or more kinds of measure, repeated for several (OR): `act`, `joint_resolution`, `concurrent_resolution`, `resolution`, `resolve`, `memorial`, `other`. Any other value is a `422` |
| `approvedFrom`, `approvedTo` | `2025-01-01` | Approval date range |
| `effectiveFrom`, `effectiveTo` | `2026-01-01` | Has an effective date in the range |
| `hasText` | `true` | Only laws whose text is served |
| `textStatus` | `held` | `held`, `withheld`, `not_held`, `pending` |
| `isLaw` | `false` | `false` lists numbered measures that are not law (a vetoed bill, a pocket veto) |
| `enactmentOutcome` | `vetoed` | One or more outcomes, repeated for several (OR) |
| `updatedSince` | `2026-10-01` | Only laws whose record changed on or after this date |
| `q` | `grain buyers` | Words in the title or the printed bill number, 3 to 100 characters. A plain substring match, not a search: for that, see [Searching the text](#searching-the-text) |
| `limit` | `50` | Rows per page, at most 200 |
| `cursor` | | `nextCursor` from the previous page |

<Expandable title="series values">
`general`, `public`, `public_act`, `special_act`, `private_and_special`, `act`, `acts`, `law`, `local`, `municipal`, `appropriation`, `resolve`, `resolves`, `resolution`, `resolution_chapter`, `joint_resolution`, `concurrent_resolution`, `memorial`, `initiated_bill`, `constitutional_amendment`.
</Expandable>

A malformed value or a missing `jurisdiction` is a `422` and is not charged.
A well formed value that matches nothing returns an empty page, which is charged.
`GET /us/statutes/coverage` lists the `series` and `instrumentType` values each state holds.

Everything taking effect in California on 1 January 2026:

```bash
curl "https://api.vaquill.ai/api/v1/us/session-laws/list?jurisdiction=ca&effectiveFrom=2026-01-01&effectiveTo=2026-01-01" \
  -H "Authorization: Bearer vq_key_..."
```

**By citation, inside a document.** `POST /us/statutes/resolve` (and `GET /us/statutes/resolve`) recognizes a state session law citation when it names no code section.
The response carries `matchedCorpus: "session_law"` and a `sessionLaw` block. `resolved` stays `false` and `section` stays `null`.
`sessionLaw.status` is `matched` (one law, with its title, bill number, dates, outcome, source URL and `href`) or `ambiguous` (every candidate listed).
There is no extra charge beyond the resolve price.
A `state` scope applies. A `corpusType` scope skips the lookup.

## Searching the text

`POST /us/session-laws/search` finds laws by what they say.
Send a question in plain words, words from a title, a quoted phrase, a citation, a code section or a bill number.
You get the laws, best first, each with the passage of its text that matched and a snippet around your words.

```bash
curl -X POST "https://api.vaquill.ai/api/v1/us/session-laws/search" \
  -H "Authorization: Bearer vq_key_..." \
  -H "Content-Type: application/json" \
  -d '{"query": "can the sheriff pay with a debit card", "jurisdiction": "al", "limit": 5}'
```

A request that fails validation is a `422` and is not charged.

### What is searched

The enacted text, as it reads once the act takes effect.
Struck-out language is not searched and never appears in a snippet.
Only laws served with text are searched. Withheld laws are not returned.

### What you can ask

| You send | How it is matched |
|---|---|
| Plain words | On the words, stemmed (`licensing` finds `licensed`), against the title and the text |
| `"a quoted phrase"` | Verbatim, in the text |
| `63-3004` or `53F-2-208` | The citation exactly, wherever the text cites it, and the code sections an act's own table lists |
| `S.F.No. 1552` or `HB 145` | The act's bill number, exactly |

Parts combine: `hemp "licensed retailer" 63-3004` reads as the words, a phrase and a citation, and `parsed` in the response shows how the query was read.

### How it ranks

Ranking is keyword relevance, not meaning.

- A question must share words with the act. `teeth cleaning professional` will not find an act that says `dental hygienist`. If nothing matches, try the legislature's words or quote a phrase.
- A law matched by title and text, or by an exact part of your query, ranks higher. `matchType` is `exact` for a quoted phrase, citation, code section or bill number, otherwise `text`. `matchedBy` lists every way (`title`, `text`, `phrase`, `citation`, `codeSection`, `billNumber`).
- There is no "no good match" flag. Read the snippet to judge the result.

### The snippet

`passage.snippet` is about 280 characters of plain enacted text around your words, with `…` where it was cut.
`passage.highlights` lists `[start, end]` character offsets in the snippet (end exclusive) for each matched word.
`passage.bodyHref` reads the text from that passage: it is the law's `/body` with `startChar` set to `passage.ownStart`.

### Filters and paging

| Field | Meaning |
|---|---|
| `query` | Required, 2 to 300 characters |
| `jurisdiction` | One state, `dc` or `pr`. Omit to search every jurisdiction we hold. `federal` is a `422` |
| `session` | One session, by `session.code`. It applies to every kind of match: text, phrase, citation, title, bill and code section |
| `series`, `instrumentType` | One or more values each, as on the list endpoint |
| `approvedFrom`, `approvedTo` | Approval date range, `YYYY-MM-DD` |
| `limit` | Laws per page, 1 to 25 (default 10) |
| `offset` | Laws to skip. `offset` plus `limit` reaches at most the 60 best matches |

A page past the 60 best matches is a `422`. Narrow the search with a filter instead.
A filtered search that finds nothing on its first page is refunded, and its `note` names the filters.
Unknown fields in the body are a `422`.

## What a law carries

```json GET /us/session-laws/SSL_MN_2025R_G_Y2025_C1
{
  "sessionLawId": "SSL_MN_2025R_G_Y2025_C1",
  "jurisdiction": "mn",
  "citation": "CHAPTER 1--S.F.No. 1552",
  "session": { "code": "2025R", "label": "2025 Regular Session", "type": "regular", "year": 2025 },
  "series": "general",
  "instrumentType": "act",
  "number": "1",
  "billNumber": "S.F.No. 1552",
  "title": "An act relating to agriculture; modifying financial reporting requirements ...",
  "approvedDate": "2025-03-17",
  "enactmentOutcome": "signed",
  "isLaw": true,
  "textStatus": "held",
  "vetoStatusAsPrinted": "Signed by the governor March 17, 2025, 10:54 a.m.",
  "amendatoryMarkup": "preserved",
  "markupConvention": "publisher_literal",
  "charCount": 5470,
  "effectiveDates": [],
  "otherDates": [
    { "kind": "approved", "date": "2025-03-17", "dateAsPrinted": "March 17, 2025, 10:54 a.m." }
  ],
  "codeSectionsAffected": [],
  "sources": [
    { "role": "text", "url": "https://www.revisor.mn.gov/laws/2025/0/Session+Law/Chapter/1/", "hostClass": "gov" }
  ],
  "creditsConsumed": 2

```

- `effectiveDates` is always a list. One act can take effect on several dates.
- `codeSectionsAffected` lists the code sections the act changed. Eleven jurisdictions publish this: California, Maryland, Utah, the District of Columbia, Washington, Iowa, Kentucky, Nebraska, Missouri, Mississippi and Hawaii.
- `enactmentOutcome` is `signed`, `became_law_without_signature`, `veto_overridden`, `line_item_veto`, `vetoed`, `pocket_veto`, `not_presented` or `unknown`. `vetoStatusAsPrinted` is the publisher's own words.
- `sources` names the documents the record came from.

## `textStatus`

| Value | Meaning | `/body` |
|---|---|---|
| `held` | Text is served | Text, 6 credits per page |
| `withheld` | Text is held but not cleared for plain reading. `withheldReason` says why. Metadata is always served | `available: false`, not charged, unless you pass `includeUnverified=true` |
| `not_held` | The law exists but has no readable text | `available: false`, not charged |

## Reading the text

`/body` returns the text as printed, in pages of about 30,000 characters.
Pass `nextCursor` back as `cursor` for the next page.
If the text changes, the old cursor is a `409`.

Session laws amend existing law, so their text carries amendment markup.
`markupConvention` says how it is written:

| `markupConvention` | Deleted text | Inserted text |
|---|---|---|
| `wdiff` | `[-...-]` | `{+...+}` |
| `publisher_literal` | The publisher's own markers, as printed | |
| `mixed` | Both | |

`amendatoryMarkup: "lost"` means deleted language could not be recovered from the source and may read as law.

## Text reliability and older versions

Each served text carries a `textReliability` label.
An `unverified` or `known_issue` text also carries `reasonCode` and `notice`.
Pass `includeUnverified=true` to read the text of a withheld law, labeled the same way.

| Field | Meaning |
|---|---|
| `textReliability` | `verified`, `unverified` or `known_issue`, defined below |
| `reasonCode` | A stable token to branch on, listed below |
| `notice` | One sentence saying what to do about it |

| `textReliability` | Meaning |
|---|---|
| `verified` | The check passed, and the markup is consistent with the text |
| `unverified` | The markup is lost, or no clean check result exists |
| `known_issue` | The markup contradicts the text, or deleted language was found in it |

<Accordion title="reasonCode values">
Codes on a text that is served with a label:

| `reasonCode` | Label | Meaning |
|---|---|---|
| `markup_contradicted` | `known_issue` | The source declares amendatory markup that the text does not carry, so deleted language may read as current law |
| `struck_text_evidenced` | `known_issue` | The source prints deleted language that the text does not reliably mark |
| `struck_text_shown_as_current` | `known_issue` | Deleted language is not marked and reads as current law |
| `struck_text_merged` | `known_issue` | Deleted language is merged into the text as if current |
| `veto_unchecked` | `known_issue` | Line-item-vetoed items may be present as if enacted and have not been checked |
| `markup_lost` | `unverified` | Strike-through and underline could not be recovered from the source |
| `markup_unverified` | `unverified` | The markup could not be verified |
| `strike_unconfirmed` | `unverified` | An automated check against the printed act did not confirm the text |
| `strike_unchecked` | `unverified` | Deleted language has not yet been checked against the text |
| `licence_unconfirmed` | `unverified` | The terms of use of the source are not yet confirmed |

Codes on a text that is not served, even with `includeUnverified=true`: `validation_failed`, `session_unresolved`, `collector_unaudited`, `licence_barred`, `unclassified`.
Branch on `reasonCode`, not on `notice`, which is for people.
</Accordion>

Check the printed act before relying on amended language in an `unverified` or `known_issue` text.

A law's text can be corrected after it is first served.
`GET /us/session-laws/{sessionLawId}/versions` lists every version, newest first, at one credit.
Each entry has a `textAccess`: `served` (a plain `/body` call reads it), `includeUnverified` (the law is withheld and the text needs that flag) or `none`.
Read one with `GET /us/session-laws/{sessionLawId}/body?version=N`, at the body price.
A version number that does not exist answers `404` and is not charged.

## Many laws at once

`POST /us/session-laws/batch` takes up to 50 ids or citations in `ids` and returns each law's record, the same one `GET /us/session-laws/{sessionLawId}` returns, in the order sent.

```bash
curl -X POST "https://api.vaquill.ai/api/v1/us/session-laws/batch" \
  -H "Authorization: Bearer vq_key_..." \
  -H "Content-Type: application/json" \
  -d '{"ids": ["SSL_MN_2025R_G_Y2025_C1", "SSL_MN_2025R_G_Y2025_C2"]}'
```

- 2 credits per law served. A miss is not charged.
- A citation in `ids` also pays 2 credits to resolve it, as on the single route.
- `includeBody: true` adds each law's first page of text as `body`, at 6 credits per page served. 50 laws with text is 400 credits.
- `jurisdiction` scopes how every citation in the batch is read.

## Keeping a copy current

`GET /us/session-laws/changes` is a feed of every law that began to be served, had its text added, was corrected, unserved, withdrawn or merged, oldest first.

1. Call it with `sinceId=0`.
2. While `hasMore` is `true`, call again with `sinceId` set to the `cursor` you were given.
3. When `hasMore` is `false`, keep the cursor and call again later.

Each entry has `kind`, `sessionLawId`, `jurisdiction` and `detectedAt`, which is when we recorded the change, not an approval or effective date.
A `withdrawn` or `merged` entry means the law no longer answers at its id.
1 credit per page of up to 200 entries. An empty page is charged.

## From a code section to the acts that changed it

`GET /us/statutes/section/{actId}/enactments` lists the session laws a state publisher's "sections affected" tables show for one code section.
It says which act added, amended or repealed the section, and when the act took effect.

```bash
curl "https://api.vaquill.ai/api/v1/us/statutes/section/{actId}/enactments" \
  -H "Authorization: Bearer vq_key_..."
```

It reads the tables of California, the District of Columbia, Hawaii, Kentucky, Missouri, Mississippi, Nebraska, Utah and Washington.
A few other states are read from the section's credit line (`basis: credit_line`).
Any other section answers `supported: false` and is refunded. `coverage.note` on each response says what applies.

It is not a complete amendment history.
An empty list with `supported: true` means no table we hold lists the section.
1 credit. A section that does not exist is not charged.
