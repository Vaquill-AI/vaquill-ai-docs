---
title: "Point-in-time law"
description: "Get the text of a US provision as it read on a past date."
---

Ask what a provision said on a date, not just what it says now.

```bash
curl "https://api.vaquill.ai/api/v1/us/statutes/section/STATE_ID_IDAPA_16_03_21_010/body?asOf=2026-06-01" \
  -H "Authorization: Bearer vq_key_..."
```

`asOf=YYYY-MM-DD` on `GET /us/statutes/section/{actId}/body` returns the section's text as it stood on that date.
It is billed as an ordinary body fetch.

Use it when the question is dated. Examples: what an employer's duty was on the day of the conduct, or which version of a rule a 2019 contract incorporated.

## Choosing the right tool

| Question | Use |
|---|---|
| What did this section say on a date? | `asOf` on `/section/{actId}/body` |
| What changed, and when? | [`/section/{actId}/changes`](/api-guide/concepts/section-intelligence) |
| Give me the whole 2004 CFR as printed | `corpusType=CFR_ANNUAL` |
| Tell me when it changes from now on | [Law change alerts](/api-guide/alerts) |
| Which sections moved since my last sync? | `changedSince` on `/statutes/search` |

## The asOf block

Every answer carries an `asOf` block.
Read `engine` first, then `source`. Two mechanisms answer the same parameter, and one of them is an estimate.

| `engine` | `source` | What you get | Charged |
|---|---|---|---|
| `observed_change` | `live` | We saw no change after your date, so today's text is returned. | Yes |
| `observed_change` | `reconstructed` | Text rebuilt from the first change we saw after your date. | Yes |
| `observed_change` | `unavailable` | The section changed but we cannot rebuild the earlier text. No text. | No, refunded |
| `stored_edition` | `published` | The publisher's own edition, verbatim. | Yes |
| `stored_edition` | `unavailable` | No edition we hold covers your date. No text. | No, refunded |

`observed_change` answers every corpus that has no published editions. It reaches back only as far as we have tracked changes for that source.

`stored_edition` answers from a publisher's dated edition: `CFR_ANNUAL`, the U.S. Code, the Copyright Compendium and the OFAC FAQs.
A date between two editions, or before the first, is out of coverage. We do not answer it from a neighboring edition.

On `observed_change`, `existed: false` means the section was first added after your date. That is a definite answer, so it is charged.
On `stored_edition` with `source: "unavailable"`, `existed` is always `false`. Read `source` and `outOfCoverageReason` instead.

| Field | Meaning |
|---|---|
| `requested` | The date you asked for. |
| `existed` | On `observed_change`, false when the section did not exist yet on your date. |
| `basisChangeId` | The change event that supplied this text. Null unless `source` is `reconstructed`. |
| `observedFrom` | The earliest change we captured for this section. |
| `isBounded` | On `observed_change`, true marks a bounded reconstruction (see the warning below). On `stored_edition`, true means your date falls inside an edition we hold. |
| `coverage` | The same limit in prose, safe to show a reader. |
| `outOfCoverageReason` | `stored_edition` only. Why no text came back. It names the earliest edition we hold when your date is before it. |
| `resolvedEditionYear`, `scheduledEditionYear`, `editionsObserved` | `CFR_ANNUAL` only. The edition year served, the year the revision schedule computed, and the editions held. |
| `html` | Always null on an `asOf` answer. Read `plain`. |

To see the event behind a `reconstructed` answer, call [`GET /us/statutes/section/{actId}/changes`](/api-guide/concepts/section-intelligence) with `sinceId` set one below `basisChangeId` and `order=asc`.

<Warning>
  On `observed_change`, `isBounded: true` means we saw no change affecting that date. It does not mean there was none.
  The text is our best reconstruction, not a verified historical text.
  Show this to your readers.
</Warning>

## How each corpus answers

Where the publisher issues dated editions, `asOf` returns the edition in force on your date.
Everywhere else it rebuilds the earlier text from changes we observed.

| Corpus | How | Point-in-time behavior |
|---|---|---|
| `CFR_ANNUAL` | Edition | 31 annual editions, 1996-2026, all 49 titles. |
| `USC` | Edition | Two editions: one current through 2025-01-06 (served only for that date) and the current release point, which governs from 2026-09-02. Other dates return no text. |
| `FEDERAL_RULES` | Edition | Past texts of the Federal Rules, back to 1998-01-26. Pass the rule's current `actId`. |
| `copyright_compendium` | Edition | Three releases (2014, 2017, 2021). |
| `ofac_faq` | Separate document | Prior FAQ versions are separate documents with `actStatus: "superseded"`. |
| `whd_opinion_letter` | Separate document | Withdrawn and superseded letters stay retrievable under their own `act_id`. |
| CMS Medicare manuals, DOL Field Operations Handbook | Observed change | The publisher replaces text in place. Expect `isBounded: true` on earlier dates. |

Where history is a separate document, you retrieve it by citation instead of by date.

<Accordion title="Federal Rules edge cases">
A date before 1998-01-26 returns `source: "unavailable"`, `available: false` and `plain: null`. The call is not charged.
A proposed amendment (`FEDERAL_RULES_PROPOSED`) asked with `asOf` is refused, because it is not law on any date.
A date before a rule existed, or after it was deleted and before its number was reused, answers that it did not exist.
Past texts are also citable under `corpusType=FEDERAL_RULES_ANNUAL`. That corpus is opt-in and is never part of an unscoped search.
</Accordion>

## Worked example

The request at the top of this page asks what an Idaho rule said on 1 June 2026.
The response:

```json
{
  "actId": "STATE_ID_IDAPA_16_03_21_010",
  "html": null,
  "plain": "...",
  "available": true,
  "asOf": {
    "requested": "2026-06-01",
    "engine": "observed_change",
    "source": "reconstructed",
    "existed": true,
    "basisChangeId": 180183,
    "observedFrom": "2026-10-26T05:10:38.805852+00:00",
    "isBounded": true,
    "coverage": "Observed changes only: what a refresh of this source detected, from when change capture began for it through today, retained 5 years. ..."
  }
}
```

`isBounded` is true here because 2026-06-01 is before `observedFrom`.

<Accordion title="A date no held edition covers">
A U.S. Code date that no held edition covers returns no text and no charge:

```json
{
  "actId": "USC_T29_C8_S207",
  "plain": null,
  "available": false,
  "asOf": {
    "requested": "2019-06-01",
    "engine": "stored_edition",
    "source": "unavailable",
    "existed": false,
    "isBounded": false,
    "outOfCoverageReason": "We hold no published edition governing 2019-06-01, so the text in force on that date is not served. The earliest edition we hold is dated 2025-01-06, which is after your date."
  }
}
```
</Accordion>
