`POST /us/statutes/search` accepts a terms-and-connectors expression when you send `matchType: "boolean"`.
It supports `AND`, `OR`, `NOT`, same-sentence and same-paragraph connectors, numeric proximity, wildcards, exact phrases and grouping.

```json
{ "query": "\"trust fund\" AND penalty NOT 6672", "corpusType": "USC", "matchType": "boolean" }
```

Three guarantees hold for every Boolean search:

1. Every result satisfies the expression, judged over the section's full text.
2. Results are ranked by relevance among the matches.
3. A malformed expression, an unsupported operator or an out-of-range value is a `422` that names the problem and its character position.

## When to use Boolean

Use `boolean` when you need to say exactly which sections qualify.
Stay on `any` if you want the API to infer intent from a question.
[How search works](/api-guide/concepts/search#matchtype) compares every `matchType`.

For a citation such as `42 U.S.C. § 1983`, use `any` or `GET /us/statutes/resolve`.
Boolean mode never pins a cited section.

## Quick start

<CodeGroup>
```bash cURL
curl -X POST https://api.vaquill.ai/api/v1/us/statutes/search \
  -H "Authorization: Bearer vq_key_..." \
  -H "Content-Type: application/json" \
  -d '{
    "query": "\"security deposit\" /s (return OR refund) NOT commercial",
    "matchType": "boolean",
    "corpusType": "STATE",
    "state": "ca",
    "limit": 5
  }'
```

```python Python
import requests

resp = requests.post(
    "https://api.vaquill.ai/api/v1/us/statutes/search",
    headers={"Authorization": "Bearer vq_key_..."},
    json={
        "query": '"security deposit" /s (return OR refund) NOT commercial',
        "matchType": "boolean",
        "corpusType": "STATE",
        "state": "ca",
        "limit": 5,
    },
)

if resp.status_code == 422:
    # Not charged. Change the expression (see Errors below).
    raise ValueError(resp.json()["detail"])
if resp.status_code == 503:
    # Not charged. Retry with backoff.
    raise RuntimeError(resp.json()["detail"])
resp.raise_for_status()

data = resp.json()
print(data["parsedQuery"])  # how the expression was read
for hit in data["results"]:
    print(hit["citation"], hit["actId"])
```

The response has the same shape as any search, plus `parsedQuery`, the paging fields and each result's `matchContexts`:

```json
{
  "results": [
    {
      "citation": "...",
      "actId": "...",
      "relevanceScore": 0.87,
      "excerpt": "...",
      "matchContexts": [
        {
          "text": "the landlord shall return the security deposit within 21 days after the tenant vacates",
          "highlights": [[19, 25], [30, 46]]
        }
      ]
    }
  ],
  "count": 5,
  "offset": 0,
  "hasMore": true,
  "query": "\"security deposit\" /s (return OR refund) NOT commercial",
  "parsedQuery": "(\"security deposit\" /s (return OR refund)) NOT commercial",
  "totalMatches": 214,

  "relevanceRankedCount": 120,
  "nextOffset": 5,
  "noGoodMatch": false,

```

Paging, filters (`state`, `corpusType`, `code`, `titleNumber`, `chapter`, `part`, `yearFrom`, `yearTo`, `excludeRepealed` and the rest) and `includeBody` work as they do for any search.
The filters narrow the corpus first, and the expression is judged inside that scope.

## Examples

| The user asks for | Expression |
|---|---|
| Trust fund penalty provisions, excluding section 6672 | `"trust fund" AND penalty NOT 6672` |
| A landlord mentioned near a security deposit | `landlord /10 "security deposit"` |
| Negligence involving motor vehicles, any form of the word | `negligen* AND (motor OR vehicle)` |
| Employer or employee retaliation or discharge in one sentence | `(employer OR employee) /s (retaliat* OR discharg*)` |
| Sections whose heading is about security deposits | `title("security deposit")` |
| Sections that use "negligence" at least five times | `atleast5(negligence)` |

## Operators

Word operators are UPPERCASE.
Lowercase `and`, `or` and `not` are ordinary words.

| Operator | Matches a section where | Example |
|---|---|---|
| `AND` | both sides appear, anywhere in the section | `contract AND breach` |
| `OR` | either side appears | `work OR employment` |
| `NOT` | the left side matches and the right side appears nowhere | `negligence NOT criminal` |
| `/p` | both sides appear in the same paragraph | `contract /p unconscionable` |
| `/s` | both sides appear in the same sentence | `covenant /s compete` |
| `/N` | both sides appear within N words, in either order (N from 1 to 255) | `arbitration /5 award` |
| `+p`, `+s`, `+N` | the same as `/p`, `/s` and `/N`, with the left side first | `notice +5 termination` |
| `atleastN(term)` | the term occurs at least N times (N from 1 to 100) | `atleast5(negligence)` |
| `atmN(term)` | the term occurs at least once and at most N times (N from 1 to 99) | `atm2(negligence)` |
| `"exact phrase"` | these words, adjacent and in this order | `"summary judgment"` |
| `term1 term2` | bare words side by side are an exact phrase too | `summary judgment` |
| `*` or `!` at the end of a word | zero or more letters or digits | `retaliat*` |
| `?` inside a word | exactly one letter or digit | `wom?n` |
| `( )` | grouping | `(work OR employment) AND retaliation` |
| `caps(word)`, `allcaps(word)`, `nocaps(word)` | the word printed with a capital, all capitals, or no capitals | `allcaps(fdic)` |
| `plural(word)`, `singular(word)` | the regular plural, or exactly the word as written | `plural(deposit)` |

Details:

- Distance counts word positions. `/1` means adjacent.
- Matching is on whole words, case-insensitively, with no stemming and no synonyms. `deposit` does not match `deposits`.
- Punctuation inside a word splits it. `§ 1983` is the phrase `section 1983`.
- A hyphenated word also matches its joined form. `non-compete` is read as `"non compete" OR noncompete`.
- `and/or` is the phrase `and or`.

## Precedence

Without parentheses, operators bind in this order, tightest first:

1. `OR` (and `XOR`)
2. `/N` and `+N`
3. `/s` and `+s`
4. `/p` and `+p`
5. `AND`
6. `NOT`

Within one proximity level, the smaller distance binds first.
Otherwise operators group left to right.
This is the order legal research services use, and it differs from textbook Boolean.

`parsedQuery` shows how your expression was grouped. When in doubt, add parentheses.

| You send | `parsedQuery` | Read it as |
|---|---|---|
| `work OR employment AND retaliation` | `(work OR employment) AND retaliation` | either word, and "retaliation" anywhere |
| `landlord /s tenant AND deposit` | `(landlord /s tenant) AND deposit` | the sentence pair, and "deposit" anywhere |
| `landlord NOT commercial OR industrial` | `landlord NOT (commercial OR industrial)` | "landlord", and neither excluded word anywhere |

Each side of a proximity connector must be a term, phrase, wildcard, an `OR` group of those, or another proximity expression.
`AND`, `NOT` and the counting functions cannot sit inside one: `(a AND b) /5 c` is a `422`.

## Also accepted

You can paste a search written in another service's syntax.
`parsedQuery` echoes the canonical form.

| Reads as | Spellings accepted |
|---|---|
| `AND` | `&`, `&&` |
| `OR` | `\|`, `\|\|` |
| `XOR` | `XOR`, read as `(a OR b) NOT (a AND b)` |
| `NOT` | `%`, `BUT NOT`, `AND NOT`, a leading `-` on a word |
| `/N` | `w/N`, `NEAR/N`, `AROUND(N)`, `NEARn`. Bare `NEAR` is `/1` |
| `+N` | `pre/N`, `before/N`, `ADJn`, `ONEARn`. Bare `ADJ` is `+1` |
| `/s` | `w/s`, `w/sent`, `WITH` |
| `/p` | `w/p`, `w/para`, `SAME` |
| `*` | `!` or `$` at the end of a word |
| `atleastN( )` | `atlN( )` |

A `-` before a word is `NOT`, so `penalty -6672` excludes 6672.

### Negative proximity

`NOT /N`, `NOT /s` and `NOT /p` match a section where the left side occurs at least once outside that range of the right side.
`landlord NOT /s tenant` matches "The landlord sues. The tenant pays." and does not match "The landlord sues the tenant."

### Refused expressions

A token that looks like an operator is either understood or refused with a `422`.
It is never searched as ordinary words.
Refused forms include:

- a leading `!`, a doubled prefix (`--x`) and a double negation (`NOT -x`)
- an unknown connector (`s/5`), or a distance in sentences or paragraphs (`WITH2`, `SAME3`)
- regular expressions, number ranges (`1..5`) and bracket ranges (`[2000 TO 2010]`)
- a case-sensitive phrase (`^"Internal Revenue"`). Use the case functions in [Operators](#operators).
- `title:26`. Use the `titleNumber` or `code` filters, or `cite( )`.
- any field a statute section does not have

## Field restrictions

A term normally searches the section's body text.
Wrap it in a field function to search somewhere else.

| You send | Searches |
|---|---|
| `title(security deposit)` | the section heading. `heading( )`, `caption( )` and `title:` are the same field |
| `cite(1950.5) AND landlord` | the citation. `section( )` and `cite:` are the same field |
| `text(landlord)` | the body, which is what an unrestricted term searches |

Write the function name directly before the parenthesis: `title (x)` is a `422`.
Other fields, such as dates, judges, courts and parties, are refused.
Filter by year with `yearFrom` and `yearTo`, by jurisdiction with `state`, and by code with `code` or `titleNumber`.

## Sentences and paragraphs

`/s` and `/p` use real sentence and paragraph boundaries, not fixed word windows.
Abbreviations such as "Sec." and "U.S.C." do not end a sentence.
A paragraph starts at a blank line, at a subsection marker such as `(a)` or `(1)`, or at a heading line starting `Sec.`, `Section`, `§`, `Rule` or `Article`.
A single line break is not a paragraph boundary.

So in "(a) The landlord may recover. (b) The tenant shall pay.", `landlord /p tenant` does not match.

## Wildcards and fuzzy terms

| You send | Matches |
|---|---|
| `retaliat*` | retaliate, retaliation, retaliatory, and "retaliat" itself |
| `wom?n` | woman, women |
| `object$3` | "object" plus at most 3 more letters or digits. `object***` means the same |
| `retaliat* claim` | a wildcard can sit inside a phrase |
| `"landlord * deposit"` | `*` alone inside quotes is exactly one word |
| `negligence~1` | any word within 1 edit |
| `negligence~` | any word within 2 edits |

- A wildcard needs at least 3 letters or digits before the first wildcard character. There are no leading wildcards.
- A fuzzy term needs at least 3 letters.
- A wildcard matches letters and digits only. It never crosses a space or punctuation.
- The count and size limits are in [Limits](#limits).

Text pasted from Word, PDFs or the web is normalized first. Curly quotes, typographic dashes and non-breaking hyphens read as their plain forms.

## Response fields

| Field | Present when | Meaning |
|---|---|---|
| `parsedQuery` | `matchType` is `boolean` | Your expression in canonical form. Sending it back as the query runs the same search |
| `queryWarnings` | The expression is valid but may not mean what you intended | A list of plain-English strings. It never changes the search |
| `queryHint` | `matchType` is `any` and the query looks like a Boolean expression | The search ran as natural language. Retry with `matchType: "boolean"` if you meant the operators |
| `totalMatches` | Boolean search | How many sections satisfy the expression within your filters, across all pages |
| `totalMatchesExact` | Boolean search | `true`: `totalMatches` is exact. `false`: it is an upper bound |
| `relevanceRankedCount` | Boolean search | How many leading results are ordered by relevance, at most 120. Later results follow in keyword order |
| `nextOffset` | While `hasMore` is `true` | The `offset` to send for the next page |
| `matchContexts` | On each result, Boolean mode only | Up to three short passages showing where that section satisfied the expression |
| `noGoodMatch` | Every search | `true` only when no section matched |
| `matchQuality` | Every search | `null` in Boolean mode |
| `rankingDegraded` | Only when `true` | The order fell back to a simpler score. Every result still satisfies the expression |

`totalMatchesExact` is `false` when the expression uses phrases, proximity, `atleastN` or wildcards inside proximity, or when you set a filter other than `corpusType`, `state`, `actStatus` or `excludeRepealed`.

Page with `nextOffset` rather than computing the offset yourself. A page can hold fewer rows than `limit`.

```python
offset, matches = 0, []
while offset is not None:
    page = requests.post(url, headers=h, json={**body, "limit": 50, "offset": offset}).json()
    matches += page["results"]
    offset = page.get("nextOffset") if page["hasMore"] else None
```

To get the total without the results, send the same expression to `POST /us/statutes/count` with `matchType: "boolean"`.
It returns `isExact` in place of `totalMatchesExact`.

`matchContexts` passages are about 240 characters.
`highlights` lists `[start, end]` character offsets into the passage `text` (end exclusive).
Unlike `excerpt`, a context always contains your terms.
`matchContexts` is `[]` when the expression matched only in the heading or citation.
Leave it out of `fields` to skip the work.

## Recall

Read `totalMatches`, then page until `hasMore` is `false`.

- When `totalMatches` is larger than you can page to, narrow with `state`, `corpusType`, `code` or `titleNumber`, or split the expression.
- Wildcard and fuzzy terms can miss a rare word form. Write it out: `retaliat* OR retaliatory`.
- A very complex expression can run out of verification time. Narrow it with `state` or `corpusType`, or use fewer `/s` and `/p` connectors.

An empty result means no section in your scope satisfies the expression.
Loosen it (`/s` to `/p`, `/p` to `AND`) or widen the scope.
To count or list every section in a body of law regardless of wording, use `POST /us/statutes/count` without a query and `GET /us/statutes/divisions`.
See [How search works](/api-guide/concepts/search#when-search-is-the-wrong-tool).

## Pricing

A Boolean search is priced like any search, and every page is its own call.

A Boolean count on `POST /us/statutes/count` costs 1 credit, and a count of zero is refunded.

## Limits

| Limit | Value |
|---|---|
| Query length | 500 characters |
| Terms, phrases and wildcards | 32 |
| Parenthesis nesting | 8 levels |
| Wildcard and fuzzy terms | 20 |
| Characters before a wildcard | at least 3 |
| Extra characters in `$N` or `***` | 1 to 5 |
| N in `/N` and `+N` | 1 to 255 |
| N in `atleastN( )` | 1 to 100 |
| N in `atmN( )` | 1 to 99 |
| Fuzzy edits | at most 2 |
| `offset` | 10,000 (70 in other modes) |
| Relevance-ranked results | 120 |

Exceeding any of the first eleven limits returns `422`.
Results past the relevance-ranked 120 are not refused. They follow in keyword order.

## Coming from another service

| Habit | Here | Write instead |
|---|---|---|
| A space means `OR` (or `AND`) | A space joins words into an exact phrase | `landlord OR tenant`, or `landlord AND tenant` |
| `*` is one character | `*` is any number of letters or digits, `?` is exactly one | `wom?n` for one character |
| Lowercase connectors work | Word operators are UPPERCASE only | `landlord OR tenant` |
| Plurals and word forms are added for you | No stemming: `damage` does not match `damages` | `damage*`, or `damage OR damages` |
| `AND` binds tighter than `OR` | `OR` binds tightest | parentheses: `(a AND b) OR c` |
| `/s` and `/p` are word windows | They are real sentence and paragraph boundaries | `/N` for a word distance |
| `!word` excludes, or is a wildcard | A leading `!` is refused as ambiguous | `NOT word`, or `word!` |
| A word that looks like an operator is searched | An uppercase operator word is an operator | Quote it, or write it in lowercase |

## Errors

An expression we cannot read returns `422` with a `detail` string.
It names the problem and, where there is one, the 0-based character position in your query.

```json
{ "detail": "Invalid Boolean query: Unclosed parenthesis at position 0" }
```

### Failure and charging

| Outcome | Cause | Charged | What to do |
|---|---|---|---|
| `422` | The expression could not be read | No | Change the expression |
| `422` | The expression is too heavy to verify in time | No | Narrow it with `state` or `corpusType`, or use fewer `/s` and `/p` connectors |
| `503` | The search backend is temporarily unavailable | No | Retry with backoff. Do not change the expression |
| `200` with no results | A valid expression that matches nothing | Yes | Loosen the expression or widen the scope |

### Common mistakes

| Mistake | Example | Fix |
|---|---|---|
| Unclosed quote or parenthesis | `"trust fund`, `(a OR b` | Close it |
| Missing operator before a parenthesis | `landlord tenant (deposit)` | Write `AND`, `OR`, `NOT`, `/s`, `/p` or `/N` between the operands |
| Only a negation | `NOT foo` | Add a term to search for |
| Wildcard too short | `ab* x` | Put at least 3 letters or digits before the first wildcard character |
| Expression ends early | `a AND` | End with a term |
| Leading `!` | `employer AND !criminal` | Write `NOT criminal` to exclude, or `criminal!` as a wildcard |

A query over 500 characters fails schema validation instead, with the `errors` array described in [Errors](/api-guide/errors).

## For AI agents

1. Send `matchType: "boolean"`. Without it the operators are searched as words.
2. Parenthesize every `OR` group and any mix of operators ([Precedence](#precedence)).
3. Read `parsedQuery` to confirm the grouping, and fix anything a `queryWarnings` entry names.
4. Quote `matchContexts`, not `excerpt`, to show why a section matched.
