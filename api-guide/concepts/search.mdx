`POST /us/statutes/search` ranks sections by relevance and returns up to a bounded number of them.
It does not list every section that matches.

## Ranking

Search is hybrid.
Two retrieval legs run in parallel over the same corpus:

- A semantic leg matches on meaning, so a section can rank for a question that shares none of its wording.
- A keyword leg matches on the terms themselves.

Results from both are fused, then reranked by a model that reads each candidate against your query.
Sections with a dead `actStatus` are demoted, not dropped, so a repealed provision can still appear below live law.
See [Status and currency](/api-guide/concepts/status-and-currency) to filter those out.

A query shaped like a citation resolves directly to that section at rank 1.

<Tip>
  If you already hold a well-formed citation, `GET /us/statutes/resolve` does the same job for fewer credits.
</Tip>

## matchType

`matchType` controls how the query is read.
Operators are plain words in every mode except `boolean`.

| Value | Behavior | Use it when |
|---|---|---|
| `any` (default) | Hybrid semantic and keyword ranking | The query is a natural-language question |
| `all` | Every whitespace-separated term must appear in the text | A multi-term lookup returns loose matches |
| `phrase` | The exact phrase must appear, case-insensitive | You want a defined term or a statutory phrase |
| `boolean` | The query is a terms-and-connectors expression, and every result satisfies it | You need alternatives, exclusions, proximity, wildcards or counts. See [Boolean search](/api-guide/concepts/boolean-search) |

In `any`, `all` and `phrase`, `AND`, `OR`, `NOT`, quotes, proximity, wildcards and `title:` syntax are ordinary text.
A query that looks like a Boolean expression gets a `queryHint` in the response.

<Warning>
  In `any` mode, several concepts in one string dilute the query.
  Search each concept separately and union the `actId` values, or write one Boolean expression.
</Warning>

- `all` and `phrase` only narrow results that ranking already retrieved. If either returns nothing, try `any` or tighter filters.
- `boolean` applies the expression across the whole corpus. The other modes stop at 120 results. See [Pagination](/api-guide/pagination).

[Best practices](/api-guide/best-practices) covers when to use each.

## Results

The `excerpt` on a result is one passage, a ranking preview sized by `excerptChars` (100 to 600, anything else is a `422`).
For the authoritative text, call `GET /us/statutes/section/{actId}/body`.

Headings and citations are searchable along with body text.

Two labels say where in a federal rule the excerpt sits:

- `matchSegment` is `rule_text`, `source_credit` or `note` (an Advisory Committee Note).
- `matchNoteYear` is the year of the committee note, and is `null` unless `matchSegment` is `note`.

Only the Federal Rules copies from the US Code appendices (`actId` beginning `USCAPP_`) are labeled.
Every other row has `null` in both.
The labels never change ranking.

## Filters

Every scoping filter (`state`, `corpusType`, `code`, `titleNumber`, `chapter`, `part`, `actStatus`, `yearFrom`, `yearTo`, `changedSince`, and the Federal Register filters) is applied before retrieval.
A search scoped to one state and one corpus type gets full depth within that slice, so scoping improves recall.

`yearFrom` and `yearTo` match on the credited amendment year, else the effective year, else the publication year.
See [Response fields](/api-guide/concepts/response-fields#filtering-by-year).

Every page of a query comes from one ranking. See [Pagination](/api-guide/pagination).
An unrecognized filter name or value returns `422`.

## What a search costs

A search is charged once ranking runs, including a search that finds no good match (`noGoodMatch: true`).

Refunds:

- A filtered search whose filters match no rows. `notes` names the filters.
- A page served with `rankingDegraded: true`. `notes` says so.

`includeBody` adds the body price for each row that returns text.

## When search is the wrong tool

If you need every section in a body of law, browse the hierarchy.
`GET /us/statutes/divisions` walks codes to chapters to sections and returns every section in a container with its `actId`.

<Card title="Browse the hierarchy" href="/api-guide/recipes/browse-hierarchy">
  Enumerate a bounded body of law without relying on ranking.
</Card>

To size a body of law first, `POST /us/statutes/count` takes the same scoping filters and returns an exact section count.
It accepts no `query`.
