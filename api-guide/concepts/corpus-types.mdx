`corpusType` chooses which body of law a search runs against.
It is the most important filter in the API, since it decides whether you get a statute, a regulation, a court rule, agency guidance or an agency adjudication.

Pass one token or a list.
This page covers the query vocabulary: what each token means and how to scope it.
For how much data sits behind each one and what is deliberately excluded, see [API Coverage](/api-guide/coverage).

## Scoping rules

- **Federal token:** send only `corpusType`, such as `{"query": "civil rights under color of law", "corpusType": "USC"}`.
- **State token:** send `corpusType` and `state`.
  Omit `state` and the search spans every jurisdiction that has that corpus ingested, which is rarely what you want and always costs the same.
  `state` also accepts a **list**, so one call can cover several jurisdictions.
- **Source:** where a token folds in several bodies, narrow further with `source`, such as `{"query": "tip credit", "corpusType": "AGENCY_GUIDANCE", "source": "whd_foh"}`.

```json
{ "query": "security deposit return", "corpusType": "STATE", "state": "ca" }
```

<Note>
  `titleNumber` is only valid alongside `corpusType` `USC` or `CFR`.
  Sending it with any other token returns a `422`.
</Note>

Call `GET /us/statutes/coverage` for the live figure and for which tokens have data in which jurisdiction.

A state-scoped token requires `state`, or spans every jurisdiction holding that corpus.

Tokens you can walk with `/us/statutes/divisions` are the ones with `browsable: true` in the coverage legend: `USC`, `CFR`, `STATE`, `REGULATION`, `STATE_RULES`, `CONSTITUTION`, `STATE_CONSTITUTION` and `FEDERAL_RULES`.

State session laws have no `corpusType`.
They are served by [`/us/session-laws`](/api-guide/session-laws), not `/us/statutes`.
`SESSION_LAW` is the federal Statutes at Large only.

The OpenAPI enum also accepts two more values that are not tokens to search today:

- `USC_ANNUAL` is GPO's retired annual edition of the US Code, kept only so a past date can be answered from a printed edition.
- `FEDERAL_BILL` holds the text of Congressional bills of the 119th Congress, which is proposed text and never law.
  It is opt in only and never part of an unscoped search, a browse or a total.
  Enacted text is served under `SESSION_LAW` and, once codified, `USC`.

`STATE_AGENCY_GUIDANCE` is the newest corpus.
It holds state Department of Insurance bulletins and circular letters.
A bulletin interprets the law and is not itself the law, so it has its own token rather than sharing `REGULATION`.
Use it for insurance compliance and 50-state survey questions.
The jurisdiction count and date range are in `GET /us/statutes/coverage`.

### Tokens that are not current law

<AccordionGroup>
  <Accordion title="FEDERAL_RULES_ANNUAL and FEDERAL_RULES_PROPOSED">
    Both tokens sit beside `FEDERAL_RULES` and share its citations, so neither is part of an unscoped search.
    Name the token to read them.
    Neither is watchable: a stage change in a pending amendment is announced on the rule's own watch (see [alerts](/api-guide/alerts#pending-federal-rules-amendments)).

    - `FEDERAL_RULES_ANNUAL` holds 1,125 superseded texts of 510 Federal Rules.
      The `actId` is the current rule's `actId` plus `_E` and the year, such as `{actId}_E2015`.
      It is superseded text by construction, so read `goodLawStatus` and use `FEDERAL_RULES` for the rule in force.
      To ask what a rule said on a date, pass `asOf` with the current `actId` (see [Point-in-time law](/api-guide/point-in-time)).
    - `FEDERAL_RULES_PROPOSED` holds 49 pending or proposed amendment documents on 36 current rules.
      The `actId` is the current rule's `actId` plus `_P` and the cycle year.
      Every row has `actStatus: "proposed"`.
      It is a proposal, not law, until its effective date.
      The rule in force lists its pending amendments in `pendingAmendments` (see [Federal coverage](/api-guide/coverage/federal)).
  </Accordion>
  <Accordion title="STATE_REGISTER">
    A state's official register prints each proposed, adopted or emergency rule as a notice on a date.
    `STATE_REGISTER` holds those notices, one document per printed item, cited by register volume and page (`36 Pa. Bull. 510`).

    **A register notice is not the law.**
    The codified rule under `REGULATION` is the operative text, and a register page often prints a rule that was later withdrawn, amended or never adopted.
    Every item is served with `goodLawStatus: "unknown"`, `year` is the year of the issue it was printed in, and it is never given the priority that binding law gets in search ranking.
    Name the token when you want register notices, and do not read one as the rule in force.

    Cite a register item by its register citation; see [Register citations](/api-guide/concepts/citation-formats#register-citations).
    The states loaded are listed on [State and territory coverage](/api-guide/coverage/states#state-administrative-registers).
  </Accordion>
  <Accordion title="STATE_AG_OPINION">
    A formal written opinion in which a state's chief legal officer construes that state's own statutes, constitution and regulations for a state officer, legislator or local government who asked.

    **Persuasive authority, not binding law.**
    `goodLawStatus` is always `unknown`.
    Officials follow these opinions in practice, and for a provision no court has reached one is often the only interpretive authority, but it does not bind a court.
    The reasoning is on [Status and currency](/api-guide/concepts/status-and-currency).

    Where a jurisdiction runs more than one series, the `series` field carries the publisher's own label, so you can filter Washington's formal `AGO` apart from its `AGLO` letter opinions, or Georgia's Official from its Unofficial opinions.
    The series is also part of the `actId`, which is what makes the field trustworthy rather than derived from a title.
  </Accordion>
  <Accordion title="SESSION_LAW and STATUTE_COMPILATION">
    Both carry `goodLawStatus: "unknown"`: they are historical records, not statements of current law.
  </Accordion>
</AccordionGroup>

## Choosing between tokens that look alike

Four pairs are routinely confused.
Picking the wrong token returns a confident answer to a different question.

| You want | Use | Not |
|---|---|---|
| What federal law says **today** | `USC` | `SESSION_LAW`, which is law as enacted and never updated |
| The text of an act Congress passed | `SESSION_LAW` | `USC`, which rearranges it by subject |
| An act that was never codified | `STATUTE_COMPILATION` | `USC`, which has no address for it |
| A regulation as it reads **now** | `CFR` | `CFR_ANNUAL`, which is a past published edition |
| What a regulation said in 2004 | `CFR_ANNUAL` | `CFR` with `asOf`, which reconstructs rather than reproduces |
| A Federal Rule as it reads **now** | `FEDERAL_RULES` | `FEDERAL_RULES_ANNUAL`, which is a past text, or `FEDERAL_RULES_PROPOSED`, which is a proposal |
| A Federal Rule on a past date | `asOf` on `/section/{actId}/body` with the current `actId` | Searching `FEDERAL_RULES_ANNUAL` for the date |
| What an agency **thinks** a rule means | `AGENCY_GUIDANCE` | `AGENCY_ADJUDICATION`, which is decided agency matters |
| How an agency **decided** a case | `AGENCY_ADJUDICATION` | `AGENCY_GUIDANCE` |

For asking any corpus what it said on a past date, see [Point-in-time law](/api-guide/point-in-time).

## Filtering to one named source

`AGENCY_GUIDANCE`, `AGENCY_ADJUDICATION`, `FEDERAL_RULES`, `CFR`, `US_TAX_TREATY`, `US_TREATY` and `STATE_AGENCY_GUIDANCE` each fold several independently filterable bodies into one token.
Every result carries a `source` field naming which one it came from; pass that value back as the `source`
filter to scope to it.

```json
{ "query": "petition for writ of certiorari", "corpusType": "FEDERAL_RULES", "source": "sct" }
```

`source` accepts a single value or a list, so `source: ["frcp", "sct"]` searches both in one call.
An unrecognized value is rejected with `422` and the error names every valid code, so the API itself is the authoritative list.
The codes for each token are in the Source codes column of the [token table](#tokens).

<Note>
  The `far` and `dfars` sources split **existing** Title 48 data by chapter.
  They are not a separate ingest and do not add sections to the `CFR` total.
</Note>
