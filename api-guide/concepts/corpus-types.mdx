The Vaquill statutes corpus is one index of US primary law, split into 11 named
slices. The `corpusType` filter on `POST /statutes/search` tells the API which
slice to search. Omit it and you search everything; set it and you narrow to one
body of law (federal statutes, state regulations, a constitution, and so on).

Corpus types come in two scopes. **Federal** corpora live under the single
`federal` jurisdiction. **State** corpora are keyed by jurisdiction, so you pair
them with a `state` filter (a 2-letter lowercase code like `ca` or `tx`) to
search one jurisdiction's data.

## The 11 tokens

### Federal-scoped

| Token | Contains | Scope | ~Size |
|---|---|---|---|
| `USC` | United States Code (federal statutes) | federal | 54,853 |
| `CFR` | Code of Federal Regulations | federal | 219,447 |
| `CONSTITUTION` | U.S. Constitution (Articles + Amendments) | federal | 74 |
| `FEDERAL_RULES` | Federal Rules of Procedure (FRCP, FRCrP, FRE, FRAP, FRBP, incl. Supplemental Admiralty and Social Security Rules) | federal | 541 |
| `EXECUTIVE_ACTION` | Presidential documents (executive orders, proclamations, memos) | federal | 3,901 |
| `FEDERAL_REGISTER` | Federal Register agency rules, final and proposed | federal | 384,794 |
| `AGENCY_GUIDANCE` | Agency guidance (SSA rulings, IRS notices, revenue rulings and procedures) | federal | 2,584 |

### State-scoped

| Token | Contains | Scope | ~Size |
|---|---|---|---|
| `STATE` | State statutory codes | state | ~2.0M across 52 jurisdictions (50 states + DC + PR) |
| `REGULATION` | State administrative regulations | state | ~1.16M across 45 states (all official-source, refreshed monthly) |
| `STATE_CONSTITUTION` | State constitutions | state | ~7.7K across 51 jurisdictions (50 states + PR) |
| `STATE_RULES` | State court rules (civil, criminal, appellate, local) | state | ~11.9K across 10 states |

<Info>
  These are approximate totals and expand weekly. The exact per-jurisdiction
  counts are always live via `GET /statutes/coverage`.
</Info>

## Scoping a search

<Steps>
  <Step title="corpusType alone">
    A federal corpus needs only `corpusType`. This searches the whole US Code:

    ```json
    {"query": "civil rights under color of law", "corpusType": "USC"}
    ```
  </Step>
  <Step title="corpusType plus state">
    A state corpus needs both `corpusType` and `state`. This searches only
    California's statutory code:

    ```json
    {"query": "security deposit return", "corpusType": "STATE", "state": "ca"}
    ```

    Omit `state` on a state-scoped corpus and the search spans every
    jurisdiction that has that corpus ingested.
  </Step>
</Steps>

<Note>
  `titleNumber` is only valid alongside `corpusType` `USC` or `CFR`. Sending it
  with any other corpus returns a `422`.
</Note>

## Example: state regulations

A `REGULATION` search paired with a state returns that state's administrative
rules. Here is Washington's environmental regulations:

<CodeGroup>

```bash cURL
curl -X POST https://api.vaquill.ai/api/v1/statutes/search \
  -H "Authorization: Bearer vq_key_..." \
  -H "Content-Type: application/json" \
  -d '{"query": "stormwater discharge permit", "corpusType": "REGULATION", "state": "wa", "limit": 5}'
```

```python Python
import requests

resp = requests.post(
    "https://api.vaquill.ai/api/v1/statutes/search",
    headers={"Authorization": "Bearer vq_key_..."},
    json={
        "query": "stormwater discharge permit",
        "corpusType": "REGULATION",
        "state": "wa",
        "limit": 5,
    },
)
data = resp.json()
for r in data["results"]:
    print(r["citation"], "-", r["title"])
```

```javascript JavaScript
const resp = await fetch("https://api.vaquill.ai/api/v1/statutes/search", {
  method: "POST",
  headers: {
    Authorization: "Bearer vq_key_...",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    query: "stormwater discharge permit",
    corpusType: "REGULATION",
    state: "wa",
    limit: 5,
  }),
});
const data = await resp.json();
for (const r of data.results) {
  console.log(r.citation, "-", r.title);
}
```

</CodeGroup>

<Tip>
  Not every corpus type exists for every state. Before you scope a state
  search, call `GET /statutes/coverage` and read that jurisdiction's `corpora`
  keys to see which tokens actually have data. This avoids empty results from
  guessing.
</Tip>

## Example: Federal Register and agency guidance

Both are **federal**, so they need only a `corpusType`, no `state`.
`FEDERAL_REGISTER` searches agency rules as published (proposed and final).
`AGENCY_GUIDANCE` searches sub-regulatory guidance: SSA rulings, IRS notices,
revenue rulings and procedures, plus a set of primary-sourced **reference
figures**, the annually adjusted dollar thresholds (for example the Subchapter V
debt limit, or SALT and CTC values) that do not live in USC or CFR section text.

<CodeGroup>

```bash cURL
# Agency guidance, including the annually adjusted figure records
curl -X POST https://api.vaquill.ai/api/v1/statutes/search \
  -H "Authorization: Bearer vq_key_..." \
  -H "Content-Type: application/json" \
  -d '{"query": "2026 Subchapter V debt limit", "corpusType": "AGENCY_GUIDANCE", "limit": 5}'
```

```python Python
import requests

resp = requests.post(
    "https://api.vaquill.ai/api/v1/statutes/search",
    headers={"Authorization": "Bearer vq_key_..."},
    json={
        "query": "2026 Subchapter V debt limit",
        "corpusType": "AGENCY_GUIDANCE",
        "limit": 5,
    },
)
for r in resp.json()["results"]:
    print(r["citation"], "-", r["title"])
```

```javascript JavaScript
const resp = await fetch("https://api.vaquill.ai/api/v1/statutes/search", {
  method: "POST",
  headers: {
    Authorization: "Bearer vq_key_...",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    query: "2026 Subchapter V debt limit",
    corpusType: "AGENCY_GUIDANCE",
    limit: 5,
  }),
});
const data = await resp.json();
for (const r of data.results) console.log(r.citation, "-", r.title);
```

</CodeGroup>

Swap `corpusType` to `FEDERAL_REGISTER` to search published agency rules the same way.

<Note>
  `FEDERAL_REGISTER` and `AGENCY_GUIDANCE` are **search-only**. They are flat, not
  a title/chapter tree, so `/statutes/divisions` does not browse them, and
  `/statutes/resolve` parses statute and regulation citations (USC, CFR, state
  codes), not Federal Register or guidance citations. Reach both through
  `/statutes/search`, then `/statutes/section/{actId}` and `.../body`.
</Note>
