Every section has one unique identifier, its **`actId`**.
Use it to fetch a section's metadata and full text.

Get the `actId` from search results and pass it back to the section endpoints. Do not build one by hand.

## What an actId looks like

Treat the whole string as an opaque key. Read it from a result, store it, and pass it back unchanged.

| Family | actId | Citation |
|---|---|---|
| USC | `USC_T42_C21_S1983` | 42 U.S.C. § 1983 |
| CFR | `CFR_T17_P240_S240_10b5_1` | 17 C.F.R. § 240.10b5-1 (the dot and hyphen become underscores) |
| State | `STATE_TX_Cpr_C93_S93.005` | Tex. Property Code § 93.005 |

State ids cannot be derived from a citation.

## Stability over time

The `actId` stays the same when a section is amended or repealed. A repealed section keeps its id and a lookup still resolves.
It changes only when the section is renumbered, moved or recodified.
Store the citation alongside the `actId`.

If a stored `actId` stops resolving, the section was probably renumbered. Re-resolve by citation with `GET /us/statutes/resolve` and update your record.
A watch on the section emits a `removed` event with the old `actId` (see [Law change alerts](/api-guide/alerts)).

## The workflow

1. **Search:** `POST /us/statutes/search` returns results, each with an `actId`.
2. **Metadata:** `GET /us/statutes/section/{actId}` returns the full result object for one section.
3. **Full text:** `GET /us/statutes/section/{actId}/body` returns the text, when available.
4. **Neighbors (optional):** `GET /us/statutes/section/{actId}/related` returns the sections before and after, in the statute's own order.
   The response has `previous` and `next` arrays of section objects and a `container` label.

Search results and the `section` object share one shape.
The fields that place and cite a section are `titleNumber`, `titleName`, `chapter`, `chapterName`, `sectionNumber`, `displayPath`, `breadcrumb`, `citation` and `citationShort`.
See [Hierarchy and container names](/api-guide/concepts/hierarchy) and [Response fields](/api-guide/concepts/response-fields).
`titleNumber` can be alphanumeric (such as `13A`), so treat it as a string.

## Example: search, then fetch

Search, take the first `actId`, then fetch its metadata and body.

```bash cURL
# 1. Search
curl -X POST https://api.vaquill.ai/api/v1/us/statutes/search \
  -H "Authorization: Bearer vq_key_..." \
  -H "Content-Type: application/json" \
  -d '{"query": "civil action for deprivation of rights", "corpusType": "USC", "limit": 1}'

# 2. Fetch metadata for the returned actId
curl https://api.vaquill.ai/api/v1/us/statutes/section/USC_T42_C21_S1983 \
  -H "Authorization: Bearer vq_key_..."

# 3. Fetch full text
curl https://api.vaquill.ai/api/v1/us/statutes/section/USC_T42_C21_S1983/body \
  -H "Authorization: Bearer vq_key_..."
```

```python Python
import requests

headers = {"Authorization": "Bearer vq_key_..."}

# 1. Search
search = requests.post(
    "https://api.vaquill.ai/api/v1/us/statutes/search",
    headers=headers,
    json={
        "query": "civil action for deprivation of rights",
        "corpusType": "USC",
        "limit": 1,
    },
).json()
act_id = search["results"][0]["actId"]

# 2. Fetch metadata
section = requests.get(
    f"https://api.vaquill.ai/api/v1/us/statutes/section/{act_id}",
    headers=headers,
).json()["section"]
print(section["citation"], "-", section["displayPath"])

# 3. Fetch full text
body = requests.get(
    f"https://api.vaquill.ai/api/v1/us/statutes/section/{act_id}/body",
    headers=headers,
).json()
print(body["plain"][:500] if body["available"] else "text unavailable")
```

```javascript JavaScript
const headers = { Authorization: "Bearer vq_key_..." };

// 1. Search
const search = await (
  await fetch("https://api.vaquill.ai/api/v1/us/statutes/search", {
    method: "POST",
```

A `404` on either section endpoint means no section was found.
Check `available` before reading `html` or `plain` from `/body`.
A section printed as images returns `bodyUnavailable: true` and `bodyUnavailableReason: "image_only_source"` instead of text.

## When an actId misses

An id built by hand will miss. Start from a citation with `GET /us/statutes/resolve` instead.

<Accordion title="The batch route and its notFound detail">
  `POST /us/statutes/sections` takes up to 50 `actIds`. It returns `sections`, `notFound` (the bare ids) and `notFoundDetail`, one entry per missed id:

  | Field | Contains |
  |---|---|
  | `actId` | The id from your request that did not resolve. |
  | `reason` | `assembled_id` or `not_in_corpus`. |
  | `didYouMean` | Up to 3 real act ids for the same section number, best first. |

  `assembled_id` means the id does not exist but the section does, under the ids in `didYouMean`.
  For example, `Tex. Property Code § 93.005` is `STATE_TX_Cpr_C93_S93.005`, not `STATE_TX_C93_S93.005`.

  `not_in_corpus` means nothing matching was found. Check `GET /us/statutes/coverage` for that jurisdiction.

  Ids in `notFound` are not charged. `notFoundDetail` can come back empty.
</Accordion>
