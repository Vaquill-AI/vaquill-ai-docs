Two fields answer "can I rely on this section today".

- `actStatus` is the publisher's own status for the section, stored as printed.
- `goodLawStatus` is our verdict, derived from `actStatus` and whether the jurisdiction publishes a repeal signal we trust.

Both appear on `POST /us/statutes/search`, `GET /us/statutes/section/{actId}`, and `POST /us/statutes/sections`.

## actStatus

The raw status of the section. It is the one you can filter on.

| Value | Group | Meaning |
|-------|-------|---------|
| `in_force` | Operative | The section is currently operative. |
| `reserved` | Dormant | A reserved placeholder with no current text. |
| `vacant` | Dormant | A vacant number with no content. |
| `inactive` | Dormant | Present and revivable, marked inactive by the publisher. |
| `not_funded` | Dormant | Enacted subject to appropriation, and not yet funded. |
| `not_yet_effective` | Dormant | Enacted with a later commencement date. |
| `repealed` | Dead | Repealed. |
| `unconstitutional` | Dead | Held unconstitutional. |
| `expired` | Dead | Reached its own sunset date. |
| `omitted` | Dead | Omitted from the code, often editorially, without repeal. |
| `deleted` | Dead | Deleted by the publisher. |
| `superseded` | Dead | Replaced by a later version of the same instrument. |
| `renumbered` | Dead | Moved to a new number. See `renumberedTo`. |
| `transferred` | Dead | Moved to a different code or title. See `transferredTo`. |
| `recodified` / `recompiled` / `relocated` | Dead | The provision exists, but not at this citation. |
| `rescinded` / `revoked` / `withdrawn` | Dead | An agency retired its own rule or guidance. |
| `terminated` / `abolished` / `removed` | Dead | The body or provision was ended by the publisher's own word. |
| `vetoed` | Dead | Passed by the legislature and vetoed. |
| `rejected` | Dead | A proposed constitutional article or amendment the voters turned down. |
| `proposed` | Dead | A draft published for comment. It has no legal force. |
| `vacated` | Dead | Set aside on review. |
| `non_precedential` | Filterable only | A document the law forbids citing as precedent, such as an IRS private letter ruling. `excludeRepealed` never drops it. |

Dead and dormant values are real answers about the law. We keep the publisher's own word instead of merging them, so a section whose whole body reads `Recompiled.` is not served as live law.

## goodLawStatus

A conservative verdict computed from `actStatus` and jurisdiction-specific repeal signals.

| Value | Meaning |
|-------|---------|
| `good_law` | Operative and current, with a reliable repeal signal for its jurisdiction. |
| `not_good_law` | Repealed, unconstitutional, or otherwise no longer operative. |
| `not_operative` | Present but with no operative text (reserved, vacant, omitted). |
| `unknown` | The jurisdiction has no reliable repeal signal, so we make no claim. |

<Warning>
  <GoodLawUnknown />

  The field is `null` when currency checking is disabled.
</Warning>

## Filtering on status

`POST /us/statutes/search` has two filters, and they are not opposites.

`excludeRepealed: true` drops every section whose own status is dead or dormant.
The rest are not all good law. Read `goodLawStatus` on each result: `good_law` is checked, `unknown` is unchecked.

`actStatus` keeps only the statuses you name, as a string or a list. Use it for a compliance diff that asks what was lost.

```json
{ "query": "security deposit", "state": "tx", "actStatus": ["repealed", "expired"] }
```

You can pass any value from the table above. An unrecognized value returns a 422. Combining a dead status with `excludeRepealed: true` also returns a 422.

## Currency and move pointers

- `currencyNote`: the source's own "current through ..." line, when the publisher gives one.
- `renumberedTo`: when `actStatus` is `renumbered`, a pointer to the new location.
- `transferredTo`: when `actStatus` is `transferred`, a pointer to the new code or title.

## Using it

Gate your product on `goodLawStatus`, show `currencyNote`, and follow a move pointer when a section has moved.

<CodeGroup>
```python Python
import requests

BASE_URL = "https://api.vaquill.ai/api/v1/us"
HEADERS = {"Authorization": "Bearer vq_key_..."}

def section(act_id: str) -> dict:
    resp = requests.get(f"{BASE_URL}/statutes/section/{act_id}", headers=HEADERS)
    resp.raise_for_status()
    return resp.json()["section"]

sec = section("USC_T42_C21_S1983")

if sec.get("goodLawStatus") == "not_good_law":
    print(f"Do not rely on {sec['citation']}: {sec.get('actStatus')}")
elif sec.get("goodLawStatus") == "unknown":
    print(f"Verify {sec['citation']} against the official source before relying on it.")

# Follow a section that moved.
if sec.get("actStatus") == "renumbered" and sec.get("renumberedTo"):
    sec = section(sec["renumberedTo"])

print(sec.get("citation"), "-", sec.get("currencyNote") or "no currency note")
```

```javascript JavaScript
const BASE_URL = "https://api.vaquill.ai/api/v1/us";
const HEADERS = { Authorization: "Bearer vq_key_..." };

async function section(actId) {
  const r = await fetch(`${BASE_URL}/statutes/section/${actId}`, { headers: HEADERS });
  if (!r.ok) throw new Error(`HTTP ${r.status}`);
  return (await r.json()).section;
}

let sec = await section("USC_T42_C21_S1983");
if (sec.goodLawStatus === "not_good_law") {
  console.warn(`Do not rely on ${sec.citation}: ${sec.actStatus}`);
} else if (sec.goodLawStatus === "unknown") {
  console.warn(`Verify ${sec.citation} against the official source before relying on it.`);
}

// Follow a section that moved.
if (sec.actStatus === "renumbered" && sec.renumberedTo) {
  sec = await section(sec.renumberedTo);
}

console.log(sec.citation, "-", sec.currencyNote ?? "no currency note");
```
</CodeGroup>

The cross-reference fields (`statutoryAuthority`, `implementingRegulations`, `crossReferencesCfr`, `crossReferencesUsc`) and the Federal Register tracking fields (`frEffectiveOn`, `frCommentsCloseOn` and the rest) are described on [Response fields](/api-guide/concepts/response-fields).

## goodLawStatus by corpus

The verdict depends on the publisher, because only a publisher that records a retirement lets us detect one.

| Source | `goodLawStatus` served |
|---|---|
| `STATE_AGENCY_GUIDANCE`, `state_insurance_bulletin` | `good_law` |
| `STATE_AGENCY_GUIDANCE`, `state_financial_bulletin` | `unknown` |
| `STATE_AG_OPINION` | `unknown` |
| `AGENCY_ADJUDICATION`, every source except CFPB | `unknown` |
| `ftc_administrative_decision`, `ftc_hsr_interpretation`, `ftc_advocacy_filing` | `unknown` |
| CFPB enforcement actions | A real verdict. `actStatus` is `in_force` or `terminated`. |

Filter on `source` if you need one behavior or the other.

<AccordionGroup>

<Accordion title="State AG opinions and agency adjudications">
An AG opinion or an adjudication is superseded by a later decision, not amended. Almost no publisher records that, so we serve the text as issued and make no claim that it is still good law.
If your use depends on currency, check the issuing body's later output.
An AG opinion is also persuasive authority, not binding law. See [Corpus types](/api-guide/concepts/corpus-types).
</Accordion>

<Accordion title="FTC decisions, HSR interpretations and advocacy filings">
- `ftc_administrative_decision`: consent orders usually end after 20 years, but the sunset is in the order's text. We do not compute an expiry, so read the order's own terms.
- `ftc_hsr_interpretation`: supersession is served as `supersedes` and `supersededBy` (act ids), so you can walk from one interpretation to its replacement. Every member of those chains keeps `actStatus: "in_force"`.
- `ftc_advocacy_filing`: it binds nobody, so currency does not apply. Scope it in or out with `source` or `forum` (`ftc_advocacy`). Each document carries a `coverageNote`.
</Accordion>

<Accordion title="BIA and Attorney General decisions: reading a supersession link">
`supersedes` and `supersededBy` carry act ids. The link points at the cited decision, not the one you are reading.
A headnote under `Matter of Diji, 30 I&N Dec. 1 (BIA 2026)` reading "*Matter of G-Y-R-*, 23 I&N Dec. 181 (BIA 2001), overruled" means G-Y-R- is dead and Diji is in force.

A link alone does not mean a decision is dead. Read `actStatus`.
Partial dispositions such as `followed`, `modified`, `clarified`, `distinguished` and `reaffirmed` do not set a dead `actStatus`. Only an unqualified overruling, vacatur, supersession or withdrawal does.
</Accordion>

<Accordion title="CFPB enforcement actions">
The Bureau publishes a lifecycle status for every action, and [defines it](https://www.consumerfinance.gov/enforcement/actions/enforcement-action-definitions/):

| CFPB status | What we serve |
|---|---|
| `Post-order/Post-judgment` | `actStatus: "in_force"` |
| `Expired/Terminated/Dismissed` | `actStatus: "terminated"` |
| `Pending Litigation` | `actStatus: "in_force"` |

Terminated actions are excluded from ordinary search. Query them with `actStatus: "terminated"` for the historical record.
The terminated status covers several kinds of ending. Read the Bureau's raw status string in `history` for the outcome.
</Accordion>

<Accordion title="Agency guidance: what a document does to earlier documents">
`supersessionActions` records what a document does to earlier documents, keyed by the issuer's own verb: `modifies`, `obsoletes`, `amplifies`, `clarifies`, `rescinds`. Each maps to the documents affected.
`supersedes` and `supersededBy` cover only the strongest of those verbs.
`rescindedOn` carries the date, where the issuer states one.
</Accordion>

</AccordionGroup>
