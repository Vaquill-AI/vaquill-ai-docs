`state` accepts 56 US jurisdictions: all 50 states, plus the District of Columbia, Puerto Rico, Guam (`gu`), the Northern Mariana Islands (`mp`), the US Virgin Islands (`vi`) and American Samoa (`as`).
Federal law lives under its own `federal` jurisdiction, separate from the states.

Accepting a jurisdiction does not mean it holds every corpus for it.
A state may have its statutory code (`STATE`) and constitution (`STATE_CONSTITUTION`) but no administrative regulations (`REGULATION`) or court rules (`STATE_RULES`) yet.
Read `GET /us/statutes/coverage` before you scope a search.

## How jurisdictions are keyed

- **Codes:** 2-letter strings (`ca`, `tx`, `ny`, `fl`), case-insensitive.
  An unrecognized value is rejected with a 422 rather than silently matching nothing.
- **Lists:** pass several at once (`"state": ["ca", "ny", "tx"]`), which is one call instead of one per jurisdiction.
- **Federal and kind:** `federal` is the jurisdiction for the federal corpora, and a federal search needs only a `corpusType`, no `state`.
  Each jurisdiction row from `/us/statutes/coverage` carries a `kind` of `federal`, `state` or `territory`, and DC plus the five territories above are `territory`.

## Reading a jurisdiction's corpora

`GET /us/statutes/coverage` returns a wrapped `{ "data": ..., "meta": ... }`
response.
Each jurisdiction in `data.jurisdictions` has a `corpora` object whose keys are the `corpusType` tokens that actually have data, mapped to the ingested document count.
Read those keys to know which searches you can scope.

The same response carries `data.corpusTypes`, a legend naming every token and whether it is federal or state-scoped, so you never need a hardcoded list.

A jurisdiction that holds [state session laws](/api-guide/session-laws) also carries a `sessionLaws` block: its sessions with `status` (`complete` or `partial`), the counts served, withheld and still open, the numbering `series` and `instrumentTypes` it holds (the values the list and search endpoints accept) and the span of approval dates.
A jurisdiction with no session laws has no block.
Session laws are not a `corpusType`.

<CodeGroup>

```bash cURL
curl https://api.vaquill.ai/api/v1/us/statutes/coverage \
  -H "Authorization: Bearer vq_key_..."
```

```python Python
import requests

resp = requests.get(
    "https://api.vaquill.ai/api/v1/us/statutes/coverage",
    headers={"Authorization": "Bearer vq_key_..."},
)
data = resp.json()["data"]

# Which corpus types does California have?
ca = next(j for j in data["jurisdictions"] if j["code"] == "ca")
print(ca["name"], ca["kind"], ca["sectionCount"])
print("available corpora:", list(ca["corpora"].keys()))
# e.g. ['STATE', 'REGULATION', 'STATE_CONSTITUTION', 'STATE_RULES']
```

</CodeGroup>

<Accordion title="JavaScript">

```javascript JavaScript
const resp = await fetch("https://api.vaquill.ai/api/v1/us/statutes/coverage", {
  headers: { Authorization: "Bearer vq_key_..." },
});
const { data } = await resp.json();

// Which corpus types does California have?
const ca = data.jurisdictions.find((j) => j.code === "ca");

```

</Accordion>

This response does not say how recently a corpus was refreshed.
Read the free `GET /boards` alongside it (see [Law change alerts](/api-guide/alerts)).

<Accordion title="Freshness: lastRetrievedAt, cadence and currentThrough">
  `GET /boards` is free and carries `lastRetrievedAt` (left out of a board that has no successful retrieval yet) and `cadence` per source, so read it alongside the counts here to tell a maintained corpus from a frozen one.

  A board names a `(jurisdiction, corpusType)` pair, never a whole jurisdiction: a state can be frozen in one corpus and current in another.
  Where a publisher states its own currency, it rides on each section as `currentThrough`.
</Accordion>

## Listing a state's codes

`state=tx` alone searches every Texas code at once.
To scope below a jurisdiction, browse its codes with `/us/statutes/divisions`
and pass one back as the `code` filter on search.

<CodeGroup>

```bash cURL
curl -G "https://api.vaquill.ai/api/v1/us/statutes/divisions" \
  -H "Authorization: Bearer vq_key_..." \
  -d "corpusType=STATE" -d "state=tx"
```

```python Python
import requests

resp = requests.get(
    "https://api.vaquill.ai/api/v1/us/statutes/divisions",
    headers={"Authorization": "Bearer vq_key_..."},
    params={"corpusType": "STATE", "state": "tx"},
)
for node in resp.json()["divisions"]:
    print(node["identifier"], node["name"], node["sectionCount"])
# tx_pe  Tex. Penal Code  ...
```

</CodeGroup>

Each node's `identifier` is what `code` on `POST /us/statutes/search` takes, so browse output feeds straight back in.
Drill one level further by passing it back to `/us/statutes/divisions`
(`corpusType=STATE&state=tx&code=tx_pe` returns that code's chapters), and keep going until `isLeaf` is true, where each node carries an `actId`.

Browse supports the tokens with `browsable: true` in the `/us/statutes/coverage` legend, so you never need to probe for it (the list is on [Corpus types](/api-guide/concepts/corpus-types#tokens)).
The rest are dated series or share no tree, so reach those with `/us/statutes/search`.

<Tip>
  Check coverage first, then structure, then search: `/us/statutes/coverage` for the corpora a jurisdiction has, `/us/statutes/divisions` for how it is structured, then `POST /us/statutes/search` with the `corpusType`, `state` and `code` you confirmed.
</Tip>
