Every result has the same keys whatever corpus you searched. Many are `null` because they belong to a different corpus.
For example, only a Federal Register rule has a docket number, and only a court rule has a rule set.

<Note>
A `null` on a field marked **not applicable** for your `corpusType` means nothing.
A `null` on a field marked **expected** is a real gap. Tell us about it.
</Note>

## Present on nearly every section

These keys carry a value on nearly every section.

| Field | Meaning |
|-------|---------|
| `actId` | The stable identifier. Use it for every follow-up call. |
| `citation` | The full citation, including the edition year where the publisher prints one. |
| `citationShort` | The citation without the edition year. |
| `title` | The section's own heading. |
| `corpusType` | Which body of law this came from. |
| `state` | `federal`, or the two-letter jurisdiction. |
| `actStatus` | `in_force`, `repealed`, `superseded`, `reserved` and similar. |
| `goodLawStatus` | Our verdict on whether it is still good law. See [Status and currency](/api-guide/concepts/status-and-currency). |

`externalUrl` is the publisher's own page for the section. It is `null` when the publisher has no per-section link.
Cite `sourceUrl`, which is that link when present and otherwise the best official alternative.

`o` = expected to carry a value where the code has that level.

| `chapter` / `chapterName` | o | o | o | - | - |
| `subchapter` / `subchapterName` | o | - | o | - | - |
| `part` / `partName` | o | o | o | - | - |
| `subpart` / `subpartName` | - | o | - | - | - |
| `sourceCredit` | o | - | - | - | - |
| `publicLawCites` | o | - | - | - | - |
| `currentThrough` | o | - | - | - | - |
| `amendmentYears` / `lastAmendedYear` | o | o | o | o (final rules) | o |
| `effectiveDate` | o | - | o | o (final rules) | o |

Two more families belong to corpora with no column above.

| Fields | Belong to |
|---|---|
| `ruleSet`, `ruleSetCode` | `STATE_RULES`, `FEDERAL_RULES` |
| `articleNumber`, `articleName` | `CONSTITUTION`, `STATE_CONSTITUTION` |

For every field on every corpus, see the `StatuteResult` schema in the OpenAPI reference.

## Version and supersession fields

These are null unless the publisher states the relation itself.

| Field | Meaning |
|-------|---------|
| `supersededBy` | `actId` of the document that replaced this one. Can hold several `actId` values joined by `; `. |
| `supersedes` | `actId` of the earlier document this one replaced. |
| `priorEffectiveDates` | Earlier effective dates the publisher records for the section. |
| `versionId` | The publisher's identifier for this version of the document. Used for Colorado regulations. |

`supersededBy` and `supersedes` appear on state agency guidance bulletins, state court rules, and the `I&N Dec.` reporter under `AGENCY_ADJUDICATION`.
See [Status and currency](/api-guide/concepts/status-and-currency) for how to read a supersession link.

## Cross-references between statutes and regulations

USC and CFR sections carry each other's citations, so you can go from a statute to its implementing regulations and back.

- **`statutoryAuthority`** (CFR results): the USC citations the regulation cites as its authority.
- **`implementingRegulations`** (USC results): the CFR sections that cite this statute as their authority.
- **`crossReferencesCfr`** / **`crossReferencesUsc`**: cross-references to the other corpus found in the section text, as a list of section strings (for example `['1.6011-4']`). A section that references itself appears as `'self:<section>'`.

All four are nullable. A null does not mean no relationship exists.

## Federal Register tracking fields

`FEDERAL_REGISTER` results (final and proposed rules) carry fields for tracking a rule from proposal through effect:

| Field | Meaning |
|-------|---------|
| `frEffectiveOn` | The rule's effective date. |
| `frCommentsCloseOn` | Deadline for public comment, on a proposed rule. |
| `frSignificant` | Whether the rule is flagged as economically or otherwise significant. |
| `frCorrectionOf` / `frCorrections` | Links a correction notice to the rule it corrects, and vice versa. |
| `frRelatedDocuments` | Other documents sharing the same Regulation Identifier Number (RIN). |
| `frRegulationIdNumbers` | The RIN(s) assigned to the rulemaking. |
| `frDocketIds` | The regulations.gov docket ID(s) for the rulemaking. |

These appear on `GET /us/statutes/section/{actId}`, not on search results.

## Point-in-time text: `asOf`

`GET /us/statutes/section/{actId}/body` accepts `asOf=YYYY-MM-DD` and returns the text as it stood on that date, with an `asOf` block.
Read its `source` and `isBounded` before using the text.
See [Point-in-time law](/api-guide/point-in-time).

## Amendment fields on the Federal Register

`amendmentYears` on a final rule is the year it was published, which is the year it amended the CFR.
A proposed rule has no amendment years.

## Filtering by year

`yearFrom` and `yearTo` match a section on the first of these that it has:

1. `lastAmendedYear`, the publisher's credited amendment.
2. The year of `effectiveDate`, for a section adopted once and never amended.
3. The publication or issue year, for Federal Register proposed rules, agency guidance, adjudications and treaties.

A section with none of the three returns zero results for a year filter, not an error.
