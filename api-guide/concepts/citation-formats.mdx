`GET /us/statutes/resolve` turns a citation string into one exact section.
`POST /us/statutes/resolve` does the same for up to 50 at a time.
This page covers what to send and when to scope it, which together decide whether either route works for you.
It covers statutes, regulations, constitutions and court rules.
The Data API is not a case law API.

## The short answer: send back the citation we gave you

Every section we return carries a `citation` field.
That string is the form the publishing jurisdiction itself prints, and feeding it back is guaranteed to resolve to the same section.

```json Result from /us/statutes/search
{
  "actId": "STATE_GA_T51_C1_S51-1-6",
  "citation": "O.C.G.A. § 51-1-6",
  "sectionTitle": "Recovery of damages upon breach of legal duty."
}
```

```bash Feed it straight back
curl -G https://api.vaquill.ai/api/v1/us/statutes/resolve \
  -H "Authorization: Bearer vq_key_..." \
  --data-urlencode "cite=O.C.G.A. § 51-1-6"
```

If you are storing citations in your own database, store the `citation` value we return rather than a form you construct.
It round-trips by definition, and it survives us adding jurisdictions.

## You do not have to send Bluebook

The Bluebook form and the form the state's own courts use resolve to the same section.
You do not need a per-state table.
Real documents carry other variants too, and these are accepted.

| Variant | Example | Note |
|---|---|---|
| State form | `Ga. Code Ann. § 51-1-6` and `O.C.G.A. § 51-1-6` | The same Georgia section |
| State form | `Wash. Rev. Code § 59.18.060` and `RCW 59.18.060` | The same Washington section |
| State form | `Ohio Rev. Code § 2305.10` and `R.C. 2305.10` | The same Ohio section |
| State form | `Tenn. Code Ann. § 49-1-602` and `T.C.A. § 49-1-602` | The same Tennessee section |
| State form | `Alaska Stat. § 11.76.115` and `AS 11.76.115` | The same Alaska section |
| Code name after the section | `§ 292.290, RSMo`, `§ 162.41, Fla. Stat.` | Resolves like the name-first form |
| Edition year in the code name | `Ala. Code 1975, § 17-14-2`, `NMSA 1978, § 22-23-1.1` | The year names the edition, not the section, and is ignored |
| Doubled section symbol | `Cal. Civ. Code §§ 1950.5` | |
| Trailing period | `42 U.S.C. § 1983.` | A citation lifted out of a sentence works |
| Typographic dashes | Non-breaking hyphens, figure dashes, minus signs | Copied from a PDF or Word document. Invisible on screen, normalized for you |
| Pinpoint subsection | `42 U.S.C. § 1983(b)(2)` | Resolves to its section. `subsection` echoes the dot-joined pinpoint (`b.2`), and a `pinpoint` object carries the unit. See [Pinpoints](/api-guide/concepts/pinpoints) |

## Forms that are refused on purpose

Some acronyms belong to two or more jurisdictions.
We read the number that follows the acronym as well, and answer only when it fits one jurisdiction.
When it fits more than one, `resolve` returns `resolved: false` rather than guessing.
Pass `state` and it resolves, because you have told us which jurisdiction you mean.

| Acronym | Kind | Claimed by | Resolves without `state` when the number settles it |
|---|---|---|---|
| `MCA` | Statute | Montana and Mississippi Code Annotated | `MCA § 27-2-204` is Montana's three-part number |
| `IC` | Statute | Indiana and Idaho Code | `IC 34-11-2-1` is Indiana's four-part number, `IC 18-4001` Idaho's two-part one |
| `G.S.` | Statute | North Carolina and Connecticut General Statutes | `G.S. 1-52` is North Carolina's. `G.S. 52-577` fits both and is refused |
| `G.L.` | Statute | Massachusetts and Rhode Island General Laws | `G.L. c. 93A, § 2` can only be Massachusetts, and `G.L. 1956 § 9-1-13` Rhode Island |
| Bare `R.S.` | Statute | Louisiana and New Jersey Revised Statutes | `R.S. 2C:12-1` is New Jersey's. `R.S. 14:30` fits both and is refused |
| `CR` | Court rule | Kentucky Civil Rules and Washington Superior Court Civil Rules | Never. Pass `state` |
| `RAP` | Court rule | Washington, Kentucky and West Virginia | Never. Pass `state` |
| `TCR` | Court rule | Oregon and West Virginia | Never. Pass `state` |
| `M. R. Civ. P.` | Court rule | Montana and Maine | Never. Pass `state` |

<Warning>
  `resolved: false` on one of these is the correct answer, not a gap.
  A wrong section misstates the law, while an unresolved citation is a question you can answer.
  For a court-rule acronym the refusal holds even when we hold that rule number for only one state, because a gap in our coverage never counts as disambiguation.
</Warning>

```bash
# resolved: false - G.S. 52-577 fits North Carolina AND Connecticut
--data-urlencode "cite=G.S. 52-577"

# resolves - Conn. Gen. Stat. § 52-577
--data-urlencode "cite=G.S. 52-577" -d "state=ct"

# resolves - CR is KY and WA, so scope it: Washington Superior Court Civil Rule 56 (SRULES_WA_CR_R56)
--data-urlencode "cite=CR 56" -d "state=wa"
```

<Accordion title="Forms that name no jurisdiction">
  Virginia's own in-state form is the bare word `Code`, so `cite=Code § 8.01-243&state=va` resolves while the string alone cannot.
  Connecticut and North Carolina both print `General Statutes § ...`, which names a compilation but no jurisdiction.
  Those resolve the same way: `cite=General Statutes § 42a-1-101&state=ct`.
</Accordion>

## Scoping: a constraint, not a hint

`state` and `corpusType` narrow a lookup and never redirect one.

<Steps>
  <Step title="A citation that agrees with the scope resolves normally">
    `cite=O.C.G.A. § 51-1-6&state=ga&corpusType=STATE` returns the same section as the unscoped call.
  </Step>
  <Step title="A citation that disagrees returns resolved: false">
    `cite=O.C.G.A. § 51-1-6&state=tx` does not find a Texas section that happens to share the number.
    It returns `resolved: false`.
  </Step>
</Steps>

`corpusType` on `resolve` takes `STATE`, `REGULATION`, `STATE_RULES`, `CONSTITUTION` or `STATE_CONSTITUTION`.
`STATE` covers statutes of every jurisdiction, federal ones included.
Any other value, such as `USC`, is refused with a `422` (code `invalid_citation_input`) that names the accepted ones, before any charge.
An unrecognized `state` is a `422` on `resolve` too.

Scope when a citation form is shared across jurisdictions or corpora, since that is when a bare lookup could pick the wrong one:

- `8 CCR 1206-2` is Colorado and `22 CCR 76227` is California. The acronym alone cannot say which, so pass `state`.
- A rule number and a statute section often collide. If your citation names a court rule, pass `corpusType=STATE_RULES` so a same-numbered statute cannot answer instead.

If you are not disambiguating, leave the scope off.
Scoping an unambiguous citation cannot improve the answer, and a scope that disagrees with the citation turns a good result into `resolved: false`.

On `POST /us/statutes/search`, `state` and `corpusType` are a different thing: they filter the candidate pool before ranking.
A recognized citation passed as the `query` is pinned to rank 1 at `relevanceScore: 1.0`, scoped or not, so for one exact section prefer `/us/statutes/resolve`, which is cheaper and tells you whether the citation is real.
For a natural-language query, scoping changes which candidates are considered, so scoped and unscoped searches legitimately return different result sets.

## When the answer is not the exact unit you cited: `matchLevel`

An exact match carries none of the fields below.
Four optional fields appear on both `GET` and `POST /us/statutes/resolve` only when `section` is not the exact unit you cited.
`resolved` keeps its meaning (a section came back) and is `true` at every level, so read `matchLevel` to tell an exact section from a first-of-several.

| `matchLevel` | You cite | `section` is | Companion field | Example |
|---|---|---|---|---|
| absent | One section | Exactly that section | None | `42 U.S.C. § 1983` gives `USC_T42_C21_S1983` |
| `container` | A chapter, series, article, part or amendment | The first section in force inside it (the first of all when none is) | `container` | `Mo. Code Regs. Ann. tit. 10, § 40-6` gives `STATE_MO_CSR_T10_D40_C6_S010`, a chapter of 12 sections |
| `multiple` | Several sections in one citation | The first of them | `citedSections` | `42 U.S.C. §§ 1983-1985` gives `USC_T42_C21_S1983` |
| `repaired` | A recognized miscite of a code name | The section the repair names | `repair` | `N.Y. Jud. Ct. Acts Law § 475` gives `STATE_NY_AJUD_A15_S475`, read as `N.Y. Judiciary Law § 475` |
| `register_reference` | A state register page, issue or filing | The register item, or a rule whose history cites it | `registerReference` | `36 Pa. Bull. 510` gives `SREGISTER_PA_V36_P510` |

<Warning>
  A flagged answer is the first section of several, or a correction of what you wrote, so do not treat it as the section you cited.
  For strict verification, accept only responses with no `matchLevel`.
  A citation that resolves only through a flagged reading is not pinned to rank 1 by `POST /us/statutes/search` and is not accepted by the `{actId}` routes.
</Warning>

<AccordionGroup>
  <Accordion title="container: chapters, series, articles and amendments">
    `container` carries `kind` (`chapter`, `subchapter`, `series`, `article`, `section` for a constitution section made of numbered paragraphs, or `amendment`), `label`, `childCount` (always exact), `children` (`actId`, `citation`, `status`, in document order) and `truncated` (true when `children` lists fewer than `childCount`; at most 50 are listed).

    More examples:

    | You send | `section.actId` | Note |
    |---|---|---|
    | `N.J.A.C. 8:33E` | `STATE_NJ_NJAC_T8_C33E_S1_S8_33E_1_1` | Chapter of 31 sections |
    | `85 CSR 20` | `STATE_WV_CSR_T85_SER20_S1` | Series of 71 sections, `truncated: true` |
    | `Ga. Const. art. X, § I` | `SCONST_GA_AX.I_SI` | Six paragraphs under one section number |
    | `Iowa Const. amend. 21` | `SCONST_IA_AV_S4` | Nine sections whose own note credits Amendment 21. `children` starts with `SCONST_IA_AV_S3`, which is repealed, so the first section in force is returned |

    A real answer, taken from the resolver:

      "container": {
        "kind": "chapter",

        "childCount": 12,

    The real response lists all twelve children.
  </Accordion>

    `citedSections` lists the sections you named, as written.

  </Accordion>
  <Accordion title="repaired: a recognized miscite of a code name">

### Register citations

`36 Pa. Bull. 510` or `17 Ill. Reg. 10414` names a page of a state register.
The answer depends on whether we hold that register:

- **We hold the item** (`registerReference.registerItemHeld: true`). `section` is the register notice itself, `corpusType` `STATE_REGISTER`. It is a notice as printed on a date, not codified law. `kind` is `page` when the citation names the page the item starts on and `range` when it names a later page of the item. Held for the jurisdictions listed under [State administrative registers](/api-guide/coverage/states#state-administrative-registers).
- **We do not hold it** (`registerItemHeld: false`). `section` is a codified rule whose history note cites that page: the first of `ruleCount`, with the others in `rules`. An omnibus item that touched more than 30 rules is refused rather than represented by one arbitrary rule.

<Accordion title="registerReference fields, samples and the exact-hit rule">
  `registerReference` carries `citation` (as we read it), `state`, `kind`, `ruleCount` (always exact), `rules` (their `actId`s, in document order, at most 25) and `registerItemHeld`.
  `kind` is `page` (a history note cites exactly this volume and page), `range` (a note cites a range that contains the page), `issue` (the citation names a register issue, as Colorado and Michigan cite) or `filing` (it names a filing identifier, as Washington, Nevada, Indiana and Wisconsin do).

  ```json register item held (36 Pa. Bull. 510)
  {
    "matchLevel": "register_reference",
    "registerReference": {
      "citation": "36 Pa. Bull. 510",
      "state": "pa",
      "kind": "page",
      "ruleCount": 1,
      "rules": ["SREGISTER_PA_V36_P510"],
      "registerItemHeld": true
    }
  }
  ```

  ```json register item not held (17 Ill. Reg. 10414)
  {
    "matchLevel": "register_reference",
    "registerReference": {
      "citation": "17 Ill. Reg. 10414",
      "state": "il",
      "kind": "page",
      "ruleCount": 18,
      "rules": ["STATE_IL_IAC_T1_P100_S100_120", "STATE_IL_IAC_T1_P100_S100_210"],
      "registerItemHeld": false
    }
  }
  ```

  Only an exact hit counts: the exact volume and page, a range that contains the page, or the exact filing identifier.
  A page that merely falls between two cited pages is never a hit, and a page is never matched without its volume.
  `17 Ill. Reg. 10415` returns `resolved: false`.
  Washington's `WSR 20-12-091` and Virginia's `27 Va. Reg. 640` resolve to the register item, and Colorado's `42 CR 15` names an issue and resolves to the first of 11 rules that cite it.
  A register citation that no held item and no rule's history note cites returns `resolved: false`.
</Accordion>

## Checking a whole document: `POST /us/statutes/resolve`

Everything above applies unchanged to the batch route.
It takes up to **50 citations** in one call and returns the same verdict per citation.
Use it when you are checking the citations in a document rather than looking one up.
A brief, a memo or a model's output typically carries dozens, and the single-citation route makes that dozens of round trips.

<CodeGroup>

```bash cURL
curl -X POST https://api.vaquill.ai/api/v1/us/statutes/resolve \
  -H "Authorization: Bearer vq_key_..." \
  -H "Content-Type: application/json" \
  -d '{"citations": ["42 U.S.C. 1983", "16 C.F.R. 444.1", "Cal. Civ. Code 1950.5"]}'
```

```python Python
import requests

resp = requests.post(
    "https://api.vaquill.ai/api/v1/us/statutes/resolve",
    headers={"Authorization": "Bearer vq_key_..."},
    json={
        "citations": [
            "42 U.S.C. 1983",
            "16 C.F.R. 444.1",
            "Cal. Civ. Code 1950.5",
        ]
    },
).json()

for item in resp["results"]:
    if item["resolved"]:
        print(item["inputCitation"], "->", item["section"]["actId"])
    else:
        print(item["inputCitation"], "-> unresolved")

print(resp["resolvedCount"], "of", resp["count"], "resolved")
```

</CodeGroup>

| Behavior | Rule |
|---|---|
| Every input gets an entry | An unresolved citation comes back with `resolved: false`, never as an omission, so you can tell which ones failed |
| Duplicates | Collapsed before pricing and before the response is built. The same citation sent twice costs once and returns one entry. `results` lines up with the de-duplicated input, in the order supplied, and `count` is its length |
| Scoping | `state` and `corpusType` apply to every citation in the call, the same constraint as on the single route. A batch spanning jurisdictions should omit them and let each citation name its own |
| Price | Billed per citation, exactly what resolving them one at a time would cost. Unresolved citations are charged, because a confident "this does not resolve" is the answer you are paying for. Only citations we failed to process because of a backend error are refunded, so read `creditsConsumed` rather than multiplying |

## State session law citations

`/us/statutes/resolve` resolves code sections first.
When a citation names no code section but does name a state session law (`CHAPTER 2025-12`, `S.F.No. 1552`), the response carries `matchedCorpus: "session_law"` and a `sessionLaw` block with the law's title, dates, outcome and `href`, and `resolved` stays `false` because `section` is null.
`sessionLaw.status` is `matched` or `ambiguous`; an ambiguous citation lists every candidate and chooses none.
There is no extra charge.
To read the law, send its `sessionLawId` or the citation itself to [`GET /us/session-laws/{sessionLawId}`](/api-guide/session-laws#finding-a-law).

## Treaty citations

A treaty citation is recognized as a treaty. It is never read as a U.S. Code section or a Public Law.

| Form | Example | Resolves |
|---|---|---|
| Senate Treaty Document | `S. Treaty Doc. No. 98-9`, `Treaty Doc. 105-1A` | Yes. The Treaty Document text when the treaty went to the Senate from 1995 on, otherwise the ratification record |
| United States Treaties | `20 U.S.T. 361` | Yes. The instrument that begins at that page (volumes 1 to 35, 1950 to 1984) |
| Statutes at Large | `49 Stat. 3000` | Yes, in volumes 1 to 64. The treaty or the session law printed at that page |
| Bevans | `1 Bevans 631` | Yes. Answered from the Statutes at Large printing of the same instrument where both exist, so `1 Bevans 631` returns `36 Stat. 2277` |
| Senate Executive Report | `S. Exec. Rep. No. 102-23` | `not_held` |
| Treaties and Other International Acts Series | `T.I.A.S. No. 95-1121`, `T.I.A.S. No. 24-815.1` | Yes, from 1984 on. The instrument with that number. An older number, such as `T.I.A.S. No. 6638`, answers from its U.S.T. printing |
| Social Security totalization agreement | `Social security totalization agreement, Norway, agreement, art. 2` | Yes. That article, or the instrument when no article is given |
| Treaty Series, Executive Agreement Series | `T.S. No. 993`, `E.A.S. No. 12` | `not_held` |
| United Nations Treaty Series | `658 U.N.T.S. 163` | `not_held` |
| League of Nations Treaty Series | `137 L.N.T.S. 11` | `not_held` |

Treaty text is served one section per article.
A cite to the instrument itself, such as `20 U.S.T. 361`, answers with `matchLevel: "container"`: `section` is the instrument's opening section, and `container.children` lists every article in printed order.
An article pinpoint written before the series cite, as in `Hague Service Convention art. 10, Nov. 15, 1965, 20 U.S.T. 361, T.I.A.S. No. 6638`, is read as the pinpoint and resolves to that article.
A pinpoint to an article the instrument does not print is refused, never answered with another article.

A `not_held` answer carries `resolved: false`, `missReason: "not_held"` and a `missReasonHint` that says the form was recognized and lists the treaty material we hold.
For U.S.T., Bevans and Statutes at Large cites the hint says that the series is held and no instrument we hold begins at or spans that volume and page, so check the citation.
For a T.I.A.S. cite it says that no instrument we hold carries that number, so check the number.
A citation that two instruments we hold share is refused, never answered with one of them, and the hint says so.
Text printed only in T.S., E.A.S., U.N.T.S. or L.N.T.S. is not held. Cite such an instrument by its U.S.T., T.I.A.S. or Statutes at Large citation where it has one.

To find an instrument by topic or party, search `corpusType=US_TREATY`, or `US_TAX_TREATY` for the IRS income tax treaties.
See [Treaty coverage](/api-guide/coverage/treaties) for what each holds.

## When something does not resolve

<Steps>
  <Step title="Check it is not a deliberate refusal">
    Compare against the shared-acronym table above.
    If it is on that list, add `state`.
  </Step>
  <Step title="Drop the scope">
    A scope that disagrees with the citation returns `resolved: false`.
    Retry without `state` and `corpusType` to find out whether the scope was the problem.
  </Step>
  <Step title="Search for it instead">
    `POST /us/statutes/search` with the citation as the `query` will surface the section even when the string is not a form we parse, and the result carries the `citation` we do recognize.
  </Step>
  <Step title="Tell us">
    A citation that a jurisdiction genuinely prints and that we cannot read back is a defect on our side, not yours.
    Send it to [contact@vaquill.ai](mailto:contact@vaquill.ai) and we will fix the parser.
  </Step>
</Steps>

### Miss reasons

An unresolved answer can carry a `missReason`.

| `missReason` | Meaning | Fix |
|---|---|---|
| `not_held` | The citation reads as one to a jurisdiction and corpus we serve, and we do not hold that section. A `U.N.T.S.` cite is an example | Read `missReasonHint` for what we do hold |
| `ambiguous_jurisdiction` | The form is one several jurisdictions print, or names none, and no `state` was given | Pass `state`. `candidates` lists the held sections it could mean when we can name them |
| `former_law` | It names a repealed, renumbered or retired compilation we do not serve as current law | Read `missReasonHint` for the successor where one is known |
| `malformed` | No parser reads it: a docket or database token, a case or treatise citation, a string with no section number | Fix the string, or search for it instead |
| `out_of_scope_corpus` | It names a body of law this route does not serve | `missReasonHint` says which and where to look |
| `container_not_supported` | It cites a chapter, article, title or part, not a section, in a form this route does not answer | Cite a section inside it, or browse with `GET /us/statutes/divisions` |
| `index_warming` | Batch items only. The code was still being read, so there is no verdict. The item is not billed | Send it again in a few seconds |
| `lookup_failed` | Batch items only. The citation resolved but we failed to load its section. The item is refunded | Retry it |
| `miss_reason_unavailable` | The check that explains a miss failed on our side. The unresolved verdict is unchanged | Resend it |
