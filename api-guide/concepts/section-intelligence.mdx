Four routes about a section you already hold, each starting from an `actId`.

| Route | Answers | Credits | Scope |
|---|---|:---:|---|
| `/section/{actId}/changes` | Has this section changed? | 1 | Any section |
| `/section/{actId}/cited-by` | Which sections cite this one? | 2 | USC and CFR |
| `/section/{actId}/definitions` | What do its defined terms mean? | 4 | Best on USC. CFR and state codes vary |
| `/section/{actId}/cross-state` | How do other states word the same rule? | 6 | State statute sections |

All four are `GET` routes under `https://api.vaquill.ai/api/v1/us/statutes`.
A call that cannot answer is refunded and carries a `note` that says why.

## Changes: what has moved

`GET /us/statutes/section/{actId}/changes` returns the changes we have observed to one section: when it was added, each time its text was replaced, and whether it was removed.

| Parameter | Default | Notes |
|---|---|---|
| `limit` | 50 | Max 200 |
| `order` | `desc` | `desc` is newest first. `asc` replays a section's life forward |
| `changeKind` | All | `added`, `amended`, `removed`. Repeat the parameter for several |
| `sinceId` | None | Poll forward: return changes with an `id` above this. Carry `cursor` |
| `beforeId` | None | Walk back: return changes with an `id` below this |

```bash
curl "https://api.vaquill.ai/api/v1/us/statutes/section/USC_T42_C21_S1983/changes?limit=10" \
  -H "Authorization: Bearer vq_key_..."
```

Each event carries `changeKind`, `detectedAt`, `displayCitation`, `hasDiff` and the `corpusType` board it was captured on.

<Warning>
  `detectedAt` is when we saw the difference, not the effective date. For the publisher's dates, read `amendmentHistory` on `GET /us/statutes/section/{actId}`.
  An empty `changes` list means no change was captured. Check the `coverage` field before treating it as "unchanged".
</Warning>

If the newest change is `removed`, the section is gone from the corpus and `section` is null. This is a charged `200`, not a `404`.

## Cited-by: the reverse index

`GET /us/statutes/section/{actId}/cited-by` returns the sections whose text cross-references the one you asked about.

| Parameter | Default | Notes |
|---|---|---|
| `limit` | 25 | Page size. Max 100 |
| `offset` | 0 | Rows to skip, max 5,000. Pass the previous response's `nextOffset` to read the next page |

```bash
curl "https://api.vaquill.ai/api/v1/us/statutes/section/USC_T42_C21_S1983/cited-by?limit=50" \
  -H "Authorization: Bearer vq_key_..."
```

Results are one row per citing section, in statutory order.
To page, pass `nextOffset` as `offset` until `hasMore` is false. A page past the end is empty and not charged.
State codes and Federal Register rules return an empty list with a `note`, and are refunded.

<Expandable title="Response fields">

| Field | Meaning |
|---|---|
| `total` | Count of distinct citing sections across all pages |
| `returned` | Rows on this page |
| `truncated`, `hasMore` | True when another page follows |
| `nextOffset` | The `offset` for the next page. Null on the last page |
| `totalCiters` | Distinct citing sections. A lower bound when `totalCitersIsLowerBound` is true |
| `totalCitersIsLowerBound` | When true, the count stopped at a ceiling and more exist |
| `verifiedCiters` | How many of the leading rows were confirmed to name this section |

</Expandable>

A missing row does not prove a section is uncited.

## Definitions: the terms that govern a section

`GET /us/statutes/section/{actId}/definitions` returns the defined terms that apply to a section, parsed from its chapter's definitions section.
It takes no parameters.

```bash
curl "https://api.vaquill.ai/api/v1/us/statutes/section/USC_T15_C1_S1/definitions" \
  -H "Authorization: Bearer vq_key_..."
```

Each entry in `terms` has the `term`, the `definition` verbatim, and the `marker` where the source numbers its definitions.
`definitionsSection` names where the terms came from, so you can cite it.

Results are most reliable on the U.S. Code. CFR and state codes are best effort.
If we find a definitions section but cannot parse it, the call returns empty with a `note` and is refunded. `definitionsSection` is still set, so you can read it from `/section/{actId}/body`.

If a definitions section is scoped to a different chapter, subchapter or part ("As used in this subchapter"), the answer is empty, the `note` says so, and the call is not charged.

## Cross-state: the same rule elsewhere

`GET /us/statutes/section/{actId}/cross-state` returns provisions in other states that address the same subject as a state statute section.

| Parameter | Default | Notes |
|---|---|---|
| `limit` | 5 | Max 25. Counts states, one provision each |

```bash
curl "https://api.vaquill.ai/api/v1/us/statutes/section/STATE_TX_Cpr_C93_S93.005/cross-state?limit=10" \
  -H "Authorization: Bearer vq_key_..."
```

The response has at most one provision per state, most similar first.
USC, CFR, regulations and court rules return empty with a `note` and are refunded.
When `rankingDegraded` is true, the neighbors are in retrieval order, `note` says so, and the call is refunded.

`statesCovered` is how many other states were examined. `neighbors` can be shorter.

`similarity` is a score from 0 to 1 for how closely two provisions read. It is not a legal opinion. Read the results as a shortlist.
