`/forums` is free, and it carries the `code` every other route takes.
Call it first. Show users what it returns rather than what this page says.

## What a matter is here

A **matter** is one case, order sheet or ruling as a forum published it.
It has a title, parties where recorded, a bench, a case number, a decision date where one can be trusted, and usually one document.

This is a **case index, not a judgment-text API**.
No judgment text exists in this corpus.
Search reads title, petitioner and respondent only, and the document is served as a file through `/file`.

Four of the 15 forums are not tribunals.
The CCI is a regulator, the IBBI a board, RERA an authority and the GST AAR an advance-ruling body.
`forumType` says which: `tribunal`, `regulator`, `board`, `authority` or `advance-ruling`.

## How to read a forum

- **Documents.** 3.5% of matters corpus-wide have no document, and almost all of that is NCLT. A missing document is a 404 `matter_file_unavailable` on `/file`, and it does not mean the matter is missing. Check `hasFile`.
- **Orders.** Only `cat_cis`, `drt` and `nclt` keep an order list. The other 12 answer `not_applicable`, which is a 200. In DRT, 2,694 matters answer `unjoinable`, which means unknown.
- **`isJudgment`.** In CAT CIS, `false` means an order sheet we hold. In NCLT, `false` means a case listing with no document.
- **`docType`.** It is informational and is not a filter. CCI uses three values (`combination`, `antitrust`, `press_releases`) and ATFP uses two (`order`, `judgment`), so read it on the matter. `isJudgment` is `true` on every CCI press release.

## Known limits

- There is no judgment text. A search miss is not evidence that a document does not mention your term.
- Read `dateQuality` before treating `decisionDate` as exact. For NCLT, 36.8% of matters store the filing date in the decision-date column. It is withheld, and `filedOn` on `/detail` carries it.
- A list row and a detail response can disagree about one NCLT matter. `/detail` is the authority.
- `caseNumber` is null on a few thousand matters, mostly DRT, and is served as `null` and never as an empty string.
- `scrapedAt` is when we collected a record, not when it was decided. Do not sort on it.
- Browse and search return no `total`. Both page with a cursor.

## Routes

Six `GET` operations under `https://api.vaquill.ai/api/v1/in/tribunals`.
All six need the scope `cases:read`.
The Credits column is a snapshot. The live pricing matrix is authoritative.

| Route, under `/api/v1/in/tribunals` | Credits | What it answers |
|---|---:|---|
| `GET /forums` | **0** | The 15 forums, with counts, the judgment split and document availability for each. |
| `GET /matters` | 1 per page | Browse by forum, bench, year, decision date or exact case number, newest decision first. |
| `GET /matters/search` | 2 per page | Search matters by party or title. Not judgment text. |
| `GET /matters/{tribunal}/{caseId}/detail` | 1 | One matter's full record, and the authority on its decision date. |
| `GET /matters/{tribunal}/{caseId}/orders` | 1 | The orders recorded against one matter, or why there is no list. |
| `GET /matters/{tribunal}/{caseId}/file` | 1 | The document held for one matter, as PDF bytes. |

Full request and response shapes are in the India API Reference tab, generated from the [India OpenAPI document](https://api.vaquill.ai/in/openapi.json).

## Paging

`/matters` and `/matters/search` page with a cursor, not an offset.
Send the `nextCursor` you were given, unchanged, to resume where you stopped.
`hasMore` tells you whether to continue.

There is no `total`, on purpose.
Use `GET /forums` for per-forum counts.

## Sources

Every matter comes from the forum's own published records.
