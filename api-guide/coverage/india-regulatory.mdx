<Info>
  This is **India regulatory publications**: what Indian regulators and courts published, and when it changed.

  It is a different corpus from [India legislation](/api-guide/coverage/india), which holds acts and sections.
  The routes, filters and units differ. No `actId` applies here, and no `documentId` applies there.
</Info>

```bash
# The live answer. Free, and authoritative over this page.
curl https://api.vaquill.ai/api/v1/in/reg/sources \
  -H "Authorization: Bearer vq_key_..."
```

`/sources` lists the publishers and sources we serve, how far back each goes, and when each was last checked.
It costs no credits. Show users what it returns rather than what this page says.
Each source reports `retrievalStatus` and `sourceCheckedAt`.

## What a document is here

A **document** is one thing a publisher issued: a circular, a notification, a gazette entry, a cause list, a judgment or a press release.
It has a publisher, a source (the listing it came from), a date, a title, and usually an archived file.

A **version** is one observation of a document.
Regulators sometimes edit a document in place, so one circular can have several versions.
The changes feed moves on versions.

## Publishers and sources

We track **47 publishers** across **273 sources**.
A new document usually appears within a day of the publisher posting it.

A **publisher** is the body that issued the document.
A **source** is one listing on that publisher's site, so a single publisher usually has several: SEBI's circulars and its settlement orders are different sources, with different document types and their own freshness.
`publisherId` and `sourceId` filter at those two levels, and `GET /sources` returns every row below with its own `documentCount`, `retrievalStatus` and `sourceCheckedAt`.

Counts per publisher are deliberately not listed here.
They move whenever a source is added or a crawl runs, and a number printed on this page would be wrong without anything failing.
Read them from `GET /sources`, which is free.

## Known limits

- Some documents have no date, so a date filter excludes them. Filter on `firstSeenFrom` to get everything.
- Some sources are metadata-only. Check `fileAvailability` before requesting a file.
- A file we never archived returns 404 `content_not_archived`. Do not retry it.

## Routes

Five `GET` operations under `https://api.vaquill.ai/api/v1/in/reg`.
The Credits column is a snapshot. The live pricing matrix is authoritative.

| Route, under `/api/v1/in/reg` | Credits | What it answers |
|---|---:|---|
| `GET /sources` | **0** | What the corpus holds and how fresh each source is. |
| `GET /documents` | 1 | Search and filter documents across every publisher. |
| `GET /documents/{id}/detail` | 1 | One document: its metadata, and optionally its text, versions or diff. |
| `GET /documents/{id}/file` | 1 | The archived file as bytes. |
| `GET /changes` | 1 | What changed, newest first, as a resumable feed. |

Full request and response shapes are in the India API Reference tab, generated from the [India OpenAPI document](https://api.vaquill.ai/in/openapi.json).

## Paging and the changes feed

Both list routes page with a cursor, not an offset.
Send the `nextCursor` you were given to resume where you stopped.
`hasMore` tells you whether to continue.

`total` has three states:

- A number means we counted.
- `null` means we did not count. It is not zero.
- `0` means empty.

On `/documents` the count is capped, and `totalIsExact: false` says so.
On `/changes`, `total` is always `null`.

<Note>
  Multi-value filters are repeated keys, not comma lists.
  `?publisherId=1&publisherId=2` selects two publishers.
  `?publisherId=1,2` is rejected with a 400.
</Note>
