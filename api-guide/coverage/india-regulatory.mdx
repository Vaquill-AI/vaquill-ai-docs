  This is **India regulatory publications**: what Indian regulators and courts published, and when it changed.

  It is a **different corpus from [India legislation](/api-guide/coverage/india)**, which holds acts and sections.

Indian regulators and courts, their own listings, polled on their own schedules.

```bash
# The live, self-describing answer, and the authoritative one. Free.
curl https://api.vaquill.ai/api/v1/in/reg/sources \
  -H "Authorization: Bearer vq_key_..."
```

`/sources` is the authoritative statement of what this corpus holds: which publishers and sources are served, how far back each one goes, and how fresh each one is.
It costs no credits, it reads the database, and it is current by construction.
Anything you display to a user should come from there rather than from this page.

## What a document is here

A **document** is one thing a publisher issued: a circular, a notification, a gazette entry, a cause list, a judgment, a press release.
It has a publisher, a source (the specific listing it came from), a date, a title, and usually an archived file.

A **version** is one observation of that document.
Regulators edit in place without saying so, so the same circular can have several versions, and the difference between two of them is often the only notice anyone gets.
This is the unit the changes feed moves on.

Do not read a document count as a version count.
Most documents have been observed once and some many times, so there are always somewhat more versions than documents.

## Freshness

Sources are polled on their own schedules rather than all at once, and a full pass across every source takes hours rather than minutes.
A document typically appears within a day of the publisher posting it.
`/sources` reports `sourceCheckedAt` per source, so you can see exactly how stale any one lane is rather than trusting a single global figure.

## Known limits

Read this section before relying on this corpus in front of a client.

**Not every document has a date.**
Most documents carry a publication date, but a small share do not: they came from listings that do not publish one, so a date filter silently excludes them.
Filter on `firstSeenFrom` instead when you need everything.

**A few dates are in the future.**
A handful of documents carry a date later than today.
These are genuine: some court listings publish the hearing date rather than the issue date, and we record what the publisher said rather than correcting it.

**The archive is not complete, and says so.**
Some sources are deliberately metadata-only: we record that a document exists without storing its bytes.
`fileAvailability` on every document tells you which.
Asking for the file of a document we never archived returns `content_not_archived` with a 404.
That is a settled answer, not a transient failure, and retrying will not change it.
A storage failure on a document we did archive is a different answer, `archive_unavailable` with a 502, and retrying that is worthwhile.

**Coverage reflects what we are permitted to redistribute.**
Publishers whose terms do not permit redistribution are withheld from this API, and withheld documents are absent rather than listed-and-blocked.
A publisher can therefore disappear from coverage between two readings, and `/sources` is the only reliable statement of what is currently served.

**Coverage moves.**
The corpus grows every day and sources are occasionally withdrawn, so this page describes shape rather than quantity.
Read `/sources` for anything you display to a user, and do not cache its answer as a constant.

## Routes

Five operations, all `GET`, all under `https://api.vaquill.ai/api/v1/in/reg`.
The Credits column is a snapshot and the live pricing matrix is authoritative.

| Route, under `/api/v1/in/reg` | Credits | What it answers |
|---|---:|---|
| `GET /sources` | **0** | What the corpus holds and how fresh each source is. |
| `GET /documents` | 1 | Search and filter documents across every publisher. |
| `GET /documents/{id}/detail` | 1 | One document: its metadata, and optionally its text, versions or diff. |
| `GET /documents/{id}/file` | 1 | The archived file as bytes. |
| `GET /changes` | 1 | What changed, newest first, as a resumable feed. |

Full request and response shapes are in the India API Reference tab, generated from the [India OpenAPI document](https://api.vaquill.ai/in/openapi.json).

## Paging and the changes feed

Both list routes page with a **cursor**, never an offset or a page number.
Send the `nextCursor` you were given and you resume exactly where you stopped.
There is no page to skip past and no window that shifts under you while you read.

`hasMore` tells you whether to continue.
`total` is three-state and worth reading carefully:

- a **number** means we counted
- **`null`** means we did not count, which is not the same as zero
- **`0`** means genuinely empty

On `/documents` the count is capped, and `totalIsExact: false` says so.
A capped count that claimed to be exact is a number somebody would do arithmetic on.
On `/changes`, `total` is always `null` by design: the feed is unbounded and counting it would cost more than reading it.

<Note>
  Multi-value filters are **repeated keys**, not comma lists.
  `?publisherId=1&publisherId=2` selects two publishers.
  `?publisherId=1,2` is rejected with a 400 rather than silently matching nothing, because a filter that quietly matches nothing returns a confident empty page.
</Note>

## Sources and refresh

Every document comes from the publisher's own website or feed.
No commercial database is a source, and nothing here is re-keyed from a third-party aggregator.

Each source is polled on its own schedule.
Every poll is recorded whether or not it found anything, so "nothing was published" and "we could not read the page" are distinguishable rather than both appearing as silence.
`/sources` exposes that per source as `retrievalStatus`.
