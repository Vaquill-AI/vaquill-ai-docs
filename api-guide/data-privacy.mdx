This page covers the developer API (`api.vaquill.ai`) and the MCP server, not the Vaquill AI chat product. They are separate systems with separate data handling.

The API returns US primary law: statutes, regulations, court rules and related government sources. It keeps as little of your traffic as possible.

- **Not stored.** Your query text, request bodies and parameters are never written to a database or log. They stay in memory for the length of the request.
- **Not used for training.** We do not train models on your requests or build datasets from them. The [Data Processing Agreement](https://vaquill.ai/dpa) commits Vaquill AI and its sub-processors to the same.
- **One sub-processor sees query text.** Voyage AI handles embeddings and re-ranking. No LLM provider receives your requests.

## What's stored

| Data | Contains | Retention |
|---|---|---|
| API key | A SHA-256 hash for authentication, an encrypted copy so the dashboard can show the key again, and a short display prefix like `vq_key_ab12...` | Until you revoke the key |
| API call log | One row per call: endpoint, HTTP status, response time, credits charged, API key and user agent. No query text, bodies or headers. | Used to report usage per key |
| Usage counters | Call counts per key, per day, per endpoint | 48 hours |
| Billing ledger | User ID, credit amount, endpoint label (for example `statutes.search`) and timestamp | Permanent billing record |
| Law Change Alerts watch | Webhook URL, an encrypted webhook secret used to sign deliveries with `X-Vaquill-Signature`, email address and the board you watch. The secret is never returned by any endpoint. | Until you delete the watch |
| Webhook delivery attempts | Status code, success or failure, a short error string and attempt number. Not the payload. Shown by `GET /watches/{watchId}/deliveries`. | 90 days |
| Request observability | Route template, status code and response time. No bodies. | Sampled |

Error monitoring runs with personally identifiable information (PII) collection disabled.

## Processors and regions

| Processor | What it sees | Where |
|---|---|---|
| Voyage AI | Query text, to create an embedding and re-rank results | See the register |
| Our application servers | Query text, in memory only | United States |
| Cloudflare | Edge traffic, served from the location nearest the caller | Edge locations worldwide |
| Hosting, database, payments, email, error monitoring | No query text | See the register |

The full sub-processor register is available to customers and their counsel at [contact@vaquill.ai](mailto:contact@vaquill.ai).
We give at least 30 days' notice before adding a sub-processor.

## Citation extraction

`POST /us/statutes/extract-citations` takes up to 200,000 characters of your text, finds the statute citations in it and looks each one up.
The text is processed in memory, discarded after the response, and never sent to a third party.

The API has no document upload or document storage.

## Sensitive and regulated matters (HIPAA, client confidences)

We do not sign Business Associate Agreements today.
The API does not need protected health information or client facts. A request is a legal research question, such as "Florida statute of limitations for medical malpractice".

<Accordion title="Using this with HIPAA or client-confidential work">
  Keep the sensitive part of the request inside your environment:

  <Steps>
    <Step title="Your user asks a question">
      The question may contain patient or client details. That stays inside your platform.
    </Step>
    <Step title="Your system decomposes it">
      Your application or agent works out the legal question and strips identifiers.
    </Step>
    <Step title="Only the legal question reaches Vaquill AI">
      You call the API or MCP server to search for the relevant section or resolve a citation.
    </Step>
    <Step title="We return the law">
      No client data reaches our systems.
    </Step>
  </Steps>

  If that does not work for you, a [bulk license](/api-guide/bulk-and-sql) takes Vaquill AI out of the query path.
  We deliver the corpus under contract, and you run search in your own environment under your own BAAs and controls.
</Accordion>

## Security and contracts

- **Certifications.** We do not hold a SOC 2 Type II, HITRUST or ISO 27001 report today. We complete security questionnaires and walk your engineers through the architecture.
- **Breach notification.** We notify the account administrator within 72 hours of learning of a breach that affects your data. See section 2.9 of the [DPA](https://vaquill.ai/dpa) and section 7 of [vaquill.ai/security](https://vaquill.ai/security).
- **DPA.** Available at [vaquill.ai/dpa](https://vaquill.ai/dpa).
- **Encryption.** AES-256 at rest for the database, TLS in transit.

## Multiple clients on one account

Several API keys per account, one key or organization per client, and building a product on the API are covered in [Rights and licensing](/api-guide/rights-and-licensing#multiple-clients-and-end-users).

## What we don't do (yet)

There is no self-serve control to set a custom retention window or request early deletion of your account's records.
If you need that, or a signed data processing agreement, email [support](mailto:contact@vaquill.ai).
