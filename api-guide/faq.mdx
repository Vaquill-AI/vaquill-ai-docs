## Search and retrieval

<AccordionGroup>

<Accordion title="How do I get every section matching a query, not just the top results?">
Search ranks results and returns a limited number per query, so it cannot list every match.

To cover a whole body of law, browse the hierarchy instead.
`GET /us/statutes/divisions` walks codes to chapters to sections and returns every section in a container with its `actId`.

See [Build a subject corpus](/api-guide/recipes/subject-corpus) and [How search works](/api-guide/concepts/search).
</Accordion>

<Accordion title="I set limit and I am still capped. How deep does paging go?">
A ranked search reaches a limited number of results, and `matchType: "boolean"` pages deeper.
The exact `limit` and `offset` ranges are in the [Pagination](/api-guide/pagination#search-paging) field table.

If you see a cap that is not 10 or 50, check the default in your own client.
</Accordion>

<Accordion title="hasMore is true but I only got a handful of results. Is something wrong?">
No.
`hasMore` and `count` describe the results reachable for that query, not the whole corpus.
A query that matches a few long sections can return fewer distinct sections than you expect.

See [Pagination](/api-guide/pagination#search-paging).
</Accordion>

<Accordion title="Does the API support AND, OR, NOT, quoted phrases or wildcards?">
Yes, with `matchType: "boolean"` on `POST /us/statutes/search`.
The query is read as a terms-and-connectors expression. It supports `AND`, `OR`, `NOT`, `/s` (same sentence), `/p` (same paragraph), `/N` (within N words), quoted phrases, `*` and `?` wildcards and parentheses.
Every result satisfies the expression, and `parsedQuery` on the response shows how it was read.

In the other modes (`any`, `all` and `phrase`) the query is not parsed, so `AND` and `OR` are ordinary words.

See [Boolean search](/api-guide/concepts/boolean-search) for the full syntax.
</Accordion>

<Accordion title="Why did a section with none of my query words rank first?">
Search matches on meaning as well as words, so a section can rank for a question it shares no wording with.
That suits a natural-language question and not a term of art.

Set `matchType` to `phrase` or `all` when you need the exact words, or to `boolean` for exclusions or proximity.

See [How search works](/api-guide/concepts/search).
</Accordion>

<Accordion title="Does search read the whole section, or just part of it?">
Search reads the full text of each section, plus its headings and citations.

The `excerpt` on a result is a preview, not the section.
Call `GET /us/statutes/section/{actId}/body` for the authoritative text.
</Accordion>

</AccordionGroup>

## Identifiers and structure

<AccordionGroup>

<Accordion title="Can I store actId permanently as my primary key?">
Store it, but store the citation next to it.
An `actId` survives an amendment and a repeal. It changes when a section is renumbered or moved.
When a stored id stops resolving, look it up again by citation with `GET /us/statutes/resolve`.

See [Section identifiers](/api-guide/concepts/section-ids).
</Accordion>

<Accordion title="How many sections are in a jurisdiction, code or chapter?">
Use `POST /us/statutes/count`.
It takes the same scoping filters as search and returns an exact section count for one credit.
A scope that matches nothing is refunded.

It takes no `query`. To count what a query matches, use search.

See [Build a subject corpus](/api-guide/recipes/subject-corpus).
</Accordion>

<Accordion title="How do I enumerate or export a state, code, title or chapter, and know it was complete?">
Enumerate it with `GET /us/statutes/divisions`.
It browses `USC`, `CFR`, `STATE`, `REGULATION`, `STATE_RULES`, `CONSTITUTION`, `STATE_CONSTITUTION` and `FEDERAL_RULES`, one level at a time.
The leaf level returns every section in the container with its `actId`.

Codes vary in depth.
Read `level` on the response instead of assuming a fixed depth, and treat any node with `isLeaf` and an `actId` as a section.

To check the enumeration is complete, look at `truncated` on every section listing.
When it is `true`, pass `nextCursor` back as `cursor` and repeat until it is `null`.
Then compare your total with the parent node's `sectionCount`.

To export the text, send the `actId` values to `POST /us/statutes/sections` with `includeBody`, 50 per call.
Size the job first with `POST /us/statutes/count`, and filter on metadata before you fetch bodies.

Do not use `POST /us/statutes/search` to enumerate a container.
Ranked search returns at most 120 results per query. `matchType: "boolean"` goes further, but browse is still the right tool.

See [Browse the hierarchy](/api-guide/recipes/browse-hierarchy).
</Accordion>

<Accordion title="Does the API expose cross-references between sections?">
For the federal corpora, yes. They are stored fields: `crossReferencesUsc`, `crossReferencesCfr`, `publicLaws`, and `statutoryAuthority` with its reverse `implementingRegulations`.

`GET /us/statutes/section/{actId}/cited-by` gives the reverse lookup across USC and CFR.
`GET /us/statutes/section/{actId}/related` returns nearby sections in reading order. This helps find scope and exception provisions, which usually sit beside the operative section.

See [Section intelligence](/api-guide/concepts/section-intelligence).
</Accordion>

<Accordion title="Is there metadata marking definition, applicability or enforcement sections?">
There is no provision-type field.

`GET /us/statutes/section/{actId}/definitions` finds the definitions section for a provision and returns the defined terms.
For applicability, exception and enforcement provisions, classify from the heading and text in your own code.
</Accordion>

</AccordionGroup>

## Keeping data current

<AccordionGroup>

<Accordion title="How do I find what changed since my last sync?">
Pick the mechanism that fits the question.

| You want | Use |
|---|---|
| Changed sections inside a subject area | `changedSince` on `POST /us/statutes/search` |
| Everything a source published | A board watch, polled at `GET /watches/{id}/changes` |
| The history of one section you already hold | `GET /us/statutes/section/{actId}/changes` |

A board watch returns the source's full history, not only what happened after you subscribed.
Polling is safe, and watch management and polling cost no credits.

See [Law change alerts](/api-guide/alerts).
</Accordion>

<Accordion title="How often does a given section actually change?">
Read `amendmentYears`, `lastAmendedYear` and `amendmentsCount` on the section.
They come from the publisher's own record and go back decades.

See [Amendment history](/api-guide/concepts/amendment-history).
</Accordion>

<Accordion title="What did this section say on a particular date?">
Pass `asOf=YYYY-MM-DD` to `GET /us/statutes/section/{actId}/body`.

Read the `asOf` block on the response before you rely on the text.
Its `isBounded` flag shows how strong the reconstruction is. Show that to your users when the answer drives a compliance decision.

See [Point in time](/api-guide/point-in-time).
</Accordion>

</AccordionGroup>

## Volume and access

<AccordionGroup>

<Accordion title="What should I design rate limits and credits around?">
Pace requests against the `X-RateLimit-*` headers on every response. Limits are counted per API key.
Retry `429` with backoff. Handle `402` separately: it means you are out of credits, not rate limited.

<CreditsConsumed />

Empty and failed lookups are refunded on the endpoints where an empty result is not the answer.

See [Errors and rate limits](/api-guide/errors#rate-limiting) and [Authentication and credits](/api-guide/authentication).
</Accordion>

<Accordion title="Is there a bulk-search or bulk-export endpoint?">
Not on the metered API.
`POST /us/statutes/sections` takes up to 50 `actId` values and `POST /us/statutes/resolve` up to 50 citations. Both need identifiers you already hold.
They are priced per item, so batch to save round trips, not cost.

Add `includeBody` to `POST /us/statutes/sections` to get each section's full text inline.

For the corpus itself, see [Bulk and SQL access](/api-guide/bulk-and-sql).
</Accordion>

<Accordion title="Can I get a bulk export of a corpus that is not in the public dataset?">
Sometimes, by agreement. It is not a self-serve download because of licensing.
Delivery matches the public files: Parquet, one file per jurisdiction, with a manifest and checksums.

A narrower scope, such as a subject area or a few jurisdictions, is easier to agree.
See [Bulk and SQL access](/api-guide/bulk-and-sql) for how to ask.
</Accordion>

</AccordionGroup>
