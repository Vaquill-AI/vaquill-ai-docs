| Python | `vaquill.ConflictError` |
| TypeScript | `ConflictError` |

## What it means

The request conflicts with the current state of a resource and no more specific code applies.
For example, you already hold the watch you tried to create.

## What to do

Read `detail` for the conflicting state.
Fetch the existing resource instead of creating it again.

## Example response

The `detail` text is illustrative and can differ by endpoint.
`retryAfterSeconds` appears only on a `429` or `503` that carries a `Retry-After` header.

```json
{
  "type": "https://www.vaquill.ai/docs/errors/conflict",
  "title": "Conflict",
  "status": 409,
  "detail": "Conflict",
  "code": "conflict",
  "retryable": false,
  "requestId": "3f2b8c1e-5a7d-4e9b-9c34-0d6a1b2f7e58"
}
```

## In the SDKs

The Python SDK raises `ConflictError` and the TypeScript SDK raises `ConflictError`.
Both expose `code`, `retryable`, the request id and the retry hint.
See [Error codes](/errors/index) for the full table and attribute names.
