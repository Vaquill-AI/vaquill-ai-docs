Errors from the Data API carry a stable `code` beside the `detail` member.
Branch on `code`, and fall back to the HTTP status when `code` is absent.
Treat an unknown code as its HTTP status class.

The `type` member of every error body is a URL of the form `https://www.vaquill.ai/docs/errors/{code}`. It opens this page at the section for that code.
For the status table, the `detail` and `errors` shapes and rate limiting, see [Errors and rate limits](/api-guide/errors).

## Body fields

| Field | Meaning |
|---|---|
| `type` | URL naming the error kind. |
| `title` | Short human title for the code. |
| `status` | The HTTP status. |
| `detail` | The legacy message, unchanged. |
| `code` | The stable machine code. |
| `retryable` | Whether the same request may succeed if you send it again. |
| `requestId` | Id of the request. Quote it to support. |
| `retryAfterSeconds` | Seconds to wait. Present only on a `429` or `503` that carries a `Retry-After` header. |

## Example response

Every error body has this shape. The `detail` text can differ by endpoint, and a few codes add members of their own.

```json
{
  "type": "https://www.vaquill.ai/docs/errors/rate_limited",
  "title": "Rate limited",
  "status": 429,
  "detail": "Rate limit exceeded",
  "code": "rate_limited",
  "retryable": true,
  "requestId": "3f2b8c1e-5a7d-4e9b-9c34-0d6a1b2f7e58",
  "retryAfterSeconds": 12
}
```

## All codes

The Python SDK (`vaquill`) and the TypeScript SDK use the same class names.
"By status" means the SDKs pick the class from the HTTP status (see [How the SDKs expose them](#how-the-sdks-expose-them)).

| Code | Status | Retryable | SDK class | Title | What to do |
|---|---|---|---|---|---|
| [`authentication_required`](#authentication_required) | 401 | No | `AuthenticationError` | Authentication required | Send your key in the `Authorization` header |
| [`invalid_api_key`](#invalid_api_key) | 401 | No | `AuthenticationError` | Invalid API key | Fix the key or create a new one |
| [`api_key_expired`](#api_key_expired) | 401 | No | `AuthenticationError` | API key expired | Create a new key |
| [`permission_denied`](#permission_denied) | 403 | No | `PermissionDeniedError` | Permission denied | Change plan, scope or jurisdiction |
| [`insufficient_scope`](#insufficient_scope) | 403 | No | `PermissionDeniedError` (by status) | Insufficient scope | Use a key with the scope `detail` names |
| [`insufficient_credits`](#insufficient_credits) | 402 | No | `InsufficientCreditsError` | Insufficient credits | Top up, then resend |
| [`rate_limited`](#rate_limited) | 429 | Yes | `RateLimitError` | Rate limited | Wait for `Retry-After`, then retry |
| [`quota_exceeded`](#quota_exceeded) | 429 | No | `RateLimitError` (by status) | Quota exceeded | Free a slot or raise the limit |
| [`daily_cap_exceeded`](#daily_cap_exceeded) | 429 | No | `DailyCapExceededError` (a `RateLimitError`) | Daily cap exceeded | Retry after the cap resets |
| [`validation_error`](#validation_error) | 422 | No | `UnprocessableEntityError` | Validation error | Fix the fields in `errors` |
| [`invalid_query`](#invalid_query) | 422 | No | `UnprocessableEntityError` | Invalid query | Fix the query named in `detail` |
| [`invalid_citation_input`](#invalid_citation_input) | 422 | No | `UnprocessableEntityError` | Invalid citation input | Fix the request as `detail` says |
| [`bad_request`](#bad_request) | 400 | No | By status | Bad request | Read `detail` and change the request |
| [`method_not_allowed`](#method_not_allowed) | 405 | No | By status | Method not allowed | Use a method the `Allow` header lists |
| [`payload_too_large`](#payload_too_large) | 413 | No | By status | Payload too large | Send a smaller body |
| [`unsupported_media_type`](#unsupported_media_type) | 415 | No | By status | Unsupported media type | Send `Content-Type: application/json` |
| [`section_not_found`](#section_not_found) | 404 | No | `NotFoundError` | Section not found | Check `reason` and `didYouMean` |
| [`resource_not_found`](#resource_not_found) | 404 | No | `NotFoundError` | Resource not found | Check the id belongs to your account |
| [`idempotency_key_reused`](#idempotency_key_reused) | 422 | No | `IdempotencyKeyReusedError` | Idempotency key reused | Use a fresh key |
| [`idempotency_in_progress`](#idempotency_in_progress) | 409 | Yes | `IdempotencyInProgressError` | Idempotency request in progress | Resend with the same key |
| [`idempotency_replay_unavailable`](#idempotency_replay_unavailable) | 409 | No | `IdempotencyReplayUnavailableError` | Idempotent replay unavailable | Check your balance, then resend with a new key |
| [`conflict`](#conflict) | 409 | No | `ConflictError` | Conflict | Fetch the existing resource |
| [`upstream_timeout`](#upstream_timeout) | 504 | Yes | `InternalServerError` | Upstream timeout | Retry with backoff. Refunded |
| [`service_unavailable`](#service_unavailable) | 503 | Yes | `InternalServerError` | Service unavailable | Retry with backoff. Refunded |
| [`internal_error`](#internal_error) | 500 | Yes | `InternalServerError` | Internal error | Retry with backoff. Refunded |

## Retrying

<RetryAfter />

The SDKs retry every code marked Retryable Yes and never retry `insufficient_credits` or `daily_cap_exceeded`.
See the [Python SDK](/api-guide/sdks/python) and the [TypeScript SDK](/api-guide/sdks/typescript) pages for client setup.

## Codes by kind

Status, retry rule and SDK class are in the table above. Each entry below says what the code means.

### Authentication and permission

Retrying a `401` or `403` unchanged cannot succeed. Change the key, plan, scope or jurisdiction first.
See [Authentication](/api-guide/authentication) for the header format and key rotation.

<a id="authentication_required"></a>
#### authentication_required

The request carried no credential.
Send your key in the `Authorization: Bearer vq_key_...` header.

<a id="invalid_api_key"></a>
#### invalid_api_key

The key is malformed, unknown or revoked. It is also the default code for any other `401`.
Check that the key starts with `vq_key_` and was copied whole.
If it was revoked, create a new key in the developer dashboard.

<a id="api_key_expired"></a>
#### api_key_expired

The key is past its expiry date.
Create a new key and replace the expired one.

<a id="permission_denied"></a>
#### permission_denied

The key is valid, but your plan, the key's scope or the requested jurisdiction does not allow this call.
For example, webhook delivery on a watch requires the Business plan.
`detail` says which one applies.

<a id="insufficient_scope"></a>
#### insufficient_scope

The key is valid but lacks the scope this route needs.
`detail` names the scope.

### Credits and limits

<a id="insufficient_credits"></a>
#### insufficient_credits

Your credit balance is too low for this call.
Top up, then send the request again. `GET /credits/balance` is free.

<a id="rate_limited"></a>
#### rate_limited

You exceeded the per-key rate window.
Wait as described under [Retrying](#retrying), then retry.

<a id="quota_exceeded"></a>
#### quota_exceeded

A standing account limit, for example the watch cap.
Retrying cannot help. Delete a watch or upgrade.

<a id="daily_cap_exceeded"></a>
#### daily_cap_exceeded

The key reached its per-key daily cap.
A short wait does not help. Retry after the cap resets.

### Request validation

Fix the request and send it again.

<a id="validation_error"></a>
#### validation_error

The request body or parameters failed schema validation. It is the default code for any other `4xx`.
The body also carries an `errors` array. Each entry has `loc` (where), `msg` (why) and `type`.

<a id="invalid_query"></a>
#### invalid_query

A Boolean query or a filter was refused. It is not charged.
`detail` gives the reason, such as a malformed expression.
See [Boolean search](/api-guide/concepts/boolean-search#errors).

<a id="invalid_citation_input"></a>
#### invalid_citation_input

The request is malformed, for example a citation that is not a string in the field the endpoint documents.
A citation that parsed but did not resolve is a different case.

<a id="bad_request"></a>
#### bad_request

The request parsed but the API refused it.
`detail` names the problem. See [400 versus 422](/api-guide/errors#400-versus-422).

<a id="method_not_allowed"></a>
#### method_not_allowed

The path exists but not for this HTTP method.
The `Allow` header lists the right ones.

<a id="payload_too_large"></a>
#### payload_too_large

The request body is over the limit.

<a id="unsupported_media_type"></a>
#### unsupported_media_type

Send `Content-Type: application/json`.

### Not found

<a id="section_not_found"></a>
#### section_not_found

No section matches the identifier you sent.
The body carries `reason` and `didYouMean`. Read `reason`, and try the candidates in `didYouMean` when present.
Use search or the hierarchy browse to find the right identifier.

<a id="resource_not_found"></a>
#### resource_not_found

A watch, board, delivery or change with that id does not exist for your account.
List the resource first to get valid ids.

### Idempotency and conflict

<a id="idempotency_key_reused"></a>
#### idempotency_key_reused

You sent an `Idempotency-Key` that was already used with a different request.
Use a fresh key for each distinct request.

<a id="idempotency_in_progress"></a>
#### idempotency_in_progress

The original request with this `Idempotency-Key` is still running.
Wait briefly and resend the same request with the same key.

<a id="idempotency_replay_unavailable"></a>
#### idempotency_replay_unavailable

The original request completed, but its response was too large to replay. You were not charged again.
Check your balance with `GET /credits/balance`. To get the data again, send a new request with a new key.

<a id="conflict"></a>
#### conflict

The request conflicts with the current state of a resource, for example you already hold the watch you tried to create.
Fetch the existing resource instead.

### Server and upstream

All three are refunded.
Retry with exponential backoff, and honor `Retry-After` when present (see [Retrying](#retrying)).

<a id="upstream_timeout"></a>
#### upstream_timeout

A service the API depends on did not answer in time.

<a id="service_unavailable"></a>
#### service_unavailable

A dependency of the API is down.

<a id="internal_error"></a>
#### internal_error

The API failed in a way it did not anticipate.
If it persists, [contact support](mailto:contact@vaquill.ai) and include the `requestId`.

## How the SDKs expose them

Both SDKs map the error body to an exception class.
They pick the class from `code` first and the HTTP status second.

| Information | Python (`vaquill`) | TypeScript |
|---|---|---|
| Base for HTTP errors | `APIStatusError` | `APIStatusError` |
| HTTP status | `status_code` or `status` | `status` |
| Machine code | `code` | `code` |
| Retryable hint | `retryable` | `retryable` |
| Wait hint | `retry_after_seconds` | `retryAfterSeconds` |
| Request id | `request_id` | `requestId` |
| Legacy members | `detail`, `errors` | `detail`, `errors` |

`code` and `retryable` are `None` in Python and `null` in TypeScript when the server did not send them.

A code without a class of its own maps by status:

| Status | Class |
|---|---|
| `401` | `AuthenticationError` |
| `403` | `PermissionDeniedError` |
| `404` | `NotFoundError` |
| `409` | `ConflictError` |
| `422` | `UnprocessableEntityError` |
| `429` | `RateLimitError` |
| `5xx` | `InternalServerError` |

The three idempotency classes share the base class `IdempotencyConflictError`.
