**`422`** `workflow-inputs-rejected`

The request parsed, and the workflow refused what it asked for: a required input missing, or a document slot that does not match what the workflow expects.

## What to do

The `detail` is the workflow's own message and it names the input at fault, so read it literally.
Then read the definition back: `GET /v1/workflows` returns the whole catalogue, and the entry whose `id` matches the one you ran carries `inputs` (each with a `key` and a `required` flag) and `documentSlots` (each with the `role` a document must be sent under).
There is no per-workflow route; the catalogue is one list.
Attaching two documents where one role is defined, or omitting a role that is not optional, are the two usual causes.
