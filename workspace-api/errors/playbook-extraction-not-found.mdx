**`404`** `playbook-extraction-not-found`

No playbook extraction with that id is available to your organization. It covers an extraction that never existed, one belonging to someone else, and an id that is well formed but names something other than an extraction.

That last case is worth knowing about. Extractions and contract reviews are the same kind of job record underneath, so a review id reshaped as a `pex_` identifier is a real row that is not an extraction. It answers with this type rather than with a review, because telling the two apart in an error would say what else your organization is running.

## What to do

Take the `pex_` id from the `resource` on the operation that started the extraction, which is the only place one is issued. There is no list: an extraction is short-lived work you started, so the operation you were handed is the handle.

An id that worked and now 404s has passed the operation retention window. Extractions are not kept indefinitely; adopt the positions you want into a playbook, which is permanent.
