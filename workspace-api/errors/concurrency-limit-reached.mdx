**`429`** `concurrency-limit-reached`

Too much of this kind of work is already unfinished for your organization. This counts running jobs, not requests, so you can meet it while comfortably inside your request budget.

## What to do

Wait for something to finish. The problem document carries `limit`, and `detail` names how many are in flight. Poll the operations you already started, and start the next run when one of them reaches a terminal status.

<Warning>
Slowing your request rate will not clear this, which is what separates it from `rate-limited`. The fix is fewer runs open at once, so cap the launches your integration keeps in flight rather than adding a delay between them.
</Warning>
