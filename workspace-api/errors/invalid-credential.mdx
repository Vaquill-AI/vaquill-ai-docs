**`401`** `invalid-credential`

The bearer token on this request is not one we can accept. Malformed, truncated, expired, revoked and never issued all answer identically, so the response cannot be used to work out which credentials exist.

## What to do

First check the value arrived whole: `Authorization: Bearer vq_ws_...`, with no quotes, stray whitespace or wrapped lines. Then confirm in the automation console that the credential is still live and inside its expiry. Credentials are not renewed in place, so an expired one is replaced by issuing a new credential and swapping it in.

<Warning>
If we are having an outage, authentication answers `503 credential-store-unavailable` instead. A `401` really is about the credential.
</Warning>
