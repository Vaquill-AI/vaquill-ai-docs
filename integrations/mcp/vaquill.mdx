The Vaquill MCP server gives any [Model Context Protocol](https://modelcontextprotocol.io) client (Claude.ai, Claude Desktop, Claude Code, Cursor, VS Code, Windsurf) access to the Vaquill AI Developer API. It covers US statutes, regulations, session laws, rulemaking records and case law. See [API coverage](/api-guide/coverage). Source: [github.com/Vaquill-AI/vaquill-mcp](https://github.com/Vaquill-AI/vaquill-mcp).

<Note>
  This page covers the US server, `https://mcp.vaquill.ai/mcp`. India is a separate host, described under [India server](#india-server), and Indian regulatory publications are a third, under [Regulatory server](#regulatory-server).
</Note>

## Quickstart

<Note>
  On Claude, the [connector](/integrations/mcp/claude-connector) is faster. Paste `https://mcp.vaquill.ai/mcp`, click Connect, and skip the key. It is also the only path that works in Cowork. The rest of this page is the API-key setup for Cursor, VS Code, Windsurf and other clients.
</Note>

The quickest key-based setup is the hosted remote MCP on Claude.ai web. It needs no install and no config files.

<Prompt
  description="**Install Vaquill MCP in Claude Code** with one paste."
  actions={["copy"]}
>
Install the Vaquill MCP server in Claude Code using my API key.

1. Run `claude mcp add --transport http --scope user vaquill https://mcp.vaquill.ai/s/_ --header "Authorization: Bearer vq_key_REPLACE_ME"` to register the remote MCP for every project.
2. Confirm the server is wired by running `claude mcp list` and looking for `vaquill`.
3. Then try a smoke test prompt like *"Use Vaquill AI to pull the full text of 18 USC 1343 and summarize it in two sentences."*

If anything fails, show me the exact error and the output of `claude mcp list`.
</Prompt>


<Steps>
  <Step title="Get an API key">
    Generate a `vq_key_...` token from your [dashboard settings](https://app.vaquill.ai/settings). See [Authentication](/api-guide/authentication).
  </Step>
  <Step title="Open Claude.ai Customize > Connectors">
    Click **Add custom connector**.
  </Step>
  <Step title="Paste the URL">
    Use either the path-token form:

    ```
    https://mcp.vaquill.ai/s/vq_key_your_key_here
    ```

    Or keep the key out of the URL by opening **Request headers** in the same dialog and adding it there:

    ```
    URL:            https://mcp.vaquill.ai/s/_
    Header name:    Authorization
    Header value:   Bearer vq_key_your_key_here
    ```

    The value field holds `Bearer vq_key_...`, not `Authorization: Bearer vq_key_...`.
  </Step>
  <Step title="Look up a statute">
    Try: *"What does 17 CFR 240.10b-5 say about insider trading?"* Claude calls `search_us_statutes` and gets the section text.
  </Step>
</Steps>

<Info>
  Remote MCP connectors need Claude Pro, Max, Team or Enterprise. The **Request headers** section is in beta and enabled per account. It accepts a short list of header names and at most four. If you do not see it, use the path-token URL or connect from Claude Code, Cursor, VS Code or Windsurf. On Team and Enterprise, an owner adds the connector under Organization settings first.
</Info>

## Client setup

The remote endpoint needs no install. The local `uvx` package reads the variables listed under [Self-hosting](#self-hosting).

<CodeGroup>
```json Claude Desktop
// Settings > Developer > Edit Config opens this file.
//   macOS    ~/Library/Application Support/Claude/claude_desktop_config.json
//   Windows  %APPDATA%\Claude\claude_desktop_config.json
//   Linux    ~/.config/Claude/claude_desktop_config.json
// Quit Claude completely and reopen it. It does not reload the file.
{
  "mcpServers": {
    "vaquill": {
      "command": "uvx",
      "args": ["vaquill-mcp"],
      "env": {
        "VAQUILL_API_KEY": "vq_key_your_key_here"
      }
    }
  }
}
```

```bash Claude Code (remote)
# --scope user registers it for every project. The default is the current directory only.
claude mcp add --transport http --scope user vaquill \
  https://mcp.vaquill.ai/s/_ \
  --header "Authorization: Bearer vq_key_your_key_here"
```

```bash Claude Code (local)
# -e stores the key with the registration, so it survives Claude Code being launched from an IDE.
claude mcp add --scope user vaquill -e VAQUILL_API_KEY=vq_key_your_key_here \
  -- uvx vaquill-mcp
```

<Tip>
  VS Code asks for the header value on first start and remembers it, so the key stays out of committed files. Windsurf accepts `${env:VAQUILL_API_KEY}`. Restart the server after you save the file.

## Tools

The US mount lists 52 read-only tools: typed tools over the API, plus the `search` and `fetch` pair.
Listing them needs no credential.
The case law tools work with any API key you create.

<Warning>
  Never build an `act_id` by hand. A constructed id usually returns 404. Get it from `search_us_statutes`, `resolve_statute_citation` or `list_statute_divisions`. See [Section identifiers](/api-guide/concepts/section-ids). Case, opinion, judge and docket ids work the same way: take them from a search, a list or `resolve_case_citations`.
</Warning>

<AccordionGroup>
  <Accordion title="Search and retrieval details">
    - `list_statutes_coverage`: call it before treating an empty result as an absence.
    - `search_us_statutes` filters by `corpusType`, `state`, `code`, `source`, status, year and Federal Register facets.
    - `get_us_statute_section` returns citation, hierarchy, breadcrumb, status and every format link.
    - `get_us_statute_section_text` supports `format=content` (operative text only, USC), `structured=true` for a subsection tree, and `asOf` for point-in-time.
    - `get_sections_batch` adds a diagnosis for each miss.
    - `resolve_statute_citation` confirms the section against the corpus.
    - `extract_statute_citations` takes a pasted brief, memo or model answer and resolves each citation in it. It does not extract case citations, which go to `resolve_case_citations`. `resolve=false` lists them for free.
  </Accordion>
  <Accordion title="Case law details">
    - Start with `resolve_case_citations` when you have a citation, and `search_us_cases` when you have words.
    - `get_us_case` returns opinion ids. Read each opinion with `get_us_opinion`, because a dissent is an opinion of its own.
    - When an opinion has `textFromOcr` set, check a quotation before you rely on it.
    - Coverage differs by court and year. Call `list_us_courts` with `include=coverage` before treating an empty result as an absence.
    - See [Case law coverage](/api-guide/coverage/case-law) for what is held.
  </Accordion>
  <Accordion title="Refunds and empty results">
    - `list_statute_divisions` is refunded on an empty level.
    - Each section intelligence tool refunds a call it cannot answer, and returns a `note` explaining why. An empty result with a note is explained by the note. Without a note it is a real answer.
    - An empty page from a rulemaking list is refunded.
    - An empty page from `search_us_cases`, `list_us_judges` or `list_us_dockets` is charged.
    - An empty page from `list_session_laws` is charged, and so is an empty result from `search_session_laws`.
  </Accordion>
  <Accordion title="Reading session-law bodies">
    - `list_session_laws` filters by session, approval date or effective date, and `jurisdiction` is required.
    - `get_session_law` returns citation, session, dates, code sections affected, official sources and `textStatus`. It takes a `sessionLawId` or a citation, and a citation adds the resolve price.
    - `get_session_law_body` returns the text as printed. Check `textReliability`, `notice` and `amendatoryMarkup`. If it is `lost`, struck language may read as law.
    - `search_session_laws` accepts plain words, a quoted phrase, a citation, a code section or a bill number. It ranks by keyword. Only enacted text is searched.
    - `get_session_laws_batch` with `includeBody` adds each law's first page of text.
    - `get_section_enactments` covers CA, DC, HI, KY, MO, MS, NE, UT and WA.
  </Accordion>
</AccordionGroup>

## India server

India is a separate server on its own host, with its own tools, resources and
prompts. A US connection never exposes India tools, and the reverse. Connect
only the server you need.

```
https://in-mcp.vaquill.ai/mcp              sign in with your account, or send an API key as a bearer
https://in-mcp.vaquill.ai/s/vq_key_...     key in the path
```

It serves three corpora of Indian primary law: central and state legislation,
Supreme Court and High Court judgments, and tribunal matters. The same
`vq_key_` works here and on the US server, against one shared credit balance.

<Note>
  **This address changed on 2026-11-26.** India used to be a path on the US
  host, `https://mcp.vaquill.ai/in/mcp` (and `https://mcp.vaquill.ai/in/s/{key}`).
  That address stopped working on 2026-11-26. Remove a connector saved against
  it and add `https://in-mcp.vaquill.ai/mcp` instead, which also lets you sign
  in with your account. Regulatory tools are on their own server,
  [reg-mcp](#regulatory-server).

  The move is what makes OAuth possible. Sign-in discovery is defined to live at
  the root of a host, so a corpus served from a sub-path could only ever take an
  API key. On its own host, India supports both.
</Note>

Two things are deliberately NOT here:

- **Regulatory publications** are on their own server, [reg-mcp](#regulatory-server)
  (circulars, orders, notices and press releases). They are administrative
  material rather than binding authority, and they were previously published in
  both places under two different tool names.
- **Translation** is REST only, not MCP. See the
  [translation API](/api-guide/india-translation-quickstart). Its tools were a
  third of this catalogue's token cost while having no bearing on what the law
  says.

The server publishes 33 tools, listed below by corpus. Costs are appended to
each tool's description at startup from the live pricing table, so
`get_pricing_in` is the authority rather than this page.

Source PDFs are not tools on this server, because a tool result cannot carry a PDF.
Records say `hasFile`, and the REST `/file` routes return the document.

**Resources**: `vaquill://guide` (how to use the corpus), `vaquill://in/filters`

code that replaced it. `indian_provision_check` finds and verifies what Indian
law says on a point, with the amendment caveat stated correctly.

## Regulatory server

Indian regulatory publications are served from their own host:

```
https://reg-mcp.vaquill.ai/mcp             sign in with your account, or send an API key as a bearer
https://reg-mcp.vaquill.ai/s/vq_key_...    key in the path
```

This is the corpus the regulatory tracker feeds: circulars, orders, notices and
press releases from named Indian regulators (SEBI, RBI, MCA, IRDAI, TRAI, DGFT
and others), captured with their original files and a change history. It is
administrative and persuasive material, not binding authority, which is why it
is a separate connection from Indian primary law.

Seven tools, and the same `vq_key_` as every other Vaquill server. Five read the
corpus. The last two are account tools, the same ones the India server offers, so
you can check your balance and the price of a workflow without switching
connections:

| Tool | Description | Credits |
|------|-------------|---------|
| `get_regulatory_coverage` | What the corpus covers and how fresh each source is. Read it before trusting an empty result anywhere else. | Free |
| `search_regulatory_documents` | One route for searching and listing, with scope filters. | 1 |
| `get_regulatory_document` | One document, with its body, capture history or diff on request. | 1 |
| `get_regulatory_document_file` | The publisher's original file as archived. | 1 |
| `list_regulatory_changes` | An append-only feed: new, rechanged or retracted. | 1 |
| `get_india_credit_balance` | Your remaining credits. | Free |
| `get_pricing_in` | Credit-to-price conversion and per-endpoint costs for the India API, billed in US dollars. No authentication is required. | Free |

<Note>
  Until 2026-11-26 the five corpus tools were published twice: here, and again on the
  India mount under different names (`list_regulatory_documents` for what is
  now `search_regulatory_documents`). The duplicates are gone. If you were
  calling them on the India connection, move to this host.
</Note>

## Authentication

The US endpoint `https://mcp.vaquill.ai/mcp` uses OAuth 2.1 by default. The client opens a browser and you sign in with your Vaquill AI account. There is no key to paste.

<Accordion title="OAuth details">
  The flow is authorization code with PKCE (S256), discovered from `/.well-known/oauth-protected-resource/mcp`. Dynamic client registration and client ID metadata documents are supported. The access token lasts about an hour and refreshes automatically.
</Accordion>

Clients that cannot run OAuth use your Vaquill API key. Three options, in priority order:

1. **Bearer header** (remote): `Authorization: Bearer vq_key_...`
2. **Path token** (remote): `https://mcp.vaquill.ai/s/vq_key_...`. Deprecated, though it still works. Use it only when your client cannot send custom headers.
3. **Environment variable** (local): `VAQUILL_API_KEY=vq_key_...` for `uvx` / stdio launches.

Keys are scoped per workspace and can be revoked from the [dashboard](https://app.vaquill.ai/settings). See [Authentication](/api-guide/authentication) for rotation.

<Warning>
  Treat the path-token URL as a secret. Anyone with it can spend your credits. Use the bearer header when your client supports it.
</Warning>

## Self-hosting

<Accordion title="Run from source">
  Run from source to pin a version, add telemetry or change tool descriptions.

  ```bash
  git clone https://github.com/Vaquill-AI/vaquill-mcp.git
  cd vaquill-mcp
  uv sync --all-extras

  # Run locally over stdio
  VAQUILL_API_KEY=vq_key_... uv run vaquill-mcp

  # Inspect tools interactively
  uv run fastmcp dev src/vaquill_mcp/server.py
  ```

  The package builds its tools from the API's OpenAPI spec at startup, so new endpoints appear without an upgrade.

  Environment variables:

  - `VAQUILL_API_KEY` (required): your API key (`vq_key_...`) from [app.vaquill.ai/settings](https://app.vaquill.ai/settings).
  - `VAQUILL_BASE_URL` (optional, default `https://api.vaquill.ai`): API base URL. Override for staging or self-hosted API instances.
  - `VAQUILL_TIMEOUT` (optional, default `120`): per-request timeout in seconds. Increase for large section-text fetches.
</Accordion>
