The Vaquill MCP server gives any [Model Context Protocol](https://modelcontextprotocol.io) client (Claude.ai, Claude Desktop, Claude Code, Cursor, VS Code, Windsurf) access to the Vaquill AI Developer API. It covers the full US corpus. See [API coverage](/api-guide/coverage). Source: [github.com/Vaquill-AI/vaquill-mcp](https://github.com/Vaquill-AI/vaquill-mcp).

<Note>
  This page covers the US mount, `https://mcp.vaquill.ai/s/_`. The India mount is described under [India mount](#india-mount).
</Note>

## Quickstart

<Note>
  On Claude, the [connector](/integrations/mcp/claude-connector) is faster. Paste `https://mcp.vaquill.ai/mcp`, click Connect, and skip the key. It is also the only path that works in Cowork. The rest of this page is the API-key setup for Cursor, VS Code, Windsurf and other clients.
</Note>

The quickest key-based setup is the hosted remote MCP on Claude.ai web. It needs no install and no config files.

<Prompt
  description="**Install Vaquill MCP in Claude Code** with one paste."
  actions={["copy"]}
>
Install the Vaquill MCP server in Claude Code using my API key.

1. Run `claude mcp add --transport http --scope user vaquill https://mcp.vaquill.ai/s/_ --header "Authorization: Bearer vq_key_REPLACE_ME"` to register the remote MCP for every project.
2. Confirm the server is wired by running `claude mcp list` and looking for `vaquill`.
3. Then try a smoke test prompt like *"Use Vaquill AI to pull the full text of 18 USC 1343 and summarize it in two sentences."*

If anything fails, show me the exact error and the output of `claude mcp list`.
</Prompt>


<Steps>
  <Step title="Get an API key">
    Generate a `vq_key_...` token from your [dashboard settings](https://app.vaquill.ai/settings). See [Authentication](/api-guide/authentication).
  </Step>
  <Step title="Open Claude.ai Customize > Connectors">
    Click **Add custom connector**.
  </Step>
  <Step title="Paste the URL">
    Use either the path-token form:

    ```
    https://mcp.vaquill.ai/s/vq_key_your_key_here
    ```

    Or keep the key out of the URL by opening **Request headers** in the same dialog and adding it there:

    ```
    URL:            https://mcp.vaquill.ai/s/_
    Header name:    Authorization
    Header value:   Bearer vq_key_your_key_here
    ```

    The value field holds `Bearer vq_key_...`, not `Authorization: Bearer vq_key_...`.
  </Step>
  <Step title="Look up a statute">
    Try: *"What does 17 CFR 240.10b-5 say about insider trading?"* Claude calls `search_us_statutes` and gets the section text.
  </Step>
</Steps>

<Info>
  Remote MCP connectors need Claude Pro, Max, Team or Enterprise. The **Request headers** section is in beta and enabled per account. It accepts a short list of header names and at most four. If you do not see it, use the path-token URL or connect from Claude Code, Cursor, VS Code or Windsurf. On Team and Enterprise, an owner adds the connector under Organization settings first.
</Info>

## Client setup

The remote endpoint needs no install. The local `uvx` package reads the variables listed under [Self-hosting](#self-hosting).

<CodeGroup>
```json Claude Desktop
// Settings > Developer > Edit Config opens this file.
//   macOS    ~/Library/Application Support/Claude/claude_desktop_config.json
//   Windows  %APPDATA%\Claude\claude_desktop_config.json
//   Linux    ~/.config/Claude/claude_desktop_config.json
// Quit Claude completely and reopen it. It does not reload the file.
{
  "mcpServers": {
    "vaquill": {
      "command": "uvx",
      "args": ["vaquill-mcp"],
      "env": {
        "VAQUILL_API_KEY": "vq_key_your_key_here"
      }
    }
  }
}
```

```bash Claude Code (remote)
# --scope user registers it for every project. The default is the current directory only.
claude mcp add --transport http --scope user vaquill \
  https://mcp.vaquill.ai/s/_ \
  --header "Authorization: Bearer vq_key_your_key_here"
```

```bash Claude Code (local)
# -e stores the key with the registration, so it survives Claude Code being launched from an IDE.
claude mcp add --scope user vaquill -e VAQUILL_API_KEY=vq_key_your_key_here \
  -- uvx vaquill-mcp
```

<Tip>
  VS Code asks for the header value on first start and remembers it, so the key stays out of committed files. Windsurf accepts `${env:VAQUILL_API_KEY}`. Restart the server after you save the file.
</Tip>

<Tip>
  `uvx` needs Python 3.10+ and [uv](https://docs.astral.sh/uv/) on `PATH`. The first run downloads the package. Later runs are instant.
</Tip>

## Tools

There is one tool per API operation, plus the `search` and `fetch` pair. Every tool is read-only.

<Warning>
  Never build an `act_id` by hand. A constructed id usually returns 404. Get it from `search_us_statutes`, `resolve_statute_citation` or `list_statute_divisions`. See [Section identifiers](/api-guide/concepts/section-ids).
</Warning>

| Group | Tool | Description | Credits |
|-------|------|-------------|---------|
| Discovery | `list_statutes_coverage` | The live coverage matrix: corpus legend and per-jurisdiction counts. | Free |
| Discovery | `get_pricing` | Current credit pricing per endpoint. No auth required. | Free |
| Discovery | `get_credit_balance` | The credits your key can spend now, by source, the next expiry and your rate limits. | Free |
| Discovery | `list_statute_divisions` | Walk the statutory hierarchy one level down. | 1 |
| Search and retrieval | `search_us_statutes` | Hybrid semantic and keyword search across every US corpus. | 4 |
| Search and retrieval | `get_us_statute_section` | Section metadata by `act_id`. | 2 |
| Search and retrieval | `get_us_statute_section_text` | Full text of a section. | 6 |
| Search and retrieval | `get_sections_batch` | Metadata for up to 50 `act_id`s in one call. | 2 per section returned |
| Search and retrieval | `resolve_statute_citation` | Turn one citation string into the exact section. | 2 |
| Search and retrieval | `resolve_statute_citations_batch` | The same verdict for up to 50 citations at once. | 2 per citation |
| Search and retrieval | `extract_statute_citations` | Find and resolve every statute, regulation, court rule and constitution citation in pasted text. | 2 per distinct citation |
| Search and retrieval | `count_statute_sections` | How many sections a filter scope holds, before you page through it. | 1 |
| Section intelligence | `get_section_changes` | Every observed add, amend and remove for one section, cursor-paged. | 1 |
| Section intelligence | `get_section_neighbors` | The sections immediately before and after, in statutory order. | 2 |
| Section intelligence | `get_section_cited_by` | Which USC and CFR sections cross-reference this one. | 2 |
| Section intelligence | `get_section_definitions` | The defined terms from the chapter's definitions section that govern this one. | 4 |
| Section intelligence | `get_section_cross_state` | At most one comparable provision per other state, most similar first. | 6 |
| State session laws | `list_session_laws` | One state's session laws (acts as enacted). | 1 per page |
| State session laws | `get_session_law` | One law's record. | 2 |
| State session laws | `get_session_law_body` | The law's text as printed, about 30,000 characters per page. | 6 per page |
| State session laws | `search_session_laws` | Find laws by what they say. | 4 per page |
| State session laws | `get_session_laws_batch` | Up to 50 laws by id or citation in one call. | 2 per law, plus 6 per page of text |
| State session laws | `get_session_law_changes` | A cursor feed of every law served, corrected, withdrawn or merged. | 1 per page |
| State session laws | `get_section_enactments` | The session laws a publisher's tables print against one code section. | 1 |
| Aliases | `search` | Single-string search, for clients that require this exact interface. | 4 |
| Aliases | `fetch` | Single-string fetch by id, URL or citation, same constraint. | 8, plus 2 for a citation |

Federal session laws are on the statute tools. Law change alerts are not MCP tools. Manage them in the console or over the REST API: see [Law Change Alerts](/api-guide/alerts).

Prefer the typed tools to the `search` and `fetch` aliases, which cannot take filters. See [ChatGPT and Codex](/integrations/mcp/chatgpt) for when to use the aliases.

<AccordionGroup>
  <Accordion title="Search and retrieval details">
    - `list_statutes_coverage`: call it before treating an empty result as an absence.
    - `search_us_statutes` filters by `corpusType`, `state`, `code`, `source`, status, year and Federal Register facets.
    - `get_us_statute_section` returns citation, hierarchy, breadcrumb, status and every format link.
    - `get_us_statute_section_text` supports `format=content` (operative text only, USC), `structured=true` for a subsection tree, and `asOf` for point-in-time.
    - `get_sections_batch` adds a diagnosis for each miss.
    - `resolve_statute_citation` confirms the section against the corpus.
    - `extract_statute_citations` takes a pasted brief, memo or model answer and resolves each citation in it. Case citations are not extracted. `resolve=false` lists them for free.
  </Accordion>
  <Accordion title="Refunds and empty results">
    - `list_statute_divisions` is refunded on an empty level.
    - Each section intelligence tool refunds a call it cannot answer, and returns a `note` explaining why. An empty result with a note is explained by the note. Without a note it is a real answer.
    - An empty page from `list_session_laws` is charged, and so is an empty result from `search_session_laws`.
  </Accordion>
  <Accordion title="Reading session-law bodies">
    - `list_session_laws` filters by session, approval date or effective date, and `jurisdiction` is required.
    - `get_session_law` returns citation, session, dates, code sections affected, official sources and `textStatus`. It takes a `sessionLawId` or a citation, and a citation adds the resolve price.
    - `get_session_law_body` returns the text as printed. Check `textReliability`, `notice` and `amendatoryMarkup`. If it is `lost`, struck language may read as law.
    - `search_session_laws` accepts plain words, a quoted phrase, a citation, a code section or a bill number. It ranks by keyword. Only enacted text is searched.
    - `get_session_laws_batch` with `includeBody` adds each law's first page of text.
    - `get_section_enactments` covers CA, DC, HI, KY, MO, MS, NE, UT and WA.
  </Accordion>
</AccordionGroup>

## Resources and prompts

The server also publishes MCP resources and prompts. Clients that support them get guidance without a tool call.

**Resources**

| URI | Contents |
|-----|----------|
| `vaquill://guide` | How to use the corpus: identifier rules, what "still good law" means here, what an empty change list tells you, and where the cost is. Read it before your first query. |
| `vaquill://us/coverage` | The live coverage matrix as a resource. |
| `vaquill://pricing` | Live per-endpoint credit pricing. |

**Prompts**: `good_law_check`, `fifty_state_survey`, `whats_changed`, `cite_check`.

## India mount

India is a separate mount with its own tools, resource and prompts. A US connection never exposes India tools, and the reverse. Connect only the mount you need.

<Accordion title="India mount: URL, tools, prompts and resource">
  `https://mcp.vaquill.ai/in/s/_` serves Indian legislation. The same `vq_key_` works on both mounts. The main tools:

  | Tool | Description | Credits |
  |------|-------------|---------|
  | `search_acts` | Semantic search across Indian central and state enactments. | 2 |
  | `list_acts` | Browse acts to discover identifiers. | 1 |
  | `list_act_filters` | The filter vocabulary available for the two above. | Free |
  | `get_act_text` | Full text of an act or provision. | 3 |
  | `get_act_amendments` | Amendment history: substitutions, insertions, omissions. | 5 |
  | `get_corresponding_provisions` | Map a provision in a repealed code to its successor. | 1 |

  Plus the `search` and `fetch` aliases.

  **Resource**: `vaquill://in/filters` lists the available act filters.

  **Prompts**: `old_code_citation`, `indian_provision_check`.
</Accordion>

## Authentication

The US endpoint `https://mcp.vaquill.ai/mcp` uses OAuth 2.1 by default. The client opens a browser and you sign in with your Vaquill AI account. There is no key to paste.

<Accordion title="OAuth details">
  The flow is authorization code with PKCE (S256), discovered from `/.well-known/oauth-protected-resource/mcp`. Dynamic client registration and client ID metadata documents are supported. The access token lasts about an hour and refreshes automatically.
</Accordion>

Clients that cannot run OAuth use your Vaquill API key. Three options, in priority order:

1. **Bearer header** (remote): `Authorization: Bearer vq_key_...`
2. **Path token** (remote): `https://mcp.vaquill.ai/s/vq_key_...`. Use this when your client cannot send custom headers.
3. **Environment variable** (local): `VAQUILL_API_KEY=vq_key_...` for `uvx` / stdio launches.

Keys are scoped per workspace and can be revoked from the [dashboard](https://app.vaquill.ai/settings). See [Authentication](/api-guide/authentication) for rotation.

<Warning>
  Treat the path-token URL as a secret. Anyone with it can spend your credits. Use the bearer header when your client supports it.
</Warning>

## Self-hosting

<Accordion title="Run from source">
  Run from source to pin a version, add telemetry or change tool descriptions.

  ```bash
  git clone https://github.com/Vaquill-AI/vaquill-mcp.git
  cd vaquill-mcp
  uv sync --all-extras

  # Run locally over stdio
  VAQUILL_API_KEY=vq_key_... uv run vaquill-mcp

  # Inspect tools interactively
  uv run fastmcp dev src/vaquill_mcp/server.py
  ```

  The package builds its tools from the API's OpenAPI spec at startup, so new endpoints appear without an upgrade.

  Environment variables:

  - `VAQUILL_API_KEY` (required): your API key (`vq_key_...`) from [app.vaquill.ai/settings](https://app.vaquill.ai/settings).
  - `VAQUILL_BASE_URL` (optional, default `https://api.vaquill.ai`): API base URL. Override for staging or self-hosted API instances.
  - `VAQUILL_TIMEOUT` (optional, default `120`): per-request timeout in seconds. Increase for large section-text fetches.
</Accordion>

## Usage examples

Type these to any connected assistant.

**Look up federal law**

> *"What does 17 CFR 240.10b-5 say about insider trading?"*
>
> *"What are the federal penalties for wire fraud under 18 USC 1343?"*
>
> *"Pull the operative text of 26 USC 501(c)(3), without the amendment notes."*

**Verify citations**

> *"Check every statutory citation in this brief against the official text, and flag any that are no longer good law."*
>
> *"Does `Cal. Civ. Code 1950.5` resolve, and what is its current status?"*

**Compare across states**

> *"How do other states word California's security-deposit return deadline?"*
>
> *"Find the data-breach notification statute in New York, Texas and Illinois."*

**Read law as it stood on a date**

> *"What did 15 USC 1681c say on 2019-03-01, and how confident are we in that reconstruction?"*

**Find what changed**

> *"What has changed in the CFR since last Tuesday?"*
>
> *"Which Texas acts take effect on September 1, 2025?"*

### Ready-to-run research prompt

<Prompt
  description="**Map a federal statute across USC and CFR.** Paste into any Vaquill-connected assistant."
  actions={["copy"]}
>
Use the Vaquill MCP to map the statutory and regulatory framework for securities anti-fraud rules.

Do these steps in order:

1. Call `search_us_statutes` for "securities fraud" filtered to the USC to find the controlling sections.
2. Call `get_us_statute_section_text` on the most relevant section to pull its full text.
3. Repeat the search filtered to the CFR to find the implementing regulations (for example 17 CFR 240.10b-5).
4. Produce a short outline: statutory hook, implementing regulation, and the key obligations each imposes.
5. End with a one-sentence takeaway for a US compliance lead.

Cite every factual claim back to the Vaquill tool that produced it. If a tool errors, show the error and continue with the next step.
</Prompt>
