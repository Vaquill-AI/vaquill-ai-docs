The [Model Context Protocol](https://modelcontextprotocol.io) lets AI assistants call external tools. The Vaquill MCP is the primary server for US legal research, backed by the full Vaquill API. Two additional third-party MCPs (CourtListener and CanLII) are documented here as optional user-connected integrations - you bring your own key and connect them directly.

## Which one should I use?

| If you want... | Use |
|---|---|
| US legal research with Vaquill's RAG | [Vaquill MCP](/integrations/mcp/vaquill) |
| Direct, unmediated access to the CourtListener API surface | [CourtListener MCP](/integrations/mcp/courtlistener) |
| Direct, unmediated access to the CanLII API surface | [CanLII MCP](/integrations/mcp/canlii) |

The Vaquill MCP is the highest-level interface for US legal research - it adds retrieval, ranking, and answer synthesis on top of Vaquill's corpus. The CourtListener and CanLII MCPs are user-connected third-party integrations that forward your request directly to the upstream API so you get the full feature surface that each provider publishes (every filter, every field, every endpoint). Use those upstream MCPs when you want exact, unmediated access to what the source publishes; use Vaquill MCP when you want an AI-grounded answer over Vaquill's corpus.

## Supported clients

All servers work with any MCP-compatible client. Tested with:

- Claude Desktop
- Claude Code
- Claude.ai web (Vaquill MCP only - remote MCP support)
- Cursor
- VS Code (GitHub Copilot)
- Windsurf
- ChatGPT Desktop
- Continue
- Any HTTP-MCP or stdio-MCP client

## Hosted vs self-hosted

| Server | Hosted endpoint | Self-host |
|---|---|---|
| Vaquill MCP | `https://mcp.vaquill.ai/s/<your-key>` | `uvx vaquill-mcp` |
| CourtListener MCP | `https://courtlistener-mcp.vaquill.ai/mcp/` | Docker / `uv run` |
| CanLII MCP | `https://canlii-mcp.vaquill.ai/mcp` | Docker / Node / Cloudflare Workers |

Hosted is the fastest path - paste a URL into your client and start using the tools. Self-hosting gives you control over rate limits, audit logging, and network egress.

## Authentication model

The servers handle credentials differently:

| Server | What you provide | How |
|---|---|---|
| Vaquill MCP | Vaquill API key (`vq_key_...`) | Header (`Authorization: Bearer ...`) or path token |
| CourtListener MCP | Your own CourtListener token | Per-request header (`X-CourtListener-Token`) - BYOK |
| CanLII MCP | Your own CanLII API key + MCP gate token | Two headers - BYOK |

BYOK ("bring your own key") means Vaquill never sees or stores your upstream credential. The hosted endpoint forwards your key on every request.
